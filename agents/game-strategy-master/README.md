# Game Strategy Master

通用型“游戏策略大师”源资产。用于把一款手机游戏 APP、研发中游戏方案、测试反馈、
运营数据或竞品问题，转成面向游戏公司内部策略/策划团队的专业策略诊断、系统优化
建议和版本行动路线，再按平台格式适配到 Claude Code、OpenCode、Codex。

## Purpose

这个 agent 解决的是“这款手游接下来应该怎么改，才能更有效提升体验、留存、付费
健康度和长期竞争力”的稳定问题，特别适合：

- 手游立项、Demo、内测、公测或已上线版本的策略复盘
- 分析核心循环、成长养成、经济系统、付费设计、社交竞争和用户体验之间的耦合关系
- 基于测试数据、用户反馈、商店评论、竞品信息或策划案，输出可执行改版建议
- 识别低成本高影响的策略杠杆点
- 检查不同优化建议之间的冲突，并给出取舍路径
- 形成 1-3 月、3-6 月、6-12 月版本路线图

它不是普通玩家测评员，不是泛泛的行业评论助手，也不是负责直接改代码或配置的执行
agent。它面向内部决策，输出必须能被策划、数值、运营、商业化、客户端和项目负责人
拿去讨论。

## Source Prompt Assessment

`tmp/游戏策略大师Agent-System-Prompt.md` 的方向是合适的：

- 覆盖 RPG、SLG、MOBA、卡牌、休闲、二次元、模拟经营等手游品类
- 已经包含品类权重、评分锚点、核心循环、交叉影响矩阵、杠杆点和版本路线图
- 输出目标明确，适合内部策略和策划团队
- 相比普通游戏评测，更强调系统耦合、优先级排序和行动路径

但作为长期复用的跨 CLI agent，原提示词需要优化：

- 去掉“由元提示词自动生成”“可直接用于 Claude / GPT-4”等一次性生成说明
- 增加证据状态，区分用户提供信息、实际游玩记录、当前公开资料、稳定设计理论、
  假设和 `[Evidence Gap]`
- 增加实时核验规则，避免凭记忆引用商店评分、竞品机制、概率公示、营收数据、
  live-ops 活动或平台政策
- 信息不足时应降级为“策略假设”或“补充信息清单”，不能强行输出完整深度报告
- 把平台 wrapper、权限字段和部署说明从系统提示词中剥离到 `DEPLOYMENT.md` /
  `TOOLS.md`
- 把建议格式强化为“改什么、怎么改、预期影响、成本、风险、优先级、证据基础”
- 增加跨 CLI 部署说明和字段刷新策略

## When To Use

- 你有一款手机游戏，想判断核心循环、成长、经济、付费、社交或留存策略是否成立
- 你有测试反馈、用户评论、数据指标或策划方案，需要转成策略改版清单
- 你想知道某个痛点的根因在玩法、数值、经济、商业化还是体验层
- 你想比较不同改版方向的收益、成本、冲突和优先级
- 你想从竞品中提取可借鉴策略，但需要判断是否适合自己的游戏
- 你需要输出版本路线图，而不是只要一份体验评价

## Input

正式分析建议提供：

- 游戏名称
- 游戏类型
- 上线状态：研发中 / 测试期 / 已上线
- 平台：iOS / Android / 双端
- 当前版本号或测试包信息
- 核心循环描述
- 主要差异化卖点
- 养成、经济、付费、社交和运营系统概要
- 可用数据：DAU / MAU、次留 / 7 留 / 30 留、ARPU / ARPPU / 付费率、流失点
- 重点关注问题
- 可选材料：试玩记录、用户评论、商店链接、竞品名、截图描述、版本更新说明

缺少关键输入时，agent 应输出“策略假设”“证据缺口清单”或“补充信息优先级”，不能
假装已经掌握完整产品和市场事实。

## Output

根据任务需要，agent 可以输出：

- 快速策略诊断
- 深度策略分析报告
- 核心循环拆解
- 品类权重与评分
- 交叉影响矩阵
- 杠杆点识别
- 冲突检测与取舍建议
- 优化建议清单
- 版本迭代路线图
- 竞品参考与适配判断
- 证据缺口与下一步验证建议

## Evidence Boundary

这个 agent 可以离线分析用户提供的策划案、试玩记录、测试反馈和指标摘要；如果要引用
当前外部事实，例如最新商店评分、公开评论趋势、竞品当前机制、概率公示、平台政策、
版本公告、活动节奏、营收数据或行业案例，必须先核验当前资料。无法核验时标记
`[Evidence Gap]`。

## Source / Deploy Boundary

这里的文件是**源资产层**，不是三平台的直接运行文件。

本仓库中的这个 agent 当前只保留在 `agents/` 目录中，作为跨平台共享设计，
不在当前项目内实际安装到任何平台运行目录。

- 源资产：`agents/game-strategy-master/`
- Claude Code 部署目标：`.claude/agents/game-strategy-master.md`
- OpenCode 部署目标：`.opencode/agents/game-strategy-master.md`
- Codex 部署目标：`.codex/agents/game-strategy-master.toml`

部署细节、平台字段、wrapper 模板与刷新策略见 `DEPLOYMENT.md`。

## Validation Notes

如需把它真正部署到目标项目中的三平台，应至少检查：

- frontmatter / TOML 字段是否与当前平台版本兼容
- 目标平台是否具备 web search / web fetch 或等价能力
- 如果目标任务要分析商店评分、竞品现状、概率公示或公开评论趋势，是否允许实时核验
- 若只做用户提供材料的离线分析，是否接受 `[Evidence Gap]` 覆盖外部事实
- Codex wrapper 是否只使用当前官方支持的自定义 agent 字段
