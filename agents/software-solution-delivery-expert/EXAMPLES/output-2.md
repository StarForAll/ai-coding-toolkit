# Output 2

## 1. Outcome

输出一个面向“权限越权事故”的救火计划，包括处理优先级、修复路径、验证步骤
和客户说明要点。

## 2. Evidence Status

`Project evidence`

说明：此类问题优先基于现有代码、日志、查询条件、租户隔离实现和发布流程做判断。
如果后续涉及最新框架漏洞公告、云数据库策略或外部中间件行为，再补 `Verified live`
核验。

## 3. Scope View

- 当前阶段：故障救火 / 修复前评估
- 已确认事实：
  - 存在跨租户数据可见问题
  - 2 天内必须拿出修复方案和验收说明
  - 不能停服，但允许灰度
- 工作假设：
  - 问题由权限重构引入，可能在查询条件、服务层过滤或缓存隔离上失效
- 主要未知：
  - 泄露范围
  - 是否仅影响读取，还是也影响写入
  - 是否存在历史缓存或导出数据污染

## 4. Deliverable

### 处理优先级

优先级：`P0`

原因：

- 涉及租户数据隔离
- 属于客户可感知且可能扩散的权限事故
- 即使只读越权，也会直接影响信任与验收

### 修复路径

1. 先做影响面收敛
   - 临时关闭或限流受影响最明显的查询/页面
   - 必要时为高风险接口加额外租户校验
2. 复现并定位真实失效点
   - 前端展示条件
   - 后端查询条件
   - 服务层权限判断
   - 数据缓存或二级索引
3. 最小修复
   - 把租户隔离校验前移到统一入口
   - 对关键查询补强“租户 ID + 角色范围”约束
   - 为事故路径增加回归测试
4. 灰度验证
   - 先在受控租户集合验证读写边界
   - 观察日志、告警和客户反馈，再扩大范围

### 验证步骤

1. 构造至少两组不同租户账号
2. 覆盖受影响页面、API、导出路径
3. 验证普通成员、管理员、特殊角色的可见范围
4. 验证直接访问接口、刷新缓存、切换租户上下文后的行为
5. 增加一条“禁止跨租户读取”的自动化回归
6. 灰度阶段记录：
   - 是否仍有越权命中
   - 是否出现误拦截
   - 关键查询性能是否异常回退

### 客户侧说明要点

- 已确认问题属于权限边界异常，当前按最高优先级处理
- 当前策略是“先收敛风险，再做最小可验证修复”
- 本次修复会附带验收清单，覆盖越权场景回归
- 若排查发现影响范围扩大，将补充受影响范围和后续处置建议

## 5. Risks / Next Actions

- 如果问题同时影响写入、导出或缓存，需要扩大验证范围。
- 如果租户隔离逻辑散落在多层，修复时间可能受“统一收口难度”影响。
- 下一步应先锁定最容易造成扩散的接口并复现问题，再决定灰度顺序。
