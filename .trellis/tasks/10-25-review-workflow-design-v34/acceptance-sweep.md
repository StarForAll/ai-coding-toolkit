## 扫 2：项目层任务 P 的全部可达处置 × 入口 + 出口（A1）

| P 的处置 | 入口 | 出口 |
|---|---|---|
| 正常完成 | §5.3 人确认 | 归档“正常”，项目层收尾关卡 |
| 返工 P | §6.4（未归档 + 无记录 / 挂起） | R 完成后清挂起，继续 P |
| 替换 P | §6.5 发起 + 静态校验 | **继任者即新的 P**（本轮新增 §6.5） |
| 放弃 P | §6.6 发起 | **只走新建替代，替代即新的 P**（本轮收敛，删边会失去判定对象） |
| 挂起中被替换 | §6.5 L458 通用规则 | 新 P 继承含 R 的前置 |
| P 正常但未归档 | §9.1 L716 专行 | 类型 3（重新归档受守卫 / 改回无记录） |
| P 异常未完成 | §9.1 第一段 | 类型 5 向前完成 |
| P 已归档 + 无记录 / 挂起 | 类型 1 | 确认正常；确认异常时**须补出新的 P**（本轮补） |
| P 已归档异常 | §9.1 已收尾表 | 以继任者为项目层（本轮 §6.5、§9.1 说明） |

结论：扫 2 发现 2 处缺口——替换 / 放弃后无继任者（已修源条款），以及类型 1 确认 P 异常时无继任者（已修）。两处都修在源（§6.5 / §7.7 类型 1），引用处只加引用。

## 扫 3：对账修复类型 1–5 的产出态合法性（B9）

| 类型 | 产出态 | 合法性 |
|---|---|---|
| 1 确认“正常” | 已归档 + 正常 | 受“前置须全正常”守卫（原有） |
| 1 确认“异常” | 已归档 + 异常 | 组合表行 5 合法；未归档下游按 §7.4 处置（替换不可用于归档任务 → 删边）；P 须补继任者（本轮补） |
| 1 确认 P 异常且补继任者 | 已归档 + 异常 + 新 P 接位 | 合法；下游改由继任者承载 |
| 2 补建 R | 未归档 + 挂起 | 组合表“挂起”行合法 |
| 2 清挂起 | 未归档 + 无记录（前置可能含非正常） | 组合表“等待”行，合法 |
| 3 重新归档 | 已归档 + 正常 | **本轮补前置守卫**；前置不全正常必须先修边或改回无记录 |
| 3 改回无记录 | 未归档 + 无记录 | 等待行 / 就绪行，合法 |
| 4 修记录 / 删边 | 视修复结果 | 归档目标删到前置全正常才合规；未归档目标可放弃并重连（原有出口） |
| 5 向前完成 | 已归档 + 异常 + 下游重连 | 合法；重连到“正常但未归档”下游时由类型 3 守卫兜住（本轮补） |

结论：扫 3 只命中类型 3（已修），其余类型产出态均合法。
