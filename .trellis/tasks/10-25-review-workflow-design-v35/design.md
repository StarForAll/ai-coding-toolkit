# 设计：v35 审查以证据门槛为骨架

## 边界

- 只读审查：本阶段不改 `workflow-design.md` 与配套文档；产出 `review-report.md` + `acceptance-sweep.md`。
- 审查结论的证据链固定在稿内（§ / 表 / 行），不引外部最佳实践。
- 后续修复（同任务、另阶段）受「判定源唯一」协议约束：源先改、引用后跟、探针再跑、附录 C 最后记；主稿与配套同一提交。

## 结论分层的门槛

1. 候选 → 四道过滤器（F1 层 / F2 决策日志 / F3 留白 vs 冲突 / F4 失败模型）→ 连过四道的进反驳验证。
2. 反驳验证三步都要做完（反驳检索含配套与附录、端到端走到稿内出口、最简合规实现测试），再做作者反驳。
3. 只有「作者一句 § 引文能反驳掉」的候选才降级；反驳成功的留在主发现，失败的一句降为 W 项。
4. 主发现上限按实况，不凑数：本轮 2 条，都落在 v35 新修复动作与旧规则的交界。

## 拒绝的方向

- 不把实现细节（提交失败回滚、幂等实现、扫描算法）当设计缺口。
- 不把已声明的事实边界与有意取舍翻案（清单见 §0 事实边界、§0.1 口径 3）。
- 不为「更优雅」重排章节、改表结构；修复只准补判定 / 补同步 / 改措辞。

## 主要风险与对策

| 风险 | 对策 |
|---|---|
| 只凭印象挑三条老面孔（角色未镜像 / 人判未标 / 修复不自守卫），一条版本一个 | 先跑口径 10 三项全量扫，结果先落盘，扫出的缺口优先于印象候选 |
| 把「配套文档问题」当成「主设计缺陷」或反过来漏掉 | 口径 6/8 分层：配套内容差异只在违反主稿同步条款（§7.9）时才报，且以主稿条文为证据 |
| 探针红被当成结论 | 探针只作重复定义的事实基线，红则独立成主发现；本轮 9 条全绿 |
| 修 F2 时顺手改写替换流程 | F2 只在类型 1 的 P 分支补执行细则，§6.5 主体不动；改动后重跑探针 3/9 |
