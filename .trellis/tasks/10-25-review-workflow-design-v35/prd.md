# 深度审查 workflow-design.md v35 设计稿（按 §0.1 约束面）

## Goal

按 `docs/workflows/workflow-design.md` 自身 §0.1「设计稿自身的约束」对**该文件当前内容（frontmatter v35，含 v35 审查修复）**做深度审查，找出后续实现方案 / 模块实现 / AI 执行时会**被迫中途修改**的设计层问题，产出可被作者反驳检验的缺陷报告；报告确认后的问题在本任务内继续修复（用户已说明本任务后续可能承载修复）。

## Background

- 该设计稿已跨 v25→v35 十余轮审查收口。v35 刚完成一轮修复：补 P 的角色继任条款（§6.5）、类型 3 重新归档加前置守卫、§5.5 成立判定归人、§0.1 加口径 10（验收面全量审计）、组合自检表纳入 id_scheme 行号保护、术语补“替换/替代任务”、§9.3 补卸载例外、§0 纪律加表内判据要点例外。
- 明显重复已清，剩余问题只可能出现在**新引入收口规则与既有规则的交界**、**角色/镜像用例的未覆盖侧**、**防御态修复动作自身的合法性**、**新增条款与旧条款的适用范围冲突**。
- 本仓库有专门的审查协议与谓词登记表：`.trellis/spec/guides/design-review-thinking-guide.md`（四道过滤器、反驳验证、必附排除候选）与 `.trellis/spec/docs/index.md`（谓词登记表 + 探针）。审查必须按其证据门槛执行，否则产出的是候选清单而不是审查。

## Requirements

1. 审查对象**仅**为 `docs/workflows/workflow-design.md` 当前版本；`1.2-零补丁嵌入方案.md` 内容按用户要求忽略（仅作版本交叉核对）。
2. 按 §0.1 审查口径 1–10 执行：先判承载；只受理内部矛盾 / 跑不通 / 与不变量冲突 / 与真实场景不符四类来源；不把有意取舍、留白、工具选型、实现细节当缺陷；结论必须引用具体 § / 表 / 行。
3. 审查前先执行口径 10 的验收面全量审计（人判点标记、P 的全部可达处置通路上入口与出口、修复类型 1–5 产出态合法性），结果写入报告独立文件。
4. 按 `design-review-thinking-guide.md` 执行四道过滤器（F1 层过滤 / F2 决策日志过滤 / F3 留白 vs 冲突 / F4 失败模型过滤）+ 反驳验证（反驳检索、端到端模拟、最简合规实现测试、作者反驳）。
5. 跑 `.trellis/spec/docs/index.md` 的谓词探针，作为“重复判定已收口”的事实基线，结果写进报告（探针通过与否是客观证据，不是结论本身）；v35 修复涉及的探针预期值须逐个实测。
6. 交叉核对配套文档 `依赖机制设计说明.md` 的 `design` 字段与 `1.2-零补丁嵌入方案.md` 的版本标注；版本结论单独报告，不混进主发现。
7. 结论格式按 §0.1 口径 9：约束编号（A/B/§）+ 证据（§/表/行）+ 来源类型 + 影响（会在哪个阶段被迫改）+ 建议（优先补判定 / 删重复 / 改措辞；新增机制须标“超出本设计”）。
8. 报告必须含四部分：主发现、措辞/精度项、**排除候选（含理由）**、版本核对。
9. 用户口径：实事求是，不吹毛求疵；琐碎项一律进排除候选或措辞节，不许用推测的“实现成本”抬高严重度。

## Acceptance Criteria

- [ ] 验收面全量审计（口径 10 三项）执行完毕，结果落盘到 `acceptance-sweep.md`。
- [ ] 每条主发现都引用具体 § / 表 / 行，写明触发场景与“会被迫改的阶段”。
- [ ] 每条主发现都附作者反驳尝试与反驳失败的说明（或已降级为措辞项）。
- [ ] 报告含 `## Review conclusion`（计数）、主发现、措辞/精度、排除候选表（逐条给理由）、版本核对五部分。
- [ ] 探针实测结果记录在报告内；任一探针红则先作为主发现处理。
- [ ] 报告落盘到本任务目录 `review-report.md`。
- [ ] 排除候选表覆盖所有被否掉的高频误报族（留白、有意取舍、实现自由、外部篡改、派生层问题），并引用 `design-review-thinking-guide.md` 的已知误报族编号。
- [ ] 审查阶段不改动 `workflow-design.md`（只读）；修复另阶段进行。

## Out of Scope

- 实现方案 / 模块代码 / 目标项目运行验证（§0.1 口径 4、8 明确由实现方案承载）。
- 派生图 / 流程图与设计稿的逐行一致性（仅版本漂移报告）。
- 机制新增建议（除标注“超出本设计”的少数项）。
