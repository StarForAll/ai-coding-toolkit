## 上游吸收与用户裁决

- **机读触碰面**：STS 原文是完整边界已知时的文件锁，不是现成 PRD glob。借显式边界思想，自建 `touch_paths` 列表、批准快照与实际路径比对。用户明确选择：越界阻断继续执行，回 Plan 扩范围或确认必要变更。已贯通 §4.2、§5.3、§6.5、§8.2；语义验收和其他权限不因 glob 命中自动成立。
- **版本递增**：mcode-stack 固定提交的 `scripts/check.mjs` 仅在设置 `CHECK_BASE` 时执行版本检查。wf 只借发行前校验：发行资产/契约/清单变化形成新发行须 bump，未发布日常编辑不用每次 bump。N 由不可变源提交和资产清单确定，同版清单冲突拒绝；不把 marketplace 的条件照搬成工作区规则。
- **入口速查**：`stacks/ronny/WORKFLOW.md` 确有时刻→技能表。纳入 §8.1 后续使用文档交付，需依实际已安装命令和权限生成；不提前造一份可能与尚未实现 CLI 不符的使用手册。
- **观察期**：继续保持 D-2 未批准，当前不引入时间态；不搬 Guard、宿主 hook、团队 workspace 或平台矩阵。

## 防止新组合问题的推演

以下仅为正文规则的逻辑复核，尚无框架可执行实现，不伪称运行测试。

| 场景 | 正文结论 |
|---|---|
| 清缓存、重装或换 CLI 后统计 | 仍从 Git 跟踪的任务策展记录计算，不使用临时读取侧车 |
| 最近任务缺少策展字段 | 未知，不当显式空集合；回收观察窗口不足不列删除候选 |
| spec 新增不足 N 个正常任务 | 不列候选，不能用其存在前任务充数 |
| 活动任务仍引用 spec | 不列自动回收候选；人的专门删除/合并仍须处理引用 |
| spec 改名后旧归档路径仍在 | Git/变更记录映射后再统计，不能通过改写归档抹去历史 |
| Execute 发现新的治理 spec | 补入持久策展引用，同时实际读取；两个动作不等同 |
| 初始任务还没有项目配置 | 与基线同样自举，用已声明发行缺省，不被自己的前置卡死 |
| 只需修改一个项目阈值 | 同通道应用批准的配置变更，不强制重复改一份基线；检查成组一致性 |
| 框架升级带新默认值 | 不覆盖配置实例，按记录版本解释缺省；非法项不能静默放宽 |
| 接受了流程本地偏离，但新版 skill 换步骤名 | 核对兼容发行集，缺步骤/接口失配不能假称更新成功 |
| 修改 spec 或配置后仍有旧 Check | 内容/规范/配置版本进入检查有效性，旧 pass 失效并回 Check |
| glob 匹配业务文件但需求/权限不允许 | 仍阻断，机读路径不是产品范围或安全授权 |
| rename 只批准新路径 | 旧路径删除也须在批准范围内，否则回 Plan |
| 项目纯调查，`touch_paths` 为空 | 允许必要任务记录；不借空列表写业务/spec 交付物，若需另写交付报告先声明路径 |
| 新增交付触碰面，模型自行改 glob | 批准快照不对应，阻断；不会从 diff 自动扩白名单 |
| 控制记录落盘但没有提交授权 | 保留待人处理，不因为框架流程写了提交就获得授权 |
| 发行版本没变但清单变了 | 身份冲突；未发布的中间编辑则不用逐次发布 |
| 任务归档移动目录 | 产品正文只连稳定来源说明，不影响链接可达 |
| 自动刷新索引词面候选 | 只更新第三列，语义说明/核对状态不能被覆盖 |
