# 实现方案文档的技术设计（design）

本文件说明「怎么写这份文档」，不是框架的技术设计；框架的实现布局写在产出的实现方案文档里。

## 文档定位与边界

- 产物：`docs/workflows/wf-framework-implementation.md`，authoring 文档族，不进入目标项目发行清单。
- 权威顺序（沿用旧模块先例的结构，仅作结构参照）：charter（要不要做）→ 设计稿（怎么做/如何验收）→ 机制稿（schema/判定编码）→ 实现方案（布局/接口/命令/发行物）→ 使用速查（本文件末章，引用而非复述）。
- 不复制规则：每处判定只给「引用 + 实现落点（文件/函数/命令）」。任何"重新解释一遍门禁"的段落视为缺陷。

## 关键取舍

1. **不改上游四保护文件 → 入站指针落在机制稿**。机制稿 §0.1 的输入摘要绑定四份文件；机制稿本身不在其内，因此在机制稿 §12.4 加一行指针即可建立入站入口而不动摘要（2026-11-02 人裁）。索引表登记仍列为后续待办（须同批改索引、重算摘要、写回 §0.1）。
2. **引用前缀约定 + 机检纳入**。本文用 `本文 §x.y` / `机制稿 §x.y` / `设计稿 §x.y` / `charter Tn` 四种前缀；`scripts/check-doc-refs.py` 已扩展 `机制稿 ` 前缀与「列举继承」规则，本文随之纳入单文件机检（0 problem(s)）。
3. **不新增哈希域**。预览令牌绑定摘要用预览对象规范 JSON 的 SHA-256（不引入 `H("wf-preview-…")`），其余全部沿用机制稿 §1.1/§3.2/§10.2 已登记域名。
4. **命令面与操作面分离**。机制稿 §11.3 的 35 个操作（30 状态动作 + 5 只读断言）不自动成为子命令；文档给一张映射表，未映射的操作标注「无公开子命令」。
5. **轮次分界的可执行表达**。第二轮/第三轮条目在首轮命令面上的行为统一为 `WF_CAPABILITY_UNAVAILABLE` + facts 记未交付能力，避免"文档宣布有、实现没有"的静默缺口。

## 风险与回退

- 风险：把实现细节写成判定规则（越界到机制稿职责）。控制：每条规则句后必须能指到机制稿章节或标记为「布局选择」。
- 风险：命令清单过宽，变成"顺手新增入口"。控制：每条命令必须映射到一个已登记的机制操作或只读查询；映射不上的删除。
- 回退点：文档内 §9 单列未落地项；若复核发现某章越界，删除该章而不改动上游文件（上游摘要保持 4/4）。
