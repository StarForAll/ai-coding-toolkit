## 3. 本任务（P0）范围

1. **证据保存**：归档任务目录、4 份 Codex 会话 JSONL、`/tmp/wf-review` 分析整树、目标侧 `.wf/lib` 与源树的 diff + 校验和；证据可校验（可复算）。
2. **`protocol/` 骨架**：状态/转移、阶段模型句、阈值、错误码的机器可读单一事实源。
3. **6 条不变量断言**：可达性 BFS、门禁错误带可执行出口、`status.next` 与真实错误码一致、投影/骨架重建等值、文档机器事实与 protocol 一致、脱敏规则只增不减。

P0 退出判据：证据可校验；不变量测试可跑；protocol 能生成文档片段。

## 4. 明确不做（P0 之外，本会话禁止推进）

- 不实施 P1–P6 的语义改动（K1/K2 身份与租约、K3/K4 锚点与报告、审查闭环、vendor/授权/三段提交、审计与投影、命名解耦）。

- 不改 charter / 设计稿 / 机制稿 / 实现稿任何条款（含不按 v42 改上位文档）。
- 不做顺手重构；不动 `.trellis/` 之外的 Trellis 资产；不动上游 Trellis 仓库。
- 不提交、不推送（P0 交付后等人确认）。

## 5. 硬性纪律（违反即返工）

- **禁止补丁式修正**：动手前先回答 v42 §7.1 两问（① 它防的失败现在由谁覆盖？② 那个覆盖在什么场景失效？），答不出不写。
- **新机制只有两个入口**：K 类（不可观察/不可逆事实）或 S 类（不增加正常路径绕弯的支撑）。
- **每条新测试**须能回答「它防的失败实际发生过或可具体推演吗」；答不出就删；历史缺陷用 defect id 豁免。
- **单一事实源**：命令、参数、状态转移、错误码、阈值先写 `protocol/`，文档与 `wf help` 从它生成；任何地方手写第二份机器事实都算缺陷。
- **删除优于新增**；不新增阈值数字；核心代码不出现平台分支。
