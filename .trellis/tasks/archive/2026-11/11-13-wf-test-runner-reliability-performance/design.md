# wf 测试运行器设计

## Boundary

本任务维护作者仓库的测试资产。修改范围是 scripts/tests/wf_runtime/full 的运行器、夹具和 r68/r71，以及 scripts/tests/wf_runtime、wf_review 中的相关回归测试、相关 README/规范。产品 payload、发行产物和 Trellis 平台部署不因本任务重构。

保留 plan.py 作为选择唯一来源、results_gate.py 作为结果判定唯一来源、repro_select.py 作为 repro 选择与证据唯一来源。新增公共模块只承载重复的进程执行和夹具生命周期，不复制业务判断，不建立新的通用框架。

## 1. Evidence is input-specific

- 每个 case 的输入指纹由 case 脚本、目标文件、实际依赖 helper、相关清单/运行协议版本组成；目标不明不能认定新鲜。
- 分别记录 green/red 成功所对应的输入指纹与时间；both 是当前同一指纹的两面均成功这一派生事实，不是可继承时间戳。
- auto 只消费当前指纹对应的 red 证据；green 更新不得写入 red 事实。局部验证不得刷新其他 case 的 helper 事实。
- 旧 schema 没有完整证据时保留可读性但派生为需要 both，不伪造历史验证。状态提交由父进程唯一负责，写入失败必须返回给运行器。
- 运行中固定指纹，提交前核对输入未变化；不把运行中修改后的摘要写成此前测试的证据。

## 2. One bounded execution mechanism

将 repro/_worker.py 已有的进程组超时能力提取到 full 下的公共执行模块，并用于 suite、flow、extra、fixture/init 与 repro。shell 保留计划编排和兼容入口，执行模块负责 argv、cwd、环境、完整日志、单调计时、退出码、超时/取消分类及结果原子写入。

执行器只按 argv 启动命令，不将路径或结果数据重新拼接为 shell 代码。超时和父进程中断终止对应进程组；捕获信号、关闭文件及写结果在同一生命周期中处理。交互 helper 的等待受外层执行截止时间覆盖；必要的提示读取使用有界辅助函数，不用在阻塞读取之后才开始计时。

所有调用点通过同一实现获得可定位结果；不再各自捕获输出后按不同规则判断。负路径内部预期失败仍由测试断言消费，不误当成夹具前置失败。

## 3. Owned fixture lifecycle

- 新公共夹具模块集中处理路径规范化、禁止目标、重叠关系、所有权标记、创建/重建/清理。
- 删除前验证目录确属测试工具，默认使用运行/套件作用域的独立目录；用户指定非空无主目录拒绝，不以参数存在等同授权删除。
- 覆盖 wf_fixture.sh、f2_setup.sh、模板目录和复制分支、F0 以及 run_one.sh，不能只保护直接入口。
- 固定 /tmp 路径尚未迁走的历史套件继续受运行级独占约束，持锁范围覆盖共享夹具和发行准备，子调用复用同一运行所有权，避免父子互锁。
- 夹具副本必须独立；保留 template_check.py 的重指与空态校验。动态任务状态不做跨 run 缓存。
- user namespace 的共享发行挂载必须确认 bind 与只读设置成功；原始来源路径同样纳入访问方式审查，不能只把一个别名变只读便声称所有路径只读。来源前后摘要作为第二道校验。

## 4. Results and measurements

每个执行单元的身份由计划中的 kind/name/phase 共同决定。结果包含 schema、身份、模式、argv/cwd、rc、status、timeout/cancel reason、耗时与 log_path。父进程按计划逐项核对恰好一份结果，并检查 rc/status/mode/phase 的一致性；repro 两面结论与 verified 由字段派生。

对已有文本测试输出暂保留适配，但集中解释；拒绝空输出/零断言、不能依赖未锚定的 PASS 子串或 status 字符串。多名称列表跨 shell 传递必须正确引用；结果缺失、重复和畸形不能被 eval 或 fallback 吞掉。重试区分基础设施失败与业务失败，保留每次尝试，不用后一次覆盖前一次证据。

summary 分开提供 requested_jobs、effective_jobs、执行分支/退回原因、各阶段墙钟和跨单元累计时间。旧字段在兼容期说明语义；移除伪毫秒精度。full、subset、representative 结果不混为同一性能样本。

## 5. r68/r71 migration

先建立任务内 assertion-map.md，逐条读取 rec() 对应的可观察行为。字段组合和判定变体迁入现有 wf_review 测试 harness，必要时补最小 CLI 测试；保留正常链路、导入后锚点失效、拒绝后 result/attempts 不写错误事实、交接代次失效、repair/dispose 锁内重核和部分写入恢复。

原 r68_tests/r71_tests 名称仍可选择并代表其保留的集成场景。拆分后的 suite/tag/module/串行原因和覆盖映射同批更新；完整收口由单元层加完整运行层共同证明。执行单元数变化必须解释，不能据套件数量变化直接声称覆盖等价。

## 6. Compatibility, risks and rollback

| 风险 | 处理 |
|---|---|
| 旧 both 时间戳无法证明当前输入 | 旧状态安全失效并要求 both，不回填可信事实 |
| 旧夹具无所有权 | 明确拒绝，提示换新临时目录；不静默清理 |
| 父子执行锁互锁 | 运行所有权传递有专门子调用测试，不重复竞争同一独占锁 |
| readonly mount/unshare 受宿主限制 | 实际能力和回退写入结果；权限边界拒绝不绕过，必要时走正式授权 |
| 迁移丢失写入拒绝/恢复断言 | 对照表逐条映射、代表反例注入、全量和候选闭环 |
| 性能被测试环境或覆盖缩减污染 | 固定来源/模式/实际并发，成对中位数，保留原始日志和行为清单 |

按证据层、执行层、隔离层、慢套件四步增量落地，每步回归；出现不可归因差异时停止该步并排查，不叠加新开关掩盖问题。新缓存 schema 不改历史被测项目；回退代码仅导致测试证据需重做。无提交授权时保留可审阅工作区，不自行提交。

## Planning self-review

按 proposal-self-review 十条检查，补齐三处原先容易遗漏的契约：旧证据失效、父子取消与夹具锁生命周期、按独有断言而非套件数量比较覆盖。每个派生事实指定唯一实现；结果的缺失/损坏/矛盾分别归因；写操作覆盖首次、同所有者重建、无权拒绝。无待用户选择的产品分歧，仍需最新方案的实施批准。
