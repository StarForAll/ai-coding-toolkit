# 技术方案

## 章节引用检查

在 `check-wf-analysis.py` 内替换整个引用检查段。删除全局 `refs/live` 分支及单独的二级扫描，统一执行下面的过程。

1. 用同一条编号规则提取标题和引用中的完整编号。每段由数字和可选的单个小写字母组成，点后紧跟数字才属于编号，所以 `§2.` 的末尾句点不计入编号。先取完整编号，再检查深度。只有一、二级编号能由 `##` 或 `###` 标题登记为目标。标题允许编号后接空白、标题句点或行尾。
2. 只为引用检查计算历史豁免区间。起点是编号恰为 `9` 的 `##` 标题，终点是下一条 `##` 标题或文末，下一条标题可以不带编号。没有起点时检查全文。章节目标仍从全文收集，正文可引用 §9。原有 `hist_start` 的计算、撤回词和矩阵标签的 `lines[:hist_start]` 保持原样。引用扫描使用自己的区间和原始行号。
3. 按出现顺序在历史段外逐行检查。完整编号在标题集合里即通过。未登记或超过两级的编号按现有 `[引用] L<行号>` 格式报告，由原有问题汇总返回退出码 1。

沿用校验器的文件布局、输入格式和无参入口。每个用例在自动清理的临时目录中，把实际脚本、当前完整方案文档和行号检查所需的 `wflib/*.py` 复制到相同相对位置，只修改自己的文档副本。用 `subprocess.run([sys.executable, …], capture_output=True, text=True)` 执行副本，统一等待进程退出并关闭管道。以退出码和 stdout 的诊断判断结果，stderr 用于解释意外失败。这个布局保留判据表等其他检查的真实前提，修改前也能用同一入口证明漏检。

回归矩阵包括原始副本通过，有效一级、二级、字母后缀及句末点号通过，悬空一级、普通二级和 `§6a.1` 失败，`§6a.1` 有完整标题时通过，带有效前缀的三级编号失败。历史测试在 §9 内放一个缺失编号，继而在其后的同级小节放同样的引用，分别断言通过和失败。没有历史节时，仍检查尾部引用，`## 9.1` 不能开启豁免。负例同时断言退出码、引用类别、完整编号与行号。

历史边界回归还要覆盖另外两个消费者。在 §10 加入会触发旧规则的撤回词 `certain` 和废弃标签 `A 档`，应继续通过。把同样的内容移到 §9 前，依然报告 `[撤回词]` 和 `[标签]`。这组用例能区分引用覆盖扩大和其他两项检查误扩。

## 文件句柄与验收

逐项处理 PRD 的 R2 清单。整文件文本使用现有风格的 `Path.read_text(encoding="utf-8")` 或上下文管理器。流式行数统计和 `json.load` 使用 `with open(...)`，避免顺手改变解析。夹具写入在 Git 读取前完成并关闭，保留工作树内容和测试断言。

资源验收以三个外层进程的实际退出码和完整 stderr 为输入。启动时用 `-W always::ResourceWarning` 让每次目标告警落到 stderr，外层在进程退出后检查类别和消息。这样也能覆盖进程退出时才输出的文件告警，且不会把预期的 runner 诊断错认成未关闭文件。验收命令放在本任务工件中，不改变 unittest 的全局警告策略，也不增加通用测试运行器。用旧代码先观察一次拒绝，修正后再执行同一门槛。

## D3 指向核对

`check-wf-analysis.py` 只核方案内的引用可达性。`check-doc-refs.py` 默认不读 backlog，而且跳过单级引用。用 AC4 的源文到目标核对确认两处 D3 的语义落点，覆盖自动检查无法判断的部分。
