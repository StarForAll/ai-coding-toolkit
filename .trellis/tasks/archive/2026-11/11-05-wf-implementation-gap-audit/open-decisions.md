## OD-8：C2「复制不构成接管许可」的调整方式 — 选 C（分级）（2026-11-08）

- **原文**（设计稿 §1.3）：会话标识是「路由标识而非凭据或人批准证明，**复制到另一会话不构成接管许可**」。
- **冲突**：自动模式身份由锚点派生，同一执行边界内的进程自动同身份 ⇒ 原承诺"同边界内没有另一个会话"被架空。
- **可选**：A 纯接受（同边界即同一执行者）/ B 纯阻断 / **C 分级**。
- **人裁**：**选 C**。
  - **可检测**：当前 root 未登记且该会话另有存活 root ⇒ **阻断**（`concurrent_unregistered_caller`），人调 `start` 显式登记后才放行；
  - **不可检测**（同一宿主进程内多聊天，同 root）⇒ 合并 + 披露（矩阵已声明不可检测）。
- **理由**：保住原承诺中"能检测到的那一半"；同时不假装能区分同一进程内的多个聊天。
- **连带**：§3.7 C2 行、§2.3d 分级规则表、§5 矩阵、§9 判据 7/7a'、§6 强度④ 已同步；"复制标识"在自动模式下本就无效（拷文件不改锚点），显式模式保留原语义。

## OD-9：C1 身份粒度 — 取 ①（执行边界）（2026-11-08）

- **原文**（设计稿 §1.3）：「采用经目标宿主核实、压缩后保持不变且**新会话不同**的稳定标识」+ environment 行「多会话分别绑定、串行写入」。
- **冲突**：聊天级粒度（原文理想）在禁止宿主适配的前提下**无信号可识别**；实际可实现的只有"边界"或"进程"两层。
- **三选项**：
  - ① **执行边界**（终端 leader + 进程链）：压缩/重启连续；**一个终端只能干一个任务**；
  - ② **进程 root**：同终端两 agent 是两个会话，但**每次重启都算新会话**（要重新绑定 + 旧会话先释放写权）；
  - ③ 聊天级：不可实现（需 per-agent 适配，被约束①禁止）。
- **人裁**：**取 ①**。
- **理由**：② 会把"重启"从"重新启用"退化为"重新绑定 + 释放写权"，在 dogfood 中是高频摩擦；① 的代价是可管理的使用约定。
- **连带**：§3.7 C1 行、§3.7g（R5 逐字改写文本 + 4 项核对清单）、§3.7f 待裁清单已同步。
  **使用约定**：一个终端同时只推进一个任务；并行请另开终端/窗口；同终端第二个 agent 须人 `start` 显式登记（C2 分级），且此后与前者**共享同一会话**。
