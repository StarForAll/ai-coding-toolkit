# wf 机制设计文档开发视角深度审查

## Goal

以 `docs/workflows/wf-framework-design.md`（及其关联 charter / index / sources）为要求与约束基准，从**实际开发（实现者）视角**深度审查 `docs/workflows/wf-framework-mechanism.md`，找出仍存在的不足、矛盾与缺漏，给出可落地的改进建议；同一任务保留后续修复入口，修复按用户另行批准后在本任务内执行。

## Requirements

- 审查基准：机制稿的行为契约必须与设计稿/charter 一致；上位判据未给出答案时按 charter T1 与设计稿 §1.5 交人裁决，审查者不自行改写上位规则。
- 不偏离初衷与核心：charter 四目标、T4 不可削减项、设计稿既有承诺不得以实现成本为由削弱；建议不引入目标外机制。
- 审查视角：实现者视角——schema 可实现性、算法确定性与可复算性、状态机与门禁完整性、跨文档字段/语义对应、恢复与幂等路径可走通。
- 实事求是：只报告影响实现正确性、契约一致性或可落地性的问题，排版/措辞类忽略；不把 C 级夸大为 A/B。
- 输入绑定：审查对象为工作树当前版本（机制稿 1090 行），并核验机制稿 §0.1 四份输入摘要与实际文件一致。
- 产出：分级的审查发现清单（A=上位矛盾 / B=实现不可判定或缺漏 / C=可改进），每条含定位（文件+行号）、证据、影响与建议，落盘至本任务目录供后续修复使用。

## Acceptance Criteria

- [x] 已通读机制稿全文与设计稿/charter 全文，并核验 §0.1 四份输入 SHA-256 与实际文件一致
- [x] 已运行 `scripts/validate-wf-design.py` 并将机检结果作为证据（机检绿不等于语义通过）
- [x] 每条发现含定位、证据（原文引用）、影响面与改进建议，且不与前序任务（11-02-wf-mechanism-review）已闭合项重复
- [x] 明确声明覆盖轴与未覆盖轴，A/B/C 分级准确，未发现 A 级时如实说明
- [x] `findings.md` 落盘并向用户完整汇报
- [x] 后续修复以本清单为输入逐条处置并留痕（两轮：六项确定性项 + 六项用户裁定项）

## Notes

- 本任务为审查型任务，PRD-only；若修复阶段涉及上位文档（design/charter）修订，须按 charter T7 同批义务执行并另行确认。
- 机制稿 status 自称 2026-11-02 人工审查通过；本次是下一轮独立复审，结论只按已覆盖轴表述。
