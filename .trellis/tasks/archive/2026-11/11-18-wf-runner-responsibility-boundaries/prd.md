# 收敛 wf 测试入口职责与验收边界

## 目标

使 wf 作者侧测试入口可靠地回答本次实际测了什么、结果如何、现场是否安全收尾。日常回归、正式候选验收和历史材料维护各有可验证的职责。本次关闭 F1–F5，并将这些边界写入仓库维护纪律与行为回归。

任务处于 `planning`。本稿经用户审查并明确批准后，实施才开始。

## 背景

- 仓库的 T1 是定向回归，T2 是 dev 全量收口，T3 包含 red/green 和候选代表集安装闭环。入口也支持独立 repro 与候选全量。见 [现有交付纪律](../../spec/docs/wf-delivery-discipline.md#8-收口前的最小证据集四层)。
- 默认运行会轮转历史结果、观察管理根，并在可用时复用跨次模板。候选、结果和证明链有真实隔离需求。审查以一次运行需要消费的资源和产出的结论为依据，执行耗时不设交付阈值。见 [当前资源准备](../../../scripts/tests/wf_runtime/full/run_all.sh#L137) 和 [当前管理入口](../../../scripts/tests/wf_runtime/full/README.md#存量盘点与精确退役唯一入口)。

## 审查发现与要求

F1–F5 对应首次审查确认的五项缺陷。R1 是默认职责调整，R7 是维护约束。

| 发现及证据 | 要求 | 验收 |

## 验收标准

- [ ] **A1（R1）** 正常与异常历史材料预置在受控范围内，单套件、dev 全量、独立 repro 的常规模式仍可运行。历史目录和共享缓存的字节与目录项保持一致。本次写入清单符合设计。无显式目的地的 help/list/dry-run 零写入。显式缓存和维护入口各有正负对照。
- [ ] **A2（R2）** 执行及显式预览分别覆盖新、空、plan-only、finished、active 和无主目录，按设计的唯一表验收，重复执行可换新路径。含手工 `*.json/`、同名 `logs/` 或替换 `summary.json` 的历史树保持字节和目录项不变，直至目录下列出的内容获得显式放弃授权。轮转只报告。退役覆盖完整预览、无授权、错代、并发占用、预览后增改、未获授权项和合规删除。
- [ ] **A3（R3）** 在候选 worker 启动后取消，或在终核阶段取消、校验失败。退出非零，进程与回收事实准确。已确认可删除的本代夹具被回收，未确认现场有原因和定位。取消后可重取应释放的租约并用新目录重跑。另覆盖 dev 及候选正常成功的对照。
- [ ] **A4（R4）** 有合法冻结 bundle 时，任一相位满足 `planned = passed + failed + unverified`。缺记录、坏记录、错代、无可验证终态和清理未确认按相位给出未验证事实，其余用例统计可见。仅本次报告的运行保持共享 proof 字节不变。显式 dev red/both 与 candidate auto 的证明传递有新鲜与失效对照。
- [ ] **A5（R5）** 候选子集、代表集、全量以及 audit 对相同执行单元的资格一致。全量不把源码安装器路径计入候选通过。代表集保留实际由候选安装的 f0、规格流程和安装 repro。R72 的卸载场景与 R67 迁出的故障传播断言都有可追溯的前后覆盖对照，审计和基线按实际结果更新。
- [ ] **A6（R6）** 发布任一必需文件失败、成功提交前收到取消、证据不足或候选身份不一致时，退出非零，无 `GATE-OK`，也无本代正式通过记录。正常通过只有一次正式提交，日志、摘要和退出码一致。按迁移表验证新读者、历史读取，以及 `finished+cleaned` 但摘要未提交的状态。
- [ ] **A7（R7）** 入口到写入、终态消费和覆盖分母三条调用链均完成审查。原有受支持模式通过实际入口验证。新规则在交付纪律、runner 用法及行为测试里一致。交付按 F1–F5 逐项引用表中对应验收及实际证据。

## 范围

作者侧 `scripts/tests/wf_runtime/full/`、`scripts/tests/wf_test_release.py` 及实际依赖的作者侧公共 helper、相关测试、用法与交付纪律。

产品 `payload`、生成发行树、上游 Trellis 和一般流水线设计属于各自的独立交付。性能纪录、更多可选运行档位、无调用方需要的协议扩展不计入本次验收。
