## 启动形态的推荐方案

建议采用项目内 Python 入口（规划名 `.wf/bin/wf.py`），文档 `wf <操作>` 只是该入口的短称，不要求 PATH 或另装 POSIX shell。标准调用为 `python3 .wf/bin/wf.py <操作>`；系统 `python3` 不可用时，可由人/宿主显式给出一条已可用的 Python 绝对路径启动同一入口，该路径只负责引导，不代替 §1.1 的目标执行器解析。

引导段仅用标准库，确定目标项目、只读解析三级配置、校验所选执行器后移交业务子命令；不在引导解释器中继续执行判定/修改，选择失败照原阻断，不静默回退。repair/uninstall 仍是独立、单文件、不导入运行时的入口；配置失效时用系统或人显式选择的可用 Python 直接运行，投放/重取路径由安装清单及恢复说明列明。安装前从人检出的发行源码运行同样的自包含入口，不假设目标 `.wf/` 已存在。

此方案不把系统 `python3` 别名作为唯一启动条件，也不新增全局配置键或永久的第二执行器优先级。进程转交、参数编码及文件布局实现仍由机制设计承担；若人工不接受此形态，A3 须另行裁决后才能改写相关契约。
