# 审查与修订 wf 框架设计契约

## Goal

在同一 Trellis 任务中完成设计审查与经人批准的修订，闭合独立 wf 的入口、会话退出/恢复、工作流动作、审查与验收契约，同时保持原有核心定位和必要控制强度。

## Background

- 初始基线 `d4b7a87`，分支 `main`；创建前无活动任务。
- 初报见 [review-report.md](./review-report.md)，2026-11-01 的人工裁决、命令证据、误报纠正和根因见 [decisions.md](./decisions.md)；后者是当前问题处置依据。
- 用户接受 F2/F4，指定 F1 的安装核验方法，明确 F3 在 wf 完成后适配；规划已获批准并启动实施，修复后仍停在人工审查。
- 首轮 F2/F4 修订保留为未提交成果。用户随后提交 A1-A3、B1-B5 及七组补充意见；逐项核实、回 Plan 形成具体方案后，用户已明确批准。第二轮在原任务完成两文件修订，仍为 `in_progress`，等待人工复审，未获收尾许可。
- 第二轮逐项证据、根因、部分不成立前提及推荐取舍见 [revision-2-review.md](./revision-2-review.md)。这是本轮规划依据，不把用户的全部缺陷定级直接视为实测结论。
- 第三轮用户明确批准 [revision-3-review.md](./revision-3-review.md) 及“WIP 保留后释放、仅限同一对象恢复”。已在原任务完成两文件修订，过程与对象哈希见 [revision-3-validation.md](./revision-3-validation.md)；保留前两轮成果和用户文件，任务仍 `in_progress`，待人工复审，未获收尾许可。

## Requirements

- R1：只用本任务，不创建子任务或其他任务、不派发子代理。首次进入实施须批准规划后 start；在途任务的新一轮实质契约修订先回逻辑 Plan，保留任务身份和原成果，批准新规划后再继续。
- R2：遵循 `.trellis/spec/docs/index.md`、`wf-design-revision-gate.md` 及相关 guides；定义、实际消费、验收与索引同批核对。
- R3：保持单人、本机、单共享工作区、串行写入、顺序工作流、本地完整路径；不引入团队、服务、外部 MCP 或 Trellis 必需依赖，不混用旧内嵌模块规则。
- R4：每个问题据当前条款和场景核实根因；区分真正缺口、已定义行为和明确延期的交付，不为形式完备新增机制。
- R5：保留初报、人工裁决与修正判断的证据关系，不把静态推演或机检称为实现运行结论，不重提已修复旧问题。
- R6：产品写入边界只有 `docs/workflows/wf-framework-design.md`、`docs/workflows/wf-framework-design.index.md`。前两轮均在用户批准具体规划后实施；第三轮按当前取舍重新审阅后再实施，需扩大文件边界时回 Plan。
- R7：修复后停在待人工审查；人工审查通过并明确要求收尾后才可收尾。未授权不提交、amend、推送、开 PR、归档、finish-work 或写收尾日志。
- R8：保留初始用户变更 `.agents/skills/grill-me/`、`.unipi/`、`skills-lock.json`，不触碰它们。
- R9 / F2（P1）：复用 §5.8 已有任务/人判两类步骤，补 §5.7 中任务内动作说明、验证引用、输入绑定和恢复边界，§5.8 只消费它。原证据：`wf-framework-charter.md:43`、`wf-framework-design.md:330-340,352,372,541`；须与 §4.2 批准/检查、§4.4 交接和 §5.4 中断核对相容。映射 AC6。
- R10 / F4（P2）：§1.1 执行器解析只约束目标项目侧安装/升级/日常入口及 repair/uninstall；§8.1 的 authoring checker 依源仓库执行环境规则运行，不借目标配置、不随目标投放。保持三级解析、失效阻断和两个恢复入口回退。证据：`wf-framework-design.md:46,479,539`、`wf-framework-charter.md:124`、`wf-design-revision-gate.md:24`；引入点为 `80d17f4` 的执行器条款。映射 AC7。
- R11：首轮 F1 采用用户指定 dry-run 安装核验，实测见 decisions.md；第二轮只按新意见 C3 澄清安装线索、纯残留和激活注入的边界，不增加宿主检测机制。F3 为 wf 完成后的适配，本轮不改共享 skill。保留原证据 `wf-framework-design.md:149,454,529,542,594` 和两侧 skill 参数表；reviewer 的 canonical path 可由传入审查根匹配，不再列为路径冲突。
