# 裁定记录：身份口径（阻断 002）

裁定人：用户（2026-11-09 13:53）。本记录是 P1 的实现契约；上位文档的对应条款仍需人审改写（见 §4）。

## 1. 裁定原文（逐字）

> 适配层把 DSH/宿主会话 id 映射成 provider=host 的 session_id；进程锚降为冲突判据与兜底，不仅仅是 dsh，其他的也是先使用会话 id

## 2. 实现契约（P1 按此实现）

### 2.1 身份解析优先级（唯一次序）

| 序 | 来源 | 入口如何得到 | 失败/缺失时 |
|---|---|---|---|
| 1 | **宿主会话标识** | 宿主/适配层映射进请求信封：`provider=host`、`identity={host_id, session_id}`；入口**只从信封读**，自己不读环境变量或命令行 | 缺失 → 退到第 2 序，并在 `facts` 里显式记 `host_identity_absent` |
| 2 | **进程锚**（会话 leader → 进程链） | 现有 `session.candidates()` 的 L1/L2（`sid`+`sid_start`、`pid`+`start`+`exe`、`boot_id`） | 两者皆无 → 第 3 序 |
| 3 | **无身份** | — | `WF_IDENTITY_UNRESOLVED`（needs_decision）+ 人调用 start 的出口 |

- **进程锚的新定位**（裁定要点）：它**不再是主身份**，职责收窄为两件事——① **冲突判据**：宿主标识与既有绑定/租约不一致时，用进程锚事实判断"是不是同一执行边界"；② **兜底**：宿主未提供标识时才作为身份来源（此时按机制稿 §1.4 的「不猜环境变量」原则，只报事实、不猜）。
- **对全部宿主生效**，不限于 `dsh`；`codex`/`zcode`/`pi`/`cursor`/`geminicli`/`copilot`/`claudecode` 同一条优先级。
- **平台知识落点（S12）**：每个宿主"会话标识从哪取"属于**安装期部署表 + 宿主适配层**，不进语义层。`session.candidates()` / `cli.py` 不得出现宿主分支；缺映射的宿主按 S12 ③ 走「适用性未知 → `WF_SEMANTIC_DECISION`」，并给 `--skill-root` / `--platform none` 两条出口。
- **机制稿 §1.4 禁令的边界**：允许的是"适配层把宿主上下文映射进信封"；禁止的是"入口自己读环境变量/命令行覆写身份"。裁定不解除后者。
- **`/clear` 的修复点**：宿主在 `/clear` 后给出新 `session_id` → 新身份 → 旧租约按 K2 的 `generation` 失效（dogfood A1）。宿主不提供标识时，必须**显式报告"该宿主无法区分 /clear"**，不得静默复用旧绑定。
- **冲突不猜**：同一身份出现不同实例标识、或宿主标识与进程锚指向不同会话 → `WF_IDENTITY_UNRESOLVED`，问人一次并钉住（钉住记录的层次待定，见 §3.3）。

## 3. 连带必须同批处理的事实（P1 范围）

1. **`identity.path` 是未登记配置键**：`cli.identity_path()` 直接读 `.wf/project-config.json` 的 `identity.path`（`P1|P2|P3`），但机制稿 §8.1 的配置表没有这个键（`protocol/thresholds.json` 的 15 个键里也没有）。这违反「未知/非法键不静默」与单一事实源（纪律 #4）。P1 必须二选一：登记进 §8.1 + protocol（并给缺省与非法出口），或删除并由新优先级取代。**倾向：删除 `identity.path`**，其"信任哪条锚"的含义已被 §2.1 的固定优先级取代；删除优于新增。
2. **`identity_store` 的 `five_state` / `rotate` / `mark_superseded` 属 v42 §4 必删项**，删除须与 K2 的 `generation` 接管同批落地，否则两套失效判定并存。
3. **钉住记录（`enable --identity`）**：`enable` 已是既有命令，裁定不要新命令则用参数；记录的层次（committed 项目配置 / runtime）与"是否算 `by=human` 的声明"仍需人给一句话。
4. **多源冲突的新形态**：宿主标识与进程锚**不再并列**，所以"冲突"只剩两种——同身份不同实例标识、以及兜底场景下 L1/L2 互指不同会话。P1 的用例要按这两种写，不再写"四档冲突"。
