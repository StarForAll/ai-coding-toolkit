## 方案自查与主动修正

| 清单项 | 核验/修正 |
|---|---|
| 1 唯一产生函数 | 将 runtime、release subject、red subject、execution fingerprint、final plan 各自列明产生点；env/TSV 不再复制权威 |
| 2 反向规则 | cache miss 只重建；成功发布后才收敛旧槽；candidate 缺 red 出口是同主体 dev red/both，显式 green 不伪装获得 red |
| 3 身份域 | red 比内容主体，green 比本次执行；dev HEAD 与 dirty 内容都在；工具/SUT、候选 tag commit 各有归属 |
| 4 首次/幂等/重做 | journal 首次 old-absent、正常命中、旧 cache 重建、失败恢复；普通 plan/显式 plan/真实 prepare 时点分开 |
| 5 事实归属 | legacy 保留但不算 proof；不同 release 槽不归本轮自动清理；bundle/context 变化使整次提交拒绝 |
| 6 错误出口 | busy 等锁释放重试；pending journal 用 ensure 独占恢复，check 保持只读；两代都不可验证保留现场，不清空缓存掩盖错误 |
| 7 阻断作用域 | release 竞争不改输入；candidate auto 拒绝不禁止显式 green；list 不因活跃全局 fixture lease 而被拦 |
| 8 读取/归因 | missing/corrupt frozen bundle 直接拒绝，current fallback 删除；source 不可读不当成 cache miss；未受控候选修改在起止 barrier 检测 |
| 9 迁移 | cache meta 失效重建；state 1/2→3 只 legacy，不推导 red；无主路径/损坏 journal 原地保留 |
| 10 数字/引用 | AC1-AC10 与 V1-V12 逐项映射；只读 link/whitespace/schema 检查，未执行实现级测试 |

额外发现并在本轮设计中修正的风险：

1. 发布锁若只保护 ensure、未覆盖消费期，手工 ensure 仍能替换活跃 runner 的发行树；新增持锁消费 wrapper。
2. 先 ensure 再释放/降级重拿锁存在接力假设；选择消费期保持同一独占 fd，明确外部 check busy 的代价。
3. user namespace 中读取宿主锁 fd 不总可行；namespace worker 由宿主 parent lease 和只读 bind 保护，只让宿主嵌套 repro 验证 ancestor lease。
4. 显式 plan 镜像可能覆盖活跃 final plan；results-root 的同一互斥锁覆盖镜像短写和真实运行生命周期，不碰普通无显式计划分支。
5. 旧 schema/输入过期的 backup 也应能恢复；journal 校验旧代字节/归属，不用当前新输入 freshness 判回滚资格；首次无旧代有独立撤销规则。
6. 新 context 不能强迫 repro list 先构建或探测 runtime；独立纯 select_cases 路径兼容原有列表输出。

### 主动回扫

按方案自查十条核对本轮波及的唯一来源、身份域、三态、所有权、错误出口与引用，额外补齐三处紧邻边界：

1. 同一 root 换 WF_RESULTS_CACHE 或嵌套目录不能得到另一把不相关的结果锁；UID 固定锁覆盖所有官方写者，嵌套必须验证继承，不能在持锁父下再申请一次。未授权新增 per-root 锁没有已部署遗留，不编造删除迁移。
2. 父 release context 必须在主 prepare 之后写到外层目录，不放在内层 repro 结果目录；内层 prepare 会删除旧 JSON，因此 handoff 不能置于会被自己清理的目录。context 文件缺失/损坏或请求身份冲突必须拒绝，不以独立 ensure 作为“恢复”。
3. 新内部继承入口必须先于旧 dev 参数拒绝分支分流，否则父传入的已核 version/ref 会触发原有 dev --release-* 拒绝；独立入口仍保持这条既有边界。candidate 无 release flock 不得伪造 dev 继承标识，仍由父 fixture/结果锁与内容/tag barrier 约束。

本轮要求是把已有方案的协议与验证写完整，不是执行修复。所有并发、嵌套 repro、prefix 读取范围与 final plan 校验仍须实施后实证。

### 方案自查十条的本轮落实

1. 唯一产生点：固定 frame encoder/decoder、scope resolver、纯 validate_repro 与受校验 commit_state，不在 G 与 S 再写两套结果解释。
2. 反向规则：测试域只转移其 own 数据，不能解除生产锁；坏 handoff/frame/lease 必须拒绝，不能 fallback 新锁或独立发行初始化。
3. 身份域：明确 host/test/unit-mount、tool/SUT、controller A/execute B、R/G/S 的 scope；核 kernel 身份而不是把 env flag 当锁证据。
4. 首次/幂等/重做：scope 一次创建多 run 一个结果锁，成功清理前先终止子进程；plan mirror 与真实 prepare 的时点仍分开；没有改 cache/state 旧迁移契约。
5. 事实归属：candidate 起始 validator 归 R，末次完整输入重核归 S，G 只读摘要；原始 token 在 R 内存，TSV/env 不成为第二份 context。
6. 错误出口：结构坏/输入变/租约失效不提交；普通 case 失败只挡该 proof，其他 eligible case 沿原有 partial-update 语义；writer 失败最终非零。
7. 阻断范围：生产全局 fixture 慢测前提明示；普通 list 不取任何锁；新增 scope 结果操作可隔离，不承诺所有 full fixture 测试可与真人 run 并行。
8. 读取归因：candidate 完整 check 不缩成 verify_repo；所有内部 frame 在公开 parser 前验证，final plan/inputs 同字节核验后解析。
9. 旧记录迁移：前两轮未实现的 UID-only/parent 模糊协议为方案演变，不编造已部署数据迁移；原 cache meta/state schema 迁移仍保留。
10. 数字/引用：当前 AC1-AC16、V1-V18；复核 source 行号与任务本地链接，并在本轮结束执行纯文档校验。

相邻风险回扫新增三项保护：namespace 关闭 FD 仅 close 本 worker 副本、不调用 unlock 影响宿主；candidate validator 的结束屏障只在有 eligible proof 时由 S 做，无提交不增加 writer；测试锁隔离探针不能自己获取真人生产锁，否则验证手段会重现其要避免的干扰。

当前仍为 planning。本节“修正”均指工件约定，不宣称 lock/frame/state writer/candidate barrier 已实现或通过运行验证。

### 自查十条与相邻边界

- 唯一产生与身份域：一个类scope正常cache pool；每调用results/fixture；每case state/HOME。正常缓存允许复用，但锁/FD/handoff不跨调用继承，proof不能跨case共享。原scope resolver只管已列接口，不能因suite调用普通open就宣称已经强制containment。
- 首次/命中/故障三态：dev首次一次双构建序列（两次builder.build）和一次template fixture/init；相同输入后续build=0；candidate只走候选准备/校验；故障专测另付private冷成本，不能污染正常池或被helper预热抹掉stale条件。
- 反向规则/作用域：plan-only零build只观察自己的调用窗口，不把类warmup当计划无副作用的证据；取消计时从目标阶段开始，但准备成本仍算同一case，不每个子调用重置900秒；不改既有full身份核验≤3s/10%任务目标。
- 读取与所有权：管理legacy fixture与任意scratch区别不能靠路径名字猜。cp4_a8.py:6、cp5_b12.py:5、r35_tests.py:5-7 已使用 WF_LEGACY_FIXTURE_ROOT，仍是runner可分配管理根；固定r*_results.json等不因此获得scope ownership。固定outside-target已存在时，不能删除真人目录或先清空x.md来让“没有输出”变绿。
- 相邻修正1：初始草案提出通用TMPDIR注入和scratch登记，进一步核验fixture_scope.py:26-32按tempfile.gettempdir判临时根，且字面量写不遵从TMPDIR，因此撤销这一额外改造，避免改变可用fixture根或引入批量套件治理。
- 相邻修正2：共享cache不等于共享proof；如果给dev red和candidate auto每个调用新state，会让同一测试的证明链断开。故同case共享state、多调用独立结果、case之间隔离并分别teardown。
- 相邻修正3：setUpClass不能急切build，否则plan-only用例也先支付构建且难验证其零副作用。cache按真实调用懒建；故障/缺失面不得被warmup自动修复，WF_NO_TEMPLATE仍必须真绕过已存在模板。
- 旧记录/数字：AC1-AC18 与 V1-V20 一一有验证归属，正常缓存池复用不替代旧meta/state迁移反例；先前三轮计数为当时记录，未宣称新实现已通过。

明确边界：宿主串行固定/tmp scratch仍可能残留、与非harness文件撞名；这是本任务未承诺解决的既有用例行为，不借scope文案掩盖。是否需要全量scratch迁移是独立工作，本轮不把它暗加进实现。真实隔离冷/暖耗时仍待批准实施后测量，当前没有把900秒余量或新增构建次数写成已实测事实。
