# 优化大众玩家游戏评论 Agent 元提示词

## Goal

在 `tmp/大众玩家游戏评论Agent.md` 的现有元提示词框架基础上，按用户的 4 条指令做定向优化，使生成的 Agent 提示词更贴近目标受众、更完整覆盖手机端场景、更具流失预警视角，并在信息不足时有清晰的最低门槛定义。

保持文档的元提示词结构不变（即：文档仍然是"让 LLM 生成 Agent 提示词的指令"）。

## Requirements

1. **玩家角色具体化**
   - 目标群体改为 15–40 岁爱玩手机游戏的大众玩家，代表普遍情况
   - 在"角色设定（System Prompt）"部分，增加对该年龄段的特征描述：
     - 15–22岁：学生群体，时间相对充裕，对付费敏感，喜欢社交和竞技
     - 23–35岁：职场人群，碎片化时间，注重效率和操作流畅度，付费意愿中等
     - 36–40岁：成熟用户，稳定收入，对内容深度和稳定性要求更高
   - Agent 生成时应综合覆盖这个范围，而不是单一固定人物

2. **补充手机端专属评估维度**
   在现有 10 个维度之后，补充手机端特有痛点（可作为第 11–14 维度或归入"技术表现"扩展）：
   - 耗电与发热（长局游戏、高帧率场景下的发热程度、耗电速度）
   - 离线 / 弱网可玩性（是否必须联网、弱网下的体验降级幅度）
   - 推送通知与后台唤醒骚扰度
   - 单手操作与横竖屏适配

3. **优化建议生成规则中增加流失视角**
   在"优化建议生成规则"部分，要求 Agent 对每条建议补充：
   - 「如果不改，玩家大概率在哪个阶段（新手期/成长期/中后期）流失，原因是什么」
   - 「改后对留存率 / 付费率 / 口碑的预期影响（主观估计，加备注"玩家直觉"）」

4. **明确信息不足时的最低门槛**
   在"特别约束"部分，定义 Agent 开始评价前必须具备的最低信息：
   - 必需：游戏名称、类型（RPG/策略/消除等）、已玩时长（建议 ≥ 1 小时）、平台（iOS/Android）
   - 强烈建议：当前版本号、是否付费（免费 / 买断 / 内购）
   - 如必需项缺失，Agent 应明确列出缺失项并暂停输出正式评价，改为输出"初步印象"

## Acceptance Criteria

- [ ] 元提示词结构（5 个部分 + 任务交付物框架）保持不变
- [ ] 第 1 部分"角色设定"中包含 15–40 岁三段式人群描述
- [ ] 第 2 部分"评价框架与维度"新增至少 4 个手机端专属维度
- [ ] 第 3 部分"优化建议生成规则"包含流失阶段和预期影响两个新子要求
- [ ] 第 5 部分"特别约束"包含必需项 / 强烈建议项的分级列表，以及缺失时的降级输出说明

## Definition of Done

- 文件可直接复制贴入 LLM，生成完整 Agent 提示词
- 修改不引入逻辑冲突或重复内容

## Decision (ADR-lite)

**Context**: 15–40 岁跨度大，年龄特征差异明显，需决定角色如何呈现。
**Decision**: 选项 A——角色设定描述三段年龄特征，但 Agent 以综合大众视角输出评价，不拆分。
**Consequences**: 输出简洁、聚焦主流感受；代价是无法体现不同年龄段的差异化意见。

## Out of Scope

- 不改变文档为"元提示词生成指令"的定位
- 不拆分为多个文件
- 不添加与手机游戏无关的评估维度（如主机端、PC端专属）
