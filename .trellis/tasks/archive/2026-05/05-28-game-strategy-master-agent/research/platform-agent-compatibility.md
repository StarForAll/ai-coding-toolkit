# Platform Agent Compatibility Research

## Topic

How to express a source-level `game-strategy-master` agent so it can be adapted
to Claude Code, OpenCode, and Codex without mixing platform-specific wrapper
syntax into the shared system prompt.

## Sources Checked

- Claude Code sub-agents documentation, fetched 2026-05-28:
  `https://code.claude.com/docs/en/sub-agents.md`
- OpenCode agents documentation, fetched 2026-05-28:
  `https://dev.opencode.ai/docs/agents/`
- OpenCode permissions documentation, fetched 2026-05-28:
  `https://dev.opencode.ai/docs/permissions/`
- Codex subagents / custom agents documentation, fetched 2026-05-28:
  `https://developers.openai.com/codex/multi-agent/`

## Findings

Claude Code project subagents are Markdown files under `.claude/agents/` with
YAML frontmatter. The current docs identify `name` and `description` as required
fields and support optional controls such as `tools`, `model`,
`permissionMode`, `mcpServers`, `skills`, `effort`, `background`, `isolation`,
and `color`.

OpenCode supports both JSON config and Markdown agent files. Markdown agent
files can live under `.opencode/agents/`. The file name becomes the agent name.
The current docs describe `description` as required and use `mode: subagent` for
subagent behavior. OpenCode's current permission model uses `permission`, and
the legacy `tools` boolean config is deprecated. `permission.edit` covers write,
edit, and patch-style file changes.

Codex custom agents are standalone TOML files under `.codex/agents/` or
`~/.codex/agents/`. The current docs require `name`, `description`, and
`developer_instructions`. Optional fields include `nickname_candidates`, `model`,
`model_reasoning_effort`, `sandbox_mode`, `mcp_servers`, and `skills.config`.
Codex custom agents inherit omitted settings from the parent session.

## Repository Mapping

This repository's `agents/` directory is the source asset layer. For this task,
the correct implementation is:

- create `agents/game-strategy-master/`
- keep the shared role prompt in `SYSTEM.md`
- put abstract capability needs in `TOOLS.md`
- put platform wrapper templates and verification notes in `DEPLOYMENT.md`
- avoid writing live platform copies unless the task explicitly asks for
  deployment files

## Prompt Assessment

The source prompt in `tmp/游戏策略大师Agent-System-Prompt.md` is suitable as a
domain foundation because it already contains category-specific weights, scoring
anchors, synthesis matrices, leverage-point analysis, and roadmap output.

It should be optimized before becoming a reusable cross-CLI agent:

- remove meta-prompt language such as "generated by a meta prompt"
- make the shared system prompt tool-agnostic and platform-neutral
- add explicit evidence-status labels
- distinguish user-provided game facts, first-hand play notes, current public
  sources, stable design theory, assumptions, and evidence gaps
- require live verification before using current store scores, public reviews,
  competitor behavior, probability disclosures, policy claims, revenue data, or
  live-ops facts
- downgrade thin inputs to a first-pass strategy hypothesis instead of forcing a
  full deep report
- avoid revealing private chain-of-thought while preserving structured analysis
  steps as an output workflow
- keep legal, compliance, publishing, and revenue predictions bounded
- make every recommendation answer what to change, how to change it, expected
  impact, cost, risk, priority, and evidence basis
