## 判定口径

每条反噬给三值之一：

- **安全**：改动后不产生新的冲突、无出口或违反不变量；或产生的影响已有既有条款覆盖。
- **需附加条件**：方向正确，但落地时必须同版补一句 / 补一行，否则留下新缺口。

## 1. R1 反噬（六问）

R1 = §4.4 `:308` 定为唯一源，成员集按**产生规则**三分：继承类 / 活动期建边后随前置归档 / **任务定义类（新增）**；§7.5 `:602`、§0 `:45`、配套 `:28`/`:216` 降为引用；§6.7 `:533` 补来源指向；A1/B9/§10 补验收位。

### 1.1 与表 4-2（`:292`–`:302`）是否冲突 → **安全**

- 表 4-2 是**账本状态转移**的唯一合法集（`:304`），其行不涉及「前置集合从哪来」。
- R1 改的是前置集合的**产生合法性**，不是账本转移。两条规则的对象不同轴，不交叠。
- 表 4-2 行 5「确认『正常』时该任务的前置集合必须全部为『正常』」（`:300`）与 §4.3 满足判定（`:267`）同口径：任务定义类允许写入已归档前置，但**该前置仍须账本『正常』才算满足**。R1 不触碰满足判定，故无冲突。

**依据**：`docs/workflows/workflow-design.md:267`、`:300`、`:304`、`:308`。

### 1.2 与 §4.3 满足判定（`:262`–`:278`）是否冲突 → **安全（但须显式写一句）**

- §4.3 `:267`「依赖满足 = 前置任务已归档且在账本中的状态为『正常』」——只看状态，不看来源。R1 只加来源族，不改满足谓词。
- §4.3 `:278`「『前置为正常』不含『正常但未归档』，视为未满足，先按类型 3」——同样与来源无关。
- **须补一句的理由**：R1 的新成员容易被读成「任务定义类写入的前置直接算满足」。应在 §4.4 源处写「来源合法不等于满足；满足判定按 §4.3」，防止读者把 R1 当成满足判定的例外通道（§0 `:37`「例外只能按状态登记」）。

**判定**：安全 + 需附加条件（一句引用句）。

### 1.3 与 §7.4 异常下游处分（`:581`–`:591`）是否冲突 → **安全**

- §7.4 处分谓词**按字段判、不按来源枚举**（`:590`），终态 / 未完成的谓词以 §7.4 表行 `:586` 为唯一源。
- R1 增加的是「已归档任务作为前置」的来源族，不改变任何任务的账本状态，也不改变「未归档下游」的范围（`:586`）。
- §7.4 的「已归档任务不可再发起替换 / 放弃」（`:590`）与 R1 无关：R1 只谈前置集合的写入来源，不授予对已归档任务的业务处分权。
- **注意**：§7.4 `:586` 末句「已归档正常下游含异常前置仍是类型 4，不因本行忽略归档历史边而放行」——这条正是「已归档 + 正常 + 前置含非正常」的既有出口，见 1.5。

**判定**：安全。

### 1.4 与 §7.7 组合表各行（`:637`–`:650`）是否冲突 → **安全**

逐行核：

| 组合表行 | 位置 | R1 后是否受影响 |
|---|---|---|
| 已归档 + 正常 + 前置全正常 | `:639` | 不受影响（合法） |
| 已归档 + 正常 + 前置含非正常 | `:640` | **见 1.5**，出口类型 4 已存在 |
| 已归档 + 挂起 / 无记录 | `:641`–`:642` | 不受影响（类型 1） |
| 已归档 + 异常 | `:643` | 不受影响（合法） |
| 未归档 + 正常 | `:644` | 不受影响（类型 3） |
| 未归档 + 挂起 | `:645` | 不受影响 |
| 未归档 + 异常 | `:646` | 不受影响（类型 5） |
| 未归档 + 无记录 + 前置全正常 | `:647` | 不受影响（就绪） |
| 未归档 + 无记录 + 前置含非正常 | `:648` | **R1 会扩大本行的可达面**：任务定义类写入已归档前置后，新任务在开工前即处于「前置含非正常」→ 命中本行「等待」。出口已存在（等前置 / 前置异常按 §7.4 / 仍无出口按类型 4）。组合表判其为**等待、不修复**，与 R1 目标一致 |

**判定**：安全。组合表承载的是合法性判定，不承载来源判定；R1 只扩大可达面，不新增组合行。

### 1.5 「已归档 + 正常 + 前置含非正常」会否从防御态变可达？出口是什么？ → **需附加条件**

推演（关键，逐条给）：

1. 该组合的**既有产生路径**已经存在：活动期建边（两端活动区）→ 后置该前置被替换 / 放弃 → 前置账本「异常」并异常归档 → 本任务已归档且账本「正常」→ 命中 `:640`。**所以它不是防御态，是已可达态**，出口 = 类型 4（`:640`「非法 → 类型 4」），修复动作按 §7.5 删边（删边不受活动区限制、可对归档目标，`:602`、`:835`）。
2. R1 新增的任务定义类**本身不会**直接产出该组合：任务定义类写入的前置若为「异常」，则该任务的前置永不全正常 → 无法走 §6.3 收尾（收尾要求前置全正常）→ 无法进入「已归档 + 正常」→ **不命中 `:640`**。真正命中仍只可能是「先合法、后降级」这一条既有路径。
3. 但 R1 确实新增了一条**间接可达面**：任务定义类写入已归档**正常**前置 → 之后该前置若被判异常（类型 1 确认异常、或 §5.5 不再成立走替换 / 放弃）——注意已归档任务不可替换 / 放弃（`:46`），所以只有**对账修复类型 1 确认「异常」**这一条能把已归档正常前置改成异常。这条路经 §7.7 类型 1 的「一般任务」分支会**先动下游**（`:657`：按 §7.4 处置其未归档下游）；而本任务若**已归档**，它不在 §7.4 的「未归档下游」范围（`:586`）内 → **没有出口**。

**这就是 R1 的真实反噬点**：任务定义类让「已归档任务持有已归档前置」成为常见形态；一旦那个前置经类型 1 被确认「异常」，被指向的已归档任务落入 `:640`，而 §7.4 的下游处分范围只覆盖「未归档下游」，类型 4 的删边又只能删**未归档侧**的边——对两个都已归档的组合，删边是否可执行？

- §7.5 `:602` 明写「删边不受此限，可对归档目标执行（类型 4 修复要用）」，`:835` 同口径。**所以出口存在**：类型 4 按 §7.5 对归档目标删边。
- 但 §7.7 类型 4（`:662`）的措辞是「修复字段，或按 §7.5 删**非法边**」，没写「可对两端均归档的边执行」。§7.5 写了、§7.7 没写 → 引用回放（口径 12）时实现者按 §7.7 会停在「无法恢复」。

**判定**：**需附加条件**。R1 落地必须同版在类型 4（`:662`）补一句「非法边删边按 §7.5，可对归档目标执行」，或在 §7.4 `:586` 补「已归档下游的非法历史边按 §7.5 删边、按类型 4 承载」。不补则 R1 把 `:640` 从「既有可达 + 既有出口」变成「可达面扩大 + 出口只在 §7.5 一句、§7.7 侧不可回放」。

### 1.6 收尾重定义后，项目完成判定是否仍有唯一出口？ → **需附加条件**

- §4.3 `:266`「项目完成 = 收尾任务完成」；§6.7 `:531`「收尾任务完成 = 项目完成」；`:533`「收尾任务自身被替换或放弃时，由人重新定义收尾任务；项目完成判定以新的收尾任务为准」。
- **替换路径已有唯一出口**：替换实施第 3 步把未归档下游重连到替换任务（`:471`）；收尾在链尾、无下游，替换任务继承旧收尾的前置集合（`:470`）→ 继任者即新收尾，身份由替换指向解析（`:683`、§6.5 P 角色解析同款机制可复用）。唯一。
- **放弃路径是缺口**：
  - 放弃-删边变体把替换指向**写为空**（矩阵 `:690`），旧收尾异常归档 → **没有任何持久标识指向新收尾**。
  - 于是图中可能并存两个收尾对象：旧（已归档 + 异常）与新（重定义，未归档）。
  - `:533` 说「以新的收尾任务为准」，但机制**没有可解析的「新的」标识**（无替换指向、无角色解析链，`§6.5 :487` 的 P 角色解析只定义 P，不定义收尾）。
- **按状态仍唯一**：旧收尾账本「异常」，按 §4.3 `:276`「替换/放弃的异常归档不产生『正常』，也不构成完成」→ 旧收尾永远不可能是「完成」→ 项目完成判定在**状态层面**唯一（只有能走到「正常」的那个收尾算数）。
- 但 §9.1 已收尾表 `:808`「无当前任务、无就绪图内任务，且收尾未完成 → 按 §7.7 完整性自检 / 对账」——「收尾未完成」这个判据在**两个收尾并存**时无解析规则。

**判定**：**需附加条件**。`:533` 补来源指向（R1.4 已列）之外，还须补一句**判定口径**：「项目完成判定按**可达『正常』完成的收尾任务**（按 §4.3），不按定义先后；异常归档的旧收尾不构成完成（§4.3 `:276`）」。否则「以新的为准」依赖一个不存在的持久标识，正是 §6.5 `:500`「角色完整性守卫」为 P 堵住的那类洞，在收尾侧仍然敞开。

**附带发现**：§9.1 已收尾表 `:808` 的「收尾未完成」判据在旧收尾异常归档 + 新收尾未建的**窗口期**（放弃实施后到人重定义之前）无定义 → 该窗口会落到 `:808`「仍无出口则报告阻塞」。这是**可达窗口且只在报告层**，按 §0.1 口径 14（`:70`）「只靠『报告阻塞』不算命中」。R1.5 补 §10 自检时应覆盖该窗口。**判定**：需附加条件。

### 1.7 §7.5 `:602` 降为引用后，`:609` 边校验是否仍完整？ → **需附加条件**

- `:609` 边变更统一校验的**前置校验清单本身是自足的**：「（两端存在；目标不是异常；**建边另要求两端在活动区、前置未完工（含『正常但未归档』）**；无自环 / 成环）」——「两端在活动区」与「前置未完工」在 `:609` 内部就写了一次。
- 所以**删掉 `:602` 的来源枚举不会让 `:609` 失去判据**。
- **但风险在另一侧**：R1.2 要求「删除 `:602` 自带的 3 成员枚举」改写为「合法来源按 §4.4 判定；本节只约束建边与重连」。若改写时把 `:602` 的**「两端都必须在活动区」与 `:603`「前置必须尚未完工」一起当作『来源句』删掉或弱化**，则这两个建边边界的**唯一定义位**会落到 `:609`（校验式列举）与 `:835`（表内判据要点）上：
  - §0 `:37`「同一判定只在一处定义，其余位置只许引用」——`:609` 是**校验入口**，不是定义位；让它成为唯一表述违反该约定。
  - `:835` 是表内判据要点，按 §0 `:37` 的例外可以复述，但它只是摘要。
  - 配套 `:216` 是镜像，不是源。

**判定**：**需附加条件**。`:602` 降为引用时**只迁走来源枚举**，「两端都必须在活动区」必须原地保留并加限定「该限制只约束建边与重连，不约束任务定义（按 §4.4）」；`:603` 同理不动。这样：建边边界源仍在 §7.5、来源判定源在 §4.4、`:609` 保持校验引用式——三处各一职，不产生第二定义位。

## 2. R2 反噬（三问）

R2 = §9.1 两表当前任务行（`:792`、`:804`）补一格「当前任务进行中、收尾被后置前置挡住 → 先按 §7.6 取该前置图内任务开工，完成后回本任务」；该格是引用 §7.6，不新建选择规则。

### 2.1 遮蔽顺序：新格与「继续当前任务」行在「命中即停止」下的关系 → **会引入新问题（若只补不排序）**

**事实**：

- §9.1 `:768`「入口分三段，**逐段判定，命中即停止**」；`:812`「三段互斥，命中即停止；同一情况只在其中一段出现」。
- 未收尾表行 1（`:792`）与已收尾表行 1（`:804`）都是**命令式无条件句**：「有当前任务、按 §3 有效且非挂起 → 继续当前任务」。
- 该行的行内子句「进行中且前置不全正常时工作不停、收尾等前置」**已经覆盖了新格要处理的那个情形**（进行中 + 前置不全正常）。

**推演**：若新格作为**另一行**追加在现有行之后，按「命中即停止」，进行中被挡的情形必然先命中现有行并停止 → 新格**永远不执行**，等于没补（这正是 fix-sync-inventory §3.2 已标记的遮蔽风险点，此处确认成立）。若把新格**排在现有行之前**，则所有「进行中 + 前置不全正常」都会被新格抢走，现有行只剩「进行中 + 前置全正常」，原行语义被改变。

二者都不是「条件互斥」——按 design-review-thinking-guide `:159`–`:162` 的明确要求：「Prefer making the two overlapping rules **mutually exclusive by condition** … over declaring 'rows are matched top-down'. Row order is a cover; the overlap stays underneath it.」**排序是掩盖，条件切分才是消解。**

**消解写法（三选一，按 §0 `:37`「同一判定只在一处定义」排序推荐 A）**：

- **A（推荐）· 行内子句消解，不新增行**：把现有两行的行内子句改写成条件二分——
  「有当前任务、按 §3 有效且非挂起 → 继续当前任务（含 P 自身、P 的返工任务、其他图内任务与图外任务）；**进行中且前置不全正常时工作不停**：**若该前置是图内且已就绪（可按 §7.6 取最早的一个），先开工该前置、完成后回本任务**；否则收尾等前置。」
  - 优点：不新增行 → 不存在遮蔽（同一行内二分天然互斥）；不触发 `id_scheme` `:10`「路由表删行后行号顺移」的风险；§8.4 `:758` 与配套 `:270` 只需同步同一句。
  - 缺点：行内变长，但两表行 1 本来就带长子句，风格一致。
- **B · 新增行但条件互斥（把现有行收窄）**：现有两行改为「有当前任务、按 §3 有效且非挂起，**且收尾未被前置挡住**（前置全正常，或该前置非图内 / 未就绪）→ 继续当前任务」；新行写「有当前任务、按 §3 有效且非挂起，进行中且收尾被某图内就绪前置挡住 → 先按 §7.6 开工该前置，完成后回本任务」。
  - 优点：两行条件显式互斥，符合 guide 的偏好。
  - 缺点：改动现有行的条件（不是只加），且**「该前置非图内 / 未就绪」是新造谓词**，须在 §3 或 §7.6 定源，否则又是一处未源化判定。
- **C（不推荐）· 只排序 + 说明区登记顺序**：违反 guide `:159`–`:162`，且 `id_scheme` `:10` 已明写「路由表删行后行号顺移，说明与引用以条件名指称」——说明区记顺序会与行号顺移叠加成双重漂移面。

**推荐 A**，并要求：两表（`:792`/`:804`）**同格同句**，§8.4 `:758` 与配套 `:270` 同步（v39 曾因漏 §8.4 留过一次缺陷，见 `:974`）。

**判定**：**会引入新问题**（按 R2.1 字面「补一格」= 新增行 + 不切条件）；采用 A 后为**安全**。**必须由人工在 A / B 间拍板**（见第 6 节决策点 D1）。

### 2.2 引用前提冲突：§7.6 `:617`「选择只在没有当前任务时」 vs 新格「引用 §7.6」 → **会引入新问题（不处理则口径 12 回放走不通）**

**事实**：

- §7.6 `:617`「选择规则用于**没有当前任务**时；有当前任务时先继续当前任务（§9.1）」——这是**适用前提的写死声明**。
- 配套 §7 `:230` 同款：「选择规则用于**没有当前任务**时；有当前任务时先继续当前任务（主设计 §9.1）」。
- 新格要引用 §7.6，但新格的调用上下文是「**有**当前任务」。沿引用回放（口径 12，`:68`「走不通就与本条同版补豁免或补细则」）→ 第一条前提就不成立。

**消解写法（按「不新建选择规则」的 R2.2 约束排序）**：

- **A（推荐）· 改 §7.6 的限定，使其成为可被两处引用的规则源**：
  `:617` 改写为「选择规则用于**没有当前任务**时；有当前任务时先继续当前任务（§9.1）。**例外（§9.1 当前任务行引用本节的定向开工）**：当前任务进行中且收尾被某个图内就绪前置挡住时，按本节排序规则取该前置中最早就绪者开工，完成后回原任务；本例外只在 §9.1 该行内被调用，不是独立入口。」
  - 符合 §0 `:37`「**例外只能按状态登记**，不得按来源、路径或角色逐格追加」：这里的例外是按**状态**（当前任务进行中 + 收尾被挡 + 该前置图内就绪）登记的，不是按角色。
  - 符合 §0 `:37`「去重 / 收口时存活的那份必须显式登记全部例外」：§7.6 是存活源，例外写在源处。
- **B · 行内子句自带、不引 §7.6**：新格写「先开工该前置（同为图内任务时按创建时间取最早）」——**会引入新问题**：这就是在 §9.1 内**第二次定义排序规则**（§7.6 `:616`「按任务创建时间排序，取最早」），违反「同一判定只在一处定义」，且 spec 注册表 `:298`「Selection when no current task / Banned: Restating the branch conditions outside §9.1」的对称面（在 §9.1 内复述排序规则）也会被踩到。
- **C · 只改 §9.1 不动 §7.6**：引用回放不通，违反口径 12。**不可选**。

**判定**：**会引入新问题**（现状）；采用 A 后为**安全**。选 A 时**必须同版改配套 §7 `:230`**（配套是同款写死前提，不动则配套侧回放仍不通，且构成跨文档副本漂移，违反口径 11）。

### 2.4 递归情形：该前置又依赖其他未跑任务 → **需附加条件（无终止条件与出口）**

**推演**（R2 唯一未被 R2.1–2.3 覆盖的结构性风险）：

- 新格说「先按 §7.6 取**最早就绪的该前置图内任务**开工」——限定为「**就绪**」，所以第一层是终止的（就绪 = 前置全正常 + 未归档 + 账本无记录，§3 `:197`）。
- **但递归不在第一层，在「回本任务」之后**：假设 T 被 U 挡住（U 已归档/异常，不是 U 未跑）。注意——若 U 就绪，直接开工 U 即可，无递归。真正的递归形态是：**U 本身不就绪**（U 的前置 V 未完成）→ 新格里的「取最早就绪的**该前置**图内任务」指的是「挡住 T 的那个前置集合里最早就绪的成员」；如果挡住 T 的是 U，而 U 未就绪，则 U **不在**「就绪」集合里 → **新格不命中** → 退回原行「收尾等前置」→ **F2 的洞没有补上**。

**这才是 R2 的真实边界**：R2.1 的措辞「取最早就绪的该前置图内任务」只覆盖「挡路者自己已就绪」这一种形态；现场形态（T 等 U，U 从未执行、U 自己也可能有未完成前置）**不命中**。

**终止条件与出口的两条可选消解**：

- **A（推荐）· 递归下沉 + 深度终止**：新格改为「沿未完成前置链下行，取链上**最早就绪的图内任务**开工（按 §7.6 排序）；链上无就绪任务时，按 §7.7 等待行的处置（前置为异常按 §7.4；『正常但未归档』按类型 3）；仍无出口则报告阻塞」。
  - 终止条件：**图是 DAG**（不变量 4，`:162`，且 §7.5 `:605` 建边禁环、`:609` 后置再检环）→ 前置链有限、无环 → 下行必然终止。这是**已有的**终止保证，不需要新增机制，但**必须在新格里显式写出**（否则实现者会写成无限循环）。
  - 出口：就绪者开工 → 完成后按 §6.3 收尾 → 触发 §6.4 第 5 步评估点与视图重建 → 回链上层；链上无就绪者 → §7.7 组合表「等待」行 `:648` / 类型 3 `:649` / 类型 4（仍无出口）。
- **B · 只补一层 + 显式登记不递归**：新格只处理「挡路者已就绪」；挡路者未就绪时按 §7.7 等待行。较保守，但**现场形态仍无出口**（退回 F2 原状）。
- **不处理**：**会引入新问题**——新格覆盖不到 F2 的实际触发形态，修了等于没修，且新增一句反而让「已修」更难被发现（正是 §3.3「把『能跑通的路径』当成『规则成立』」的复发形态）。

**判定**：**需附加条件**，且这是 R2 的**关键前置决策点**（见第 6 节 D2）。采用 A 时须同版在 §9.1 说明区登记「下沉终止于 DAG 无环（不变量 4）」。

## 3. R3 反噬（三问）

R3 = §7.8 `:680` 写入前校验枚举补「返工登记准备（R 预生成依赖标识）」；矩阵给依赖标识一个受控重生成许可；类型 4 恢复边界 `:704` 补依赖标识受控重生成；配套 §6.4 `:163`、§6.5 `:193` 同步占用校验。

### 3.1 与 §6.4 `:424`「位置占用 → 停止、不另生成 ID」如何区分？会否绕过？ → **需附加条件（但不绕过）**

**两条规则的逐字对照**：

| | §6.4 `:424`（既有） | R3 新增（建议） |
|---|---|---|
| 校验对象 | **稳定基底定位**（目录 / 位置） | **依赖标识**（雪花 ID） |
| 冲突时动作 | 「位置占用、创建结果不明或无法唯一核对时**停止**，按类型 4 恢复已知信息，**不另生成 ID**、不盲目重复建任务」 | 预生成标识被占用 → **重新生成后重校验**（与 §6.5 `:461` / §6.6 `:508` 同款） |
| 语义 | 位置是**基底事实**，冲突意味着「可能已有一个 R」，不能再造一个 | 标识是**机制事实**（§3 `:184` 雪花 ID），冲突意味着「这个 ID 已被别的身份用了」，换个 ID 不改变任何基底事实 |

**区分是否成立**：**成立**。位置占用关乎「任务实体是否唯一」（再造一个是**重复建任务**，会破坏基底事实）；标识占用关乎「编号是否唯一」（换一个号不新增任务实体）。§6.4 `:424` 的「不另生成 ID」在原文语境里是「**不另生成一个 R**」（读全句：「不另生成 ID、**不盲目重复建任务**」），不是「不重新生成依赖标识」。

**但会绕过吗**：**不会绕过 `:424` 的防护意图，但会造成措辞级冲突**——R3 写「重新生成后重校验」，`:424` 写「不另生成 ID」，两句在同一节（§6.4）相邻两行（`:423` 预生成、`:424` 创建或找回），照字面读就是自相矛盾，命中 §0.1 口径 2 的「内部矛盾」来源。

**消解写法（须同版）**：`:424` 的「不另生成 ID」改为「**不另生成标识来新建第二个 R**」（限定为不重复建任务），并在 `:423` 或 `:424` 补「依赖标识的占用校验与受控重生成按 §7.8 标识占用校验（时点 1），与本步的稳定定位占用分域：位置占用停止，标识占用重生成后重校验」。

**判定**：**需附加条件**。不改 `:424` 措辞 = 引入新的内部矛盾（`:424` vs `:680`）。

### 3.2 返工 R 已创建后发现撞号，是否有出口？ → **需附加条件（当前无出口）**

**推演**（三种撞号时机，逐个给出路）：

| 时机 | 状态 | 当前出口 | 判定 |
|---|---|---|---|
| a. 准备阶段、R 未创建 | 标记已含 R 的依赖标识 + 稳定定位，尚未提交 / 已提交但 R 未建 | 若 `:680` 补了「返工登记准备」→ 时点 1 拦住，重新生成后重校验。**R3.1 补完即有出口** | 安全（R3 覆盖） |
| b. R **已创建但未发布** | 标记已提交（含稳定定位 + 依赖标识）；R 的基底任务已建；机制来源 / 边未提交 | §6.4 `:424`「创建调用中断 / 已建未发布 → 读回同一位置，找到即复用；**不明则类型 4 阻断**」——但「读回同一位置」用的是**稳定定位**，与**依赖标识**无关。若撞号发生在标识层（R 的记录里写了一个已被别人占用的标识），读回位置**找不到冲突** → 冲突继续潜伏到发布 | **需附加条件** |
| c. R **已创建且已发布**（标识已落盘进任务记录） | 重号已进已提交记录 | §7.8 `:681` 时点 2 只谈**替换指向**落盘后被占用 → 类型 4 阻断。**依赖标识落盘后被占用没有对应句** | **需附加条件**（无出口） |

**对 c 的两个候选出口，逐个判**：

- **类型 4 能否改标识？** §7.8 `:704` 类型 4 恢复边界（唯一源）的现行许可只覆盖：替换指向（可恢复到存在任务 / 未建的预写标识 / 合法空值；**例外**：原预写标识被他身份占用时可改指本次重新生成且经占用校验的标识）、返工来源（可恢复原挂载点，**不能移除 / 改变返工身份或凭空新增身份**）、说明（须保留仍必需的异常原因与未完成登记意图）。**没有依赖标识这一项**。
  - **关键约束**：`:704` 明写「**不得借修复新建任务 / 关系**」（`:662` 同款）。改一个**已发布 R 的依赖标识**是否算「新建关系」？——按 `:704` 的既有例外形态（原预写标识被占用 → 改指本次新生成标识，**作为原关系的载体更正**），同款处理是**可对齐的**：依赖标识只是载体，改它不改 R 与 T 的挂载关系（挂载关系由「返工来源」表达，§3 `:200`、矩阵 `:697`）。
  - 所以**可以改**，但**必须在 `:704` 显式补一行**（R3.3 已列），否则类型 4 的许可集里没有它，按「唯一源 + 其他位置只许引用」的字面，改它就是矩阵外写入 → 违反矩阵后的禁止式约束（`:702`「未在矩阵登记的业务写入 / 清空不允许」）。
- **§6.6 放弃 R 能否作为出口？** §6.4 `:429`「**R 已创建时先完成登记，再按 §6.6 放弃 R**；不删掉任务冒充取消」。所以「放弃 R」是**合法出口**，但它**不解决撞号**——放弃后若人又要返工，会走一次新的登记准备，届时 `:680`（已补）会拦住重号。所以放弃 R 是「止损路径」而非「修复路径」。
  - **额外约束**：按 §0.1 B9 与 §6.6，放弃只适用于**未归档任务**（`:506`）；已发布的 R 通常未归档，故适用。若 R 已归档（撞号在归档后才发现），放弃不可用 → **只剩类型 4 一条**。这进一步说明 `:704` 必须补。

**判定**：**需附加条件**。R3.3（`:704` 补依赖标识受控重生成）**不是可选项而是唯一出口**；且须写明「只改标识载体、不改挂载关系（返工来源不变），仍须人确认、不得借修复新建关系」，与 `:704` 既有例外句同款。

### 3.3 与矩阵 13 行及 P 继任守卫是否冲突？ → **安全（补行方式）+ 需附加条件（口径同步）**

**（a）与矩阵 13 行（`:688`–`:700`）**：

- 三种补法的影响：
  - **补行**（新增「依赖标识占用与受控重生成」行）：13 → 14 行。连带 spec `:346` 探针期望值「exactly one full main matrix (13 rows)」须同版改（fix-sync-inventory #68 已列）。**安全**。
  - **补列**（新增「依赖标识」列）：行数不变，但 `:683`、`:696` 的「指向终值」「说明 / 原因终值」提法与 spec `:293` 注册表行须逐处核对。**安全但连带面不同**。
  - **不补、只在 `:680` 加枚举**：**会引入新问题**——§10 `:880` 类迁移义务要求「识别条件依赖的每个字段都须在 §7.8 有行」；只在 `:680` 加枚举而不进矩阵，等于把 §10 自己的义务违反一次（正是 §3.5「类迁移义务只在被点到的那一格执行」的复发）。
- **推荐补行**（与既有第 11 行「返工登记准备」`:698` 相邻，语义最近；且比补列改动面小）。

**（b）与 P 继任守卫（`:500`、矩阵 `:696`「已确立的 P 继任关系不得置空」）**：

- 依赖标识**不是** P 继任关系的载体（载体是**替换指向**，`:683`）。改依赖标识不触碰替换指向 → **不冲突**。
- 但 `:704` 的 P 守卫是**按关系**写的（「禁止形成继任环、清空已确立的 P 继任关系，项目层已收尾也不豁免」）。若新增的「依赖标识受控重生成」被误用到** P 的依赖标识**上（P 换过 ID，§6.5 `:485`），会与「P 的指向不得被改」的语义相邻 → **须在新增句里限定**：「本项只适用于**任务自身的依赖标识**；P 的继任关系仍按替换指向解析，继任者的身份变更不属本项」。
- **判定**：**需附加条件**（一句限定），不加则与 P 守卫的边界模糊，构成 spec `:301` 注册表「Identity occupancy …」行的 Banned 面（「using type 4 to invent an unrelated existing relationship」）的相邻风险。

**（c）与 §10 `:880` / 口径 10⑥ `:66`「三字段」枚举** —— 见第 4 节 4.2（同类载体扫描），此处只记结论：**必须同版扩枚举**，否则 R3 自己制造新的枚举漂移。

### 9.2 新增反噬问：R1 任务定义类的措辞会连带豁免 `:603` 的「异常前置不得建边」

前文 1.5 走的是「先合法、后经类型 1 降级」的间接路径。这里补**直接路径**（review-report-v2.md `:149` 的字面措辞：「**不受『两端活动区 / 前置未完工』限制**」）：
