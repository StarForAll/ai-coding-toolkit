### 1.4 配套 §13 已确定实现口径（`依赖机制设计说明.md:318-340`）

全部标注为「实现层选择，不影响上述规则」，逐条列入不可重复提出：

1. 账本按需登记发生状态变化的图内任务；未登记按“无记录”；“正常”长期保留不清理；“异常/挂起/替换指向”长期保留（L322）
2. 对账修复是“正常”的第二合法写入者，只用于已归档且无记录/挂起；确认“正常”时前置须全正常；正常未归档保持“正常”或改回无记录；挂起清除、替换/放弃完成不写“正常”（L323）
3. 返工任务集合由扫描双区派生，不单独存储、不新增 ID 列表字段（L324）
4. 多组件共用一个 DAG 视图文件，按组件分区（L325）
5. 异常归档使用原生归档动作，状态只在账本表达；实施后不回退（L326）
6. 启动时对账；不保留操作日志；收尾失败按 §8 兜底恢复、不重放（L327）
7. 就绪选择按创建时间；不引入优先级字段（L328）
8. 解析器 = 任务元数据中的雪花 ID + 活动/归档双区扫描；账本路径仅作缓存（L329）
9. 派生件每次状态变化后重建；对账不通过禁止开工（L330）
10. 边变更统一走前置/后置校验；建边、返工加边、替换/放弃重连共用（L331）
11. 状态写入与边变更一样在机制入口统一校验；非法转移拒绝不写入（L332）
12. 返工挂载点为未归档任务；已归档不直接返工（L333）
13. 当前任务指针是提示；有效性按主设计 §3（L334）
14. 启动时完整性自检读账本与基底任务状态；非法组合按类型 1/4 标记、不自动修复（L335）
15. 返工登记标记/发布及旧口径移交按 §6.4；稳定基底定位由实现方案验证，不能假设创建与机制提交原子（L336）
16. 收尾、替换/放弃、返工不要求跨系统/跨任务原子（L337）
17. 边变更先暂存、后置校验通过后提交；失败回滚并报告（L338）
18. 机制写入范围与选择性提交统一按主设计 §3（L339）
19. 卸载脚本幂等，中断后重跑不产生副作用（L340）

## 2. 端到端场景模拟（正常诚实使用，走到出口）

约定：每条给出**入口 → 中间态 → 出口**，出口必须是文档明确允许的动作（完成/恢复/报告阻塞/卸载/人判）。未标「无出口」者即为有出口。

### S1 0→1 冷启动

- 起点：无项目层任务、无当前指针、无账本记录。
- §9.1 第一段（L770-775）：模块可用；无完整性/登记/移交项；无基线变更 → 不命中。
- §9.1 第二段（L777）：无当前任务、无挂起任务 → 不进入。
- §9.1 第三段未收尾表（L788-798）：「无当前任务（含视为无当前任务）、无项目层任务」→ **启动 P：立项 + 基线 + 任务图**（L794）。
- P 收尾：§5.3 序列（L358）人确认 → 校验源状态（无记录 + 前置全正常；P 初始无前置，§5.1 L335）→ 归档 → 账本正常 + 持久化 → 重建视图。P 已归档 + 正常 → 组合表行 1 合法（L639）。
- §6.5 P 角色解析表行 3（L493）：已归档 + 正常 + 前置满足 → 正常完成的 P 终点，项目层已收尾。
- 出口：项目层已收尾表（L800-808）→ 无当前任务 + 存在就绪图内任务 → 取最早就绪（L806）。实现任务 1 就绪（§5.3 L361「P 正常归档后，实现任务 1 就绪」）。
- **有出口**。

### S2 维护期选择（收尾完成，无就绪图内任务）

- §9.1 已收尾表 L807：无当前任务、无就绪图内任务、收尾完成 → **迭代期普通任务**。
- §9.1 说明 L815：「收尾完成」只在无当前任务、无就绪图内任务时命中。
- 迭代任务可选走原生流程（图外），或建边成图内（§7.5 建边，两端活动区）。
- **有出口**。

### S3 返工登记 → 发布 → 执行 → 清挂起（含逐窗口）

- 入口：T 未归档且账本无记录/挂起（§6.4 L419）。
- 步骤 1 准备（L423）：校验无未完成登记；预生成 R 标识 + 稳定基底定位；T 记挂起（表 4-2 行 2，L297）+ 按 §7.8 矩阵「返工登记准备」行（L698）写标记，同次提交。T 原已挂起只登记意图、不重复转移（L423）。
- 步骤 2 创建或找回（L424）：按标记中稳定定位建 R 或读回同一位置；位置占用/结果不明 → 停止，按类型 4 恢复已知信息。R 未发布前不得执行、不得当图外任务继续；§9.1 全局旁路先接管。
- 步骤 3 发布（L425）：按 §7.5 暂存 + 后置校验，把 R 标识、返工来源（矩阵「返工来源写入」行 L697）、继承前置、T 加 R 边、消费登记标记（矩阵「返工登记发布」行 L699）同次提交。
- 步骤 4 执行（L426）：R 按普通图内任务；完成按 §6.3。
- 步骤 5 挂起清除（L427）：T 未归档且挂起、无未完成登记、返工集合非空且无未归档成员、前置全正常 → 表 4-2 行 3 清挂起，T 回就绪。
- 出口：T 就绪后经 §9.1 第三段继续；或 §9.1 第二段「有未归档 R → 进入 R」（L781）/「满足清除条件 → 清除并继续 T」（L782）。
- 逐窗口（L435-444）九行，每行有残留识别项 + 恢复；见下 S7。
- **有出口**。

### S4 返工登记取消（R 未创建 / R 已创建）

- R 未创建：§6.4「登记恢复与取消」（L429）→ 人决定取消且已确认 R 尚未创建 → 按矩阵「返工登记取消」行（L700）消费标记 + 恢复 T 登记前状态，同次提交；登记前无记录走表 4-2 行 7（L302），登记前挂起则仍挂起（不清旧挂起）。
- R 已创建：先完成登记，再按 §6.6 放弃 R（L429）；不删任务冒充取消。
- 出口：取消提交后 T 回到登记前状态（无记录→就绪；挂起→仍挂起，经 §6.4 步骤 5 评估）。**有出口**。

### S5 返工完成（R 正常归档，T 清挂起）

- R 收尾（§6.3）→ 归档 → 账本正常 + 持久化；R 已归档 + 正常 → 组合表行 1 合法。
- 评估点含「R 收尾」（§6.4 步骤 5 L427）→ 满足条件则表 4-2 行 3 清挂起。
- §9.1 第二段 L782：「对应 T 满足 §6.4 第 5 步清除条件 → 清除挂起，继续 T」。
- 出口：T 继续 / 就绪后按第三段选。**有出口**。

### S6 重复返工（同一 T 再次返工）

- T 已挂起时仍按 §6.4 登记本次意图，不重复写「挂起」（§4.4 L306；§6.4 L423）。
- 矩阵「返工登记准备」行 L698：同一 T 不覆盖未完成登记。
- §6.4 L431：多个未完成登记按挂载 T 的创建时间逐项恢复；同一 T 的后续新增请求先完成当前登记，不覆盖它。
- §4.4 L306 明确：说明标记维护及状态值不变的其他字段维护不属状态转移。**不构成非法转移**。
- 场景：T 挂起 + R1 未完成 → 再次发起登记被拒（有未完成登记）→ 先完成/取消 R1 登记 → 再登记 R2（T 仍挂起，只写标记）。
- 出口：完成或取消后进入 R2 流程。**有出口**，且同对象重放可由标记区分（标记含 R 标识 + 定位 + T 登记前状态）。

### S7 重复替换（替换任务再被替换）

- 第一次替换 T→T'：§6.5 实施 6 步（L469-474），T 记异常 + 指向 T'（矩阵「替换实施」行 L688），T' 从无记录开始。
- 再次替换 T'→T''：T' 未归档、账本无记录 → 符合 §6.5 发起静态校验（L463）。实施第 1 步 T' 记异常 + 指向 T''。
- P 角色解析沿指向链逐任（§6.5 L485、v41 L955）：T/T'/T'' 若 P 链 → 沿指向解析到链尾。
- 出口：每次替换后按 §7.4 表行判处分终态；未完成时 §7.7 类型 5 向前完成。**有出口**。
- 交叉核对：§7.4 表行「处分已到终态」含「（无替换指向 或 继任者已建）」（L586）——T' 有指向 T'' 且 T'' 已建 → 终态。B 面已证明两分支形式互补，此处一致。

### S8 普通任务替换（未归档 T，无挂起）

- 发起静态校验（L460-463）：继承前置 = T 当前前置；预生成标识未被占用（§7.8 写入前校验 L680）；重连后不成环；目标状态合法（新任务不存在、T 未归档、T 账本无记录/挂起）。
- 实施（L469-474）：① T 记异常 + 说明/指向（矩阵行 L688）+ 持久化 + 清指针；② 建新任务继承前置，从无记录开始；③ 未归档下游重连 + 移除旧标识，边变更按 §7.5；④ 检环，失败则停止报告、T 保持异常、由 §7.7 完成入口向前处置；⑤ T 异常归档；⑥ 重建视图 + 持久化。
- 出口 4 的失败：§7.7 类型 5 向前完成（L663-668），窗口④「继任者已建、下游未重连完 → 补齐重连」。
- 出口：新任务就绪后按第三段选；T 已归档 + 异常 → 组合表行 5 合法（L643）。**有出口**。

### S9 挂起中的 T 被替换（R 是前置，不重连）

- §6.5 L481：R 是 T 的前置，不属于「未归档下游」，不重连；R 留图中按普通任务处置；新任务继承 T 当前前置集合（含 R），仍等待 R；不再需要 R 则按 §6.6 放弃 R。
- 出口：R 完成后新任务就绪；或放弃 R（§6.6，删边/新建替代）。§10 自检已列「替换挂起中的 P 后继续（新 P 继承 R 并进入 R）」（L891）。
- **有出口**。与 §9.1 第二段 L781「对应 T 有未归档返工任务 R → 进入 R」一致。

### S10 P 被替换（继任者承担项目层）

- §6.5 L485：P 的继任者即新的 P（替换任务）；旧 P 异常归档不再承担项目层；§5.6/§9.1 项目层判定与 §4.5 项目层关卡以继任者为对象（P 按角色解析，换 ID 不改判定）。基线产物由继任者续写。
- §6.5 P 角色解析表 L489-498：账本异常 + 指向合法继任者 + 处分已完成 → 沿指向继续解析。
- 出口：新 P 未归档 + 无记录 → §9.1 未收尾表 L796「只执行 P」；新 P 已归档 + 正常 → 已收尾表。**有出口**。§10 自检 L891 已列此场景。
- 注意 §9.1 未收尾表 L794「无当前任务、无项目层任务 → 启动 P」不会被误命中：P 角色解析到继任者即「P 存在」，不重新立项（v35 L1006 已修）。

### S11 P 被放弃（只允许新建替代变体）

- §6.6 L524：放弃 P 只允许新建替代变体——删边变体不留继任者，项目层判定失去对象。
- 实施（L512-518）：① 旧 P 记异常 + 指向 = 预生成替代标识（矩阵「放弃-新建替代」行 L689）+ 持久化 + 清指针；② 用第 1 步预写标识建替代任务 + 继承旧 P 当前前置（L515）+ 重连下游（§6.5 实施第 2–3 步）；③ 检环；④ 旧 P 异常归档；⑤ 重建视图 + 持久化。
- 出口：替代任务即新的 P（§6.5 L485），沿指向解析。**有出口**。§10 自检 L891 已列「放弃 P（新建替代）后跨 CLI 接手」。

### S12 放弃两变体（一般任务）

- 删边变体：矩阵「放弃-删边变体」行 L690 → 指向终值「空」，说明写放弃原因；实施第 2 步删除所有未归档下游前置中的旧任务标识（L514）；旧任务异常归档（L517）。§7.4 表行：无替换指向 → 属「无替换指向」枝；已归档 + 下游不指向 → 终态（L586）。
- 新建替代变体：矩阵行 L689 → 指向 = 预生成替代标识；实施第 2 步（L515）。§7.4 表行：有指向 + 继任者已建 → 终态。
- 出口：两者都归组合表行 5「已归档 + 异常」合法（L643）。**有出口**。

### S13 类型 1 恢复（已归档但账本无记录/挂起）

- 一般任务：§7.7 类型 1（L656-657）：人确认「正常/异常」。确认正常 → 前置须全正常，否则先类型 4 修边或改确认异常。确认异常 → 账本写异常 + 说明（矩阵「类型 1 一般任务」行 L692，无指向）→ 按 §7.4 处置未归档下游（无指向 → 类型 5「无替换指向」分支补删边与归档）。
- P 分支（L658）：同次写异常 + 说明 + 预生成新 P 标识作为指向（矩阵「类型 1 P 分支」行 L691）→ 用指向里的标识建新 P（不走 §6.5 发起/实施第 1 步，因旧 P 已归档）→ 继承旧 P 当前前置 → 重连未归档下游（校验存在性/非异常/不成环）。
- 逐窗口（L659）四窗口，残留一律按类型 5 向前完成。
- 出口：类型 1 补记后组合表行 1（正常）或行 5（异常）合法。**有出口**。

### S14 类型 2 恢复（返工登记未完成 / 挂起无返工）

- §7.7 类型 2（L660）：有合法登记标记 → 按 §6.4 原序列恢复/取消，不重跑已确认的人判；标记有损先类型 4。无标记且已完成旧口径移交 → 人确认补建（按 §6.4 新登记）或确无返工记录时按表 4-2 行 7 清挂起。旧口径无标记存量挂起先按 §6.4 移交条款确认。
- 出口：恢复登记 → S3；取消 → S4；清挂起 → 表 4-2 行 7。**有出口**。
- §9.1 第二段 L784「找不到返工任务记录 → 按 §7.7 类型 2 对账修复」同口径。

### S15 类型 3 恢复（正常但未归档）

- §7.7 类型 3（L661）：人确认重新归档（账本保持正常；前置须全正常，否则先类型 4 修边或改回无记录）或改回无记录。
- 入口侧：§3 就绪 L197「正常但未归档按 §7.7 类型 3 处理」；§9.1 未收尾表 L795「P 存在且未归档，账本为正常但未归档 → 按 §7.7 类型 3 修复后再继续」；§8.4 L758；组合表行 6（L644）。
- 出口：重新归档 → 组合表行 1；改回无记录 → 组合表行 9/10（未归档 + 无记录）。**有出口**。

### S16 类型 4 恢复（无法解析或非法记录/边）

- §7.7 类型 4（L662）：人发起，机制按 §7.8 矩阵「类型 4 记录修复」行（L696）及恢复边界（L704）修复字段，或按 §7.5 删非法边。恢复字段同次提交；提交前失败仍是原不一致，提交后重新分类。预写指向恢复后目标未建 → 转类型 5；登记标记恢复 → 转类型 2。
- 未归档任务确需放弃：先恢复到普通放弃守卫可接受的状态 + 先完成未完成登记，再按 §6.6 处分（L662）。
- 无法恢复 → 阻断（不静默放行）。§9.1 已收尾表 L808「仍无出口则报告阻塞」。
- 出口：修复后重新分类；不可恢复则阻断 + 报告。**有出口（含「阻断并报告」这一文档明确出口）**。

### S17 类型 5 恢复（替换/放弃未完成，向前完成）

- 唯一源 §7.7 类型 5（L663-668），顺序固定「先补建/重连、后归档」。
- 补建（L664）：用指向里的标识建新任务 + 继承前置 + 重连未归档下游；继任者已建只补重连；最后归档旧任务。不重跑实施前「旧任务账本为无记录/挂起」校验，但按 §7.8 校验目标标识、目标非异常、不成环。
- 改判放弃（L665）：只在继任者不存在时、由人决定。一般任务 → 指向置空 + 说明改写为放弃原因（矩阵「类型 5 改判放弃（一般任务）」行 L694）+ 删边 + 归档；P → 沿用预写指向建替代并重连（矩阵行 L695 不新增写入）+ 归档。
- 无替换指向（L666）：补下游删边 + 旧任务归档；指向与说明双缺失 → 先类型 4 补写说明再回本分支。
- 逐窗口（L667）五窗口：① 人确认后未写入 → 重走本项；② 指向置空/说明改写后未删边 → 走「无替换指向」；③ 删边后未归档 → 补归档；④ 继任者已建、下游未重连完 → 补重连；⑤ 按 §7.4 表行判终态 → 组合表行 5 合法，处分收敛。
- 出口：⑤ 收敛。**有出口**。

### S18 跨 CLI 接手（指针为空/残留）

- §8.4（L748-758）：① §7.7 完整性分类 → 读 DAG 视图；指针只作提示，有效/无效按 §3，指针为空或残留一律以 DAG 视图与账本为准；② 读账本；③ 读任务记录与基线；④ 异常按三段处理：第一段全局旁路（§9.1）→ 第二段挂起 → 第三段非挂起（改引 §9.1 两表，v39 L974）。
- 指针为空：§3 L195「重启或换 CLI 后可能为空，也可能残留」；§9.1 说明 L813「指针无效或为空时先走第二段（有挂起任务时），再按第三段选择就绪任务」。
- 出口：第一段恢复入口 / 第二段挂起四行 / 第三段两表。**有出口**。

### S19 卸载 → 原生归档 → 重装 → 对账

- §9.4（L855-871）：机制不可用 → 不降级，唯一动作是卸载；默认仅模块卸载（保留项目数据）。
- 卸载健壮性（L866）：入口不依赖机制运行时/账本/入口脚本；必须恢复基底配置、移除 hook 与变体 pin；步骤可重复执行、中断后重跑不产生副作用。
- 仅模块卸载期间用原生流程归档的图内任务，重装后按 §7.7 对账修复补记账本（L870，**明确为设计允许的合法路径**）。
- 重装后：按 §7.7 对账，账本与前置集合继续有效（L869）。
- 出口：类型 1 补记（S13）。**有出口**。§10 自检 L891 已列该往返。

### S20 边变更失败（建边后置校验失败 / 被拒的归档目标建边）

- 建边流程（§7.5 L609）：前置校验（两端存在；目标非异常；建边另要求两端活动区 + 前置未完工（含正常但未归档）；无自环/成环）→ 写入暂存（不提交）→ 后置校验（检环、重建视图）→ 通过后提交；失败 → 回滚暂存、不提交、报告。
- 对已归档目标建边：§7.5 L602 明令两端必须在活动区 → 前置校验失败 → 不写入。**有出口（拒绝并报告）**。
- 给进行中任务建边：允许（前置未完工），只阻收尾不阻继续（L607）；组合表「等待」行（L648）。
- 出口：回滚报告 / 等前置 / 按删边或替换放弃处置（L607）。**有出口**。

### S21 当前指针无效或为空

- 无效清单（§3 L195）：指向已归档、规划中且前置未满足、未归档且账本异常、账本为「正常但未归档」→ 视为无当前任务。
- 未归档异常 → §9.1 第一段全局旁路接管（L793/L805 明确）。
- 正常但未归档 → §7.7 类型 3（L195、L758）。
- 指针为空 → §9.1 说明 L813。
- 出口：全部有明确分支。**有出口**。

### S22 类型 4 身份恢复（P 继任指向丢失 / 已落盘指向被占用）

- 场景 A：异常 P 指向丢失/非法 → §6.5 P 角色解析表末行（L498）：角色完整性不一致，先类型 4 恢复既有关系；无据则阻断，不走一般任务无指向删边分支。§6.5 角色完整性守卫 L500：异常 P 的指向丢失/非法先于类型 5 分流；合法预写标识在而目标未建属类型 5，不因目标未建误算非法。
- 场景 B：已落盘指向在补建/重连时发现目标标识已被其他身份占用 → §7.8 标识占用校验时点 2（L681）：按 §7.7 类型 4 阻断；不得覆盖或当同一继任者。合法原关系的恢复仍按类型 4 恢复边界。
- 场景 C：原预写标识被他身份占用 → §7.8 类型 4 恢复边界例外（L704）：允许把指向改为本次重新生成且经占用校验通过的标识，作为原关系的载体更正；须人确认；不得改挂无关既有任务、不得覆盖其身份。矩阵类型 4 行（L696）已含该第三许可（v45 L928）。
- 出口：恢复后重分类（目标未建 → 类型 5 补建）；不可确认 → 阻断（§9.1 L808 报告阻塞）。**有出口**。
- 人面向核对提示（L704 段末，v45 新增）：改指前须核对目标目录与其说明是否同一任务；机制只校验存在性、无环、不清 P 链，不校验身份归属。→ 该提示是「由人确认」的加强，未新增机制。

### S23 v43–v45 标识占用场景

- 写入前（§7.8 L680）：替换/放弃-新建替代/类型 1 P 预写指向，及据指向建任务前 → 校验预生成标识未被现有记录（含已预写标识）中其他身份占用；冲突 → 不写入、不覆盖，重新生成后重校验。对应 §6.5 发起 L461、§6.6 发起 L508（v44 L934）。
- 已落盘（L681）：冲突 → §7.7 类型 4 阻断。对应 S22-B。
- 类型 5 补建（L664）：按 §7.8 占用规则校验目标标识（v44 L934）。
- 载体更正（L704 + 矩阵 L696）：S22-C。
- 出口：重新生成重校验（写入前）/ 阻断（已落盘）/ 载体更正（人确认 + 占用校验通过）。**三条都有出口**。
- §10 自检 L891 已含「修复丢失的已预写未建继任指向」。

### S24 兜底：所有场景的共同终局

- §7.7 绕过兜底（L628-631）四分支覆盖：已归档无记录/挂起 → 类型 1；正常未归档 → 类型 3；无法解析/非法 → 类型 4；合法可解析异常处分 → §7.4 表行（异常 P 先过 §6.5 守卫）。
- §9.1 已收尾表末行 L808：无当前任务、无就绪图内任务、收尾未完成 → §7.7 完整性自检/对账；异常前置按 §7.4；仍无出口则**报告阻塞**。
