| 类型 4 记录修复（L662） | 恢复字段同次提交（L662） | 提交前失败=原不一致；提交后重新分类 | 原不一致仍在 | §7.7 L635 分类前置守卫 | ✓ |

**§7.1 结论：所有多步动作的第一步都写入了识别标记（满足口径 13「标记随第一步写入」）；每个残留都有唯一签名并能被启动自检/类型识别句/组合表行命中（满足口径 14）。**

### §7.2 重复动作：相同可读快照是否会选出互斥的自动恢复

| 场景 | 快照 | 可能的恢复 | 区分事实 | 是否互斥自动恢复 |
|---|---|---|---|---|
| 对同一任务二次替换 | X 已归档+异常+指向→X'（终态） | §6.5 L456 拒绝（只适用未归档） | 归档态 | 否 ✓ |
| 替换后再放弃同一任务 | X 异常 | §6.6 L506 例外 → 类型 5（不重新发起） | 账本已异常 | 否 ✓ |
| 替换后再返工同一任务 | X 已归档 | §6.4 L419 拒绝（已归档不直接返工） | 归档态 | 否 ✓ |
| 挂起 + **有**登记标记 | T 挂起 + 标记在 | 类型 2 恢复/取消 | 标记 | 否 ✓ |
| 挂起 + 无标记 + 返工集合**非空**无未归档成员 | 已移交 | §6.4 步骤 5 / 表 4-2 行 3 清挂起 | 集合非空 | 否 ✓ |
| 挂起 + 无标记 + 返工集合**空** | 已移交 | 类型 2：人确认补建 **或** 行 7 清挂起 | **人确认** + 「确无返工记录」 | 两者均**人发起**，无自动恢复；且 L446「无法确认时阻断」。→ 否 ✓（候选 C5） |
| 挂起 + 无标记 + **移交未完成** | 存量 | L625 禁止自动评估清挂起 | 移交持久判据 | 否 ✓ |
| 已落盘指向被他身份占用 | 指向 X，X 有其他身份 | 类型 4 阻断 (L681) **或** 类型 4 改指新标识 (L704 例外) | **人能否确认原关系** | 均人发起；L704「无法确认…阻断，不猜测」。→ 否 ✓（候选 C4） |
| 有指向 + 继任者未建（二次进入） | 同 §7.4(a) | 类型 5 补建（幂等，窗口①） | 同 | 否 ✓ |
| 取消登记后再取消 | 标记已消费 + 原状态已恢复 | 窗口末行「后不重复取消；原挂起不得误清」 | 标记已消失 | 否 ✓ |

**§7.2 结论：未发现「相同可读快照 → 两个互斥的自动恢复」。** 两处看似二选一的分支（C4、C5）都以**人判**为选择依据，且都设有「无法确认则阻断」的兜底，不做静默猜判。

### §7.3 guides 盲点 13（历史记录掩盖新登记）专项核查

场景：T 挂起、历史 R1 已归档正常、新一轮 R2 尚未创建且标记丢失。
- 若**移交未完成** → L446 + L625 禁止自动评估与清挂起 → 不静默清。✓
- 若**移交已完成** → 移交过程已由人确认每项意图；若确认为"新一轮未建 R"则按 §6.4 补登记（写入标记）→ 该任务不再是"无登记阻断" → 步骤 5 不适用。✓
- 移交后新登记必带标记（L446 末句）。✓
→ 盲点 13 在该设计下已封闭。

## §8 候选判定：四层过滤 → 反驳搜索 → 端到端模拟 → 最简合规实现 → 作者反驳

按 `design.md` §3.4 八步闸 + guides Step 2/3 依次过闸。缺陷门槛 = guides Core Rule 四类来源。

### §8.1 候选 C1 — 配套 §6.4/§6.5 发起步缺少标识占用校验（来自探针 #30）

- 证据：M L461、M L508 有「预生成标识未被现有记录（含已预写标识）占用；被占用则重新生成后重校验」；C L163-165（替换发起 3 条）、C L193（放弃发起）**均无此句**。
- **F1 承载层**：配套 §9 (C L281/282) 已按引用式跟随 §7.8；占用校验唯一源在 §7.8 (M L679)，配套未重述不构成第二定义，也不改变义务。**不是设计层缺陷**。
- **F2 决策日志**：v44 (M L934) 记录「§6.5/§6.6 发起静态校验补预生成标识的占用与重新生成重校验；配套 §9 保持引用式跟随，未新增定义副本」→ 未要求配套发起步同步。
- **F3 留白 vs 冲突**：差异是"复述与否"，非两规则冲突。
- **F4 故障模型**：正常诚实使用下按 §7.8 校验，结果相同。
- **反驳搜索**：C L281「业务预写/受控恢复的时点、终值与清空以主设计 §7.8 识别字段写入矩阵为唯一规则源」— 命中。
- **端到端模拟**：照配套实现，发起时机制仍须按 §7.8 校验占用 → 行为一致。
- **最简合规实现**：把校验放在 §7.8 一个位置，两文档都引用它 → 满足。
- **作者反驳**：「占用校验的唯一源是 §7.8（M L679），v44 已记录配套 §9 降为引用；发起步是否复述不改变义务（§0：其他位置只许引用、不得复述终值）。」
- **判定：排除（措辞/精度项）。**

### §8.2 候选 C2 — 「替换指向为空」与「P 的指向不得置空」的措辞混合

- 证据：探针 #28 显示「P 的指向不得置空」只出现在两处**历史记录**（M L954 v41、C L454 v41）；当前正文的对应表述是「**已确立的 P 继任关系不得置空**」（M L696 矩阵格、M L704 恢复边界）。
- **F1/F3**：正文两处一致，历史条目按 §0「只记录不定义」不适用「同一判定只在一处定义」。
- **反驳搜索**：M L696、L704 — 命中，当前规范表述存在且一致。
- **作者反驳**：「附录 C 是记录性文字（§0 写作约定明文排除），正文守卫用『已确立的 P 继任关系不得置空』表述一次于矩阵、一次于恢复边界，二者逐字相同。」
- **判定：排除（措辞/精度项 — 历史用词与现正文用词不同，建议在后续修订中统一，但非缺陷）。**

### §8.3 候选 C3 — §6.5 L479「把继任者按 §6.6 的变体放弃」未显式提 P 约束

- 证据：L479「继任者已存在而人决定不再继续时，只能把继任者按 §6.6 的变体放弃并完成相应的重连 / 删边」；若继任者是 P，§6.6 L524 要求「只允许新建替代变体」。
- **F2 决策日志**：v38 (M L981) 已记录身份面收口「§7.7 的 P-放弃接续改为由人决定且不置空」。
- **反驳搜索**：§6.6 是整节引用，L524 属该节 → 约束随之适用；§7.7 类型 5 改判放弃-P (L695) 明确规定「沿用已预写的替换指向建替代任务并重连…不新增写入」。
- **端到端模拟**：放弃继任 P → §6.6 → L524 只允许新建替代 → 新 P 建立 → 项目层判定仍有对象（§6.5 L485）。有出口。
- **作者反驳**：「§6.6 的变体限制（L524）随整节引用生效；且类型 5 改判放弃-P 已单独写明 P 路径（L695）。」
- **判定：排除（措辞项 — 可在 L479 补「（P 按 §6.6 只允许新建替代）」，但约束已可达）。**

### §8.4 候选 C4 — 「已落盘指向被他身份占用」的两条处置（L681 阻断 vs L704 改指）

- 证据：M L681「若已落盘的替换指向在补建/重连时发现目标标识已被其他身份占用，按 §7.7 类型 4 阻断；不得直接覆盖或把它当作同一继任者。合法原关系的恢复仍按本节类型 4 恢复边界执行」；M L704 例外「若原预写标识已被其他身份占用，允许把指向改为本次重新生成且经占用校验通过的标识，作为原关系的载体更正」。
- **表面冲突**：同为「原预写标识被他身份占用」，一处说阻断，一处说可改指。
- **F3 留白 vs 冲突**：L681 后半句明文「合法原关系的恢复仍按本节类型 4 恢复边界执行，不因其目标已存在而误判为冲突」→ L681 把「合法原关系」分支**显式转交** L704；剩下的「阻断」针对的是**不是合法原关系**的情形（无法确认原关系 / 改挂无关任务）。两句管辖的是不同输入域。
- **反驳搜索**：L704「**仍须人确认**，不得改挂无关的既有任务，不得借此覆盖其身份」「无法确认、多个候选或当前关系仍非法时阻断，不猜测」— 命中，且给出选择依据是「能否由人依据现有项目记录或版本库确认原关系」。
- **端到端模拟**：(a) 人能确认原关系 → 载体更正（改指新标识）→ 交类型 5 补建；(b) 不能确认 → 阻断。两条互斥且都人发起。
- **最简合规实现**：以「人能否确认原关系」为唯一分支条件 → 同时满足两句。
- **作者反驳**：「L681 与 L704 的分水岭是原关系能否被确认；L681 已明文把可确认的情形转交 L704，二者不构成同一情形的两种处置。」
- **判定：排除（属 §3.4 已登记的受控恢复例外，非冲突）。**

### §8.5 候选 C5 — 「挂起 + 无标记 + 已完成移交」的两种处置（补建 vs 清挂起）

- 证据：§7.7 类型 2 (L660)「无标记且已完成旧口径移交后，人确认补建（按 §6.4 新登记）或在确无返工记录时按表 4-2 行 7 清挂起」。
- **表面冲突**：同一快照两个相反出口（补建 R / 清挂起）。
- **F3**：选择依据是「**人确认**」+「确无返工记录」，不是自动判定。
- **反驳搜索**：L446「无法确认时阻断」；L625「启动只识别/报告，不写账本、不改任务状态，不自动执行对账修复」。→ 无自动恢复。
- **端到端模拟**：启动 → 识别为类型 2 → 报告 → 人判断 → 二选一。两条都是允许的、人发起的出口，符合「有出口」。
- **最简合规实现**：报告 + 等确认 → 满足。
- **作者反驳**：「两者都由人确认，且 L446/L625 禁止自动执行；不存在同一快照被自动判为两种互斥恢复的情形。」
- **判定：排除。**

### §8.6 候选 C6 — 建边对「处分已完成的异常目标」永久被禁

- 证据：§7.5 L604「目标账本为'异常'的不得建边（先按 §7.7 类型 5 向前完成）」。若目标 X 的处分**已完成**（已归档 + 下游不指向它 + 继任者已建，§7.4 L586 终态），则类型 5 无需动作 → 建边条件永远不满足。
- **F1 承载层**：设计层规则明确 → 属设计层。
- **F2 决策日志**：§0 事实边界「已归档任务不可替换、不可放弃、不可重开」(L46)；§7.5 L602「已归档任务不再被选择、不再收尾，给它挂前置改变不了任何判定，只会在归档终态上留下'前置非正常'的组合，所以不接新建边」。→ X 处分完成后必然已归档 → **已落入 L602「两端都必须在活动区」的独立禁令**，L604 不是唯一拦路者。
- **语义核对**：终态 X 必然已归档（终态三条件之首即"已归档"）→ L602 已独立禁止。L604 与 L602 同向，不构成"缺出口"。
- **真实场景**：想给一个"已被替换且处分完成"的旧任务挂新前置 —— 该任务已归档，按有意取舍不参与后续顺序。
- **反驳搜索**：L602（两端活动区）+ L586（终态需已归档）— 命中。
- **作者反驳**：「处分完成蕴含已归档，L602 已独立禁止对归档目标建边；L604 只是并列的一条，删除它结论不变。」
- **判定：排除（冗余但不冲突；措辞项可选）。**

### §8.7 候选 C7 — 类型 1 一般任务「按 §7.4 处置其未归档下游」作用于已归档任务

- 证据：L657 一般任务分支，对象**已归档**（类型 1 的输入即"已归档但账本无记录/挂起"），却要求「按 §7.4 处置其未归档下游」。
- **表面问题**：guides 盲点 6「引用当作出口，但目标段开头限定只适用于未归档任务」。
- **前提核对**：§7.4 **没有**「只适用于未归档任务」的开篇限定（与 §6.5 L456「替换只适用于未归档任务」不同）；§7.4 表行 (L586) 明确以「已归档 / 未归档」为谓词输入，且明文「已归档任务不可再发起替换 / 放弃；已实施部分按类型 5 完成」→ 该段**显式覆盖已归档对象**。
- **反驳搜索**：L586 括注「处分未完成（…**该任务未归档**——三者任一）→ 类型 5」与「已到终态（**已归档**，且…）」→ 已归档态被显式建模。
- **端到端模拟**：已归档 + 无指向 + 下游仍指向 → (b) 为真 → 类型 5「无替换指向」分支 → 补齐删边（L666）。有出口。
- **判定：排除（§7.4 的域覆盖两种归档态，不是盲点 6 的形状）。**

### §8.8 候选 C8 — §7.5 L595 的「先按 §9.1 第一段分流」自引用

- 证据：L595「以下开工、完成、返工、替换/放弃和边变更，在各自静态校验之前先按 §9.1 第一段分流」；而类型 5 的补建/重连/删边本身是边变更，且类型 5 就在 §9.1 第一段的「其他未完成替换/放弃…走类型 5」结果里。
- **F3**：循环形状，但（a）类型 5 是**人发起的修复动作**，进入时已在第一段命中并转交；（b）L610 给类型 4/类型 5 的字段改写登记了「不适用本表校验」豁免；（c）§7.5 的边变更校验（L609）是**技术校验**（两端存在、不成环、暂存后置），不是入口分流。
- **反驳搜索**：L609「边变更的统一校验」仅含前置/暂存/后置/回滚 — 命中，无 §9.1 分流环节。
- **最简合规实现**：把 §7.5 边变更校验实现为纯技术校验，不做路由 → 无循环。
- **作者反驳**：「L595 的分流是入口级，L609 的校验是写入级；类型 5 自分流进入后不再回到分流。」
- **判定：排除。**

### §8.9 候选 C9 — 类型 5 无指向分支与类型 1 一般任务落在同一「无指向 + 有原因」签名

- 证据：L666「无替换指向（有原因、无指向）：补齐下游删边与旧任务归档」；类型 1 一般任务 (L657) 也产出「无指向 + 有原因 + 已归档」。
- **核对**：两者归档态不同（类型 1 已归档，类型 5 可能未归档），但动作集合相同（删边 + 归档），不存在互斥；且 L657 括注明文「本类型没有替换指向，处分未完成时按 §7.7 类型 5 的'无替换指向'分支补齐删边与旧任务归档」→ 设计已显式把两者合并到同一分支。
- **判定：排除（有意合并，非冲突）。**

### §8.10 候选 C10 — 「唯一清空点」表述只在历史记录，正文无对应句

- 证据：探针 #26 仅 1 命中（M L954 v41 记录）：「唯一清空点 = 一般任务改判放弃、归档前置空」。

- **判定：排除（符合 §0 的封闭断言闸口要求；属有意改造）。**

### §8.11 候选 C11 — 主稿 §9.1 未收尾表「P 存在且未归档，账本为'正常但未归档'」专行 vs 非 P 无专行
