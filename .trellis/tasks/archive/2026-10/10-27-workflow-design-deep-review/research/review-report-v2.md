## 2. 主发现

### F1 — 已归档任务作为前置的「合法来源清单」四份副本三种成员集，且收尾任务放弃后重定义无任何来源

**约束编号**：§4.4 / §7.5 / §0 事实边界 / 配套 §2·§6.7；涉及 B9、A1
**来源类型**：内部矛盾（事实 A）+ 与真实场景不符 / 跑不通（事实 B）
**严重度**：中偏低
**影响阶段**：实现方案建图与建边校验阶段会被迫二选一；若按 §7.5 字面实现，真实存在的边会被判非法。

**事实 A：两份清单成员集不一致（硬矛盾，不是措辞分歧）**

| 位置 | 已归档任务作为前置的合法来源 |
|---|---|
| §4.4 `:308` | 0→1 建图、返工、**替换与放弃-新建替代**、**类型 1 补建的继承**、活动期建边后随任务归档 → **5 个成员** |
| §7.5 `:602` | 0→1 建图、返工与替换继承、活动期建边后该前置归档 → **3 个成员** |
| §0 `:45` 事实边界 | 同 §7.5 → 3 个成员 |
| 配套 `:28`、`:216` | 同 §7.5 → 3 个成员 |

§7.5 的 `:602` 是**机制校验句**（`:609` 的边变更统一校验以此为前置条件）。照它字面判，「放弃-新建替代」与「类型 1 补建」产生的已归档前置边不合法；但 §4.4 `:308` 与 §6.5/§6.6 明确要求产生这类边。**§4.4 与 §7.5 对同一条边给出相反判定。**

**事实 B：收尾任务放弃后重定义，无任何清单成员可用**

- §6.7 `:528` 明写收尾「依赖最后一个实现任务」；`:533` 明写「收尾任务自身被替换或放弃时，由人重新定义收尾任务」。
- 放弃的**删边变体**（`:514`）把最后一个实现任务留在归档区（旧任务异常归档），**不作重连**。
- 此时新收尾任务的前置是已归档任务，产生方式是「任务定义（人重新定义收尾）」——既不在 §4.4 的 5 个成员里，也不在 §7.5 的 3 个成员里。
- 想走建边又必然撞 `:602`「两端都必须在活动区」+ `:603`「前置必须尚未完工」。
- 这是**可达的诚实使用场景**，且没有合法来源。

**为什么「能跑通」不改变结论**：创建任务时写 deps 不进 §7.5 的校验（`:609` 只列建边 / 返工加边 / 重连），所以真实系统靠「创建期不校验」侥幸成立。这恰恰说明规则文本是错的，而且让缺陷更隐蔽——按 §7.5 执行的人会判错，而收尾这条确实没有合法来源。

**最小修复方向**：见第 4 节根治方案 R1。

### F2 — 给进行中任务追加前置后，「下一步去跑那个前置」在入口表里没有一格

**约束编号**：§3 / §7.6 / §9.1；涉及 B1（AI 仅凭设计稿可执行）
**来源类型**：跑不通 / 入口缺一格
**严重度**：中
**影响阶段**：实现方案的入口路由实现；AI 单跑会停在「报等待」而无下文。

**证据链**：

- §3 `:195` 指针无效清单 = {指向已归档、规划中且前置未满足、未归档且账本异常、正常但未归档}，**不含「进行中且前置未满足」** → 指针不释放。
- §9.1 两表当前任务行（`:792`、`:804`）是命令式：「继续当前任务……进行中且前置不全正常时工作不停、收尾等前置」；§9.1 开头明写「逐段判定，命中即停止」。
- §7.6 `:617`：选择规则只在**没有当前任务**时进行。
- 于是「当前任务被后置前置挡住」时，路由表只有「继续 + 等前置」，选择规则又不启动，**没有一格指向「先去跑那个前置」**。
- `:607` 给的出口是「人按删边或替换 / 放弃处置」——那是撤销顺序约束，不是执行前置。

**反驳尝试（我按作者立场构造，未撤销）**：「指针只是提示，以 DAG 与账本为准」（§3）；建边由人发起，人在场能自己开工前置。这使它不是硬死锁，但 B1 要求「AI 仅凭设计稿与基底机制就能执行」，而路由行是命令式且「命中即停止」，AI 单跑会停住。现场（进行中任务等一个 planning 前置，该前置从未执行，报告判「卡点：无」）正好演示了这一点。

**最小修复方向**：见第 4 节根治方案 R2。

### F3 — 返工登记准备的预生成标识无占用校验，且依赖标识撞号后无受控重生成路径

**约束编号**：§7.8 / §6.4；涉及 §10 类迁移义务、口径 10⑥
**来源类型**：内部矛盾 / 防御缺口
**严重度**：低（概率低，链路可构造）
**影响阶段**：实现方案的标识分配与类型 4 修复能力。

**证据链**：

- §7.8 `:680` 写入前校验的唯一源枚举只列「替换 / 放弃-新建替代 / 类型 1 P 预写指向，及据指向建任务前」，**没有返工登记准备**（§6.4 `:423` 明确要求「预生成 R 的依赖标识」）。
- §6.4 `:424` 只校验**稳定定位**占用（「位置占用…停止」），**不校验依赖标识**是否被占用。
- §7.8 矩阵（`:686`–`:700`）为「写入路径 / 写入时点 / 指向终值 / 说明·原因终值 / 依据」五列，**没有「依赖标识」行**；类型 4 恢复边界（`:704`）只谈指向 / 返工来源 / 说明 → 撞号后**没有改回标识的路**。
- 触发链：标识重生成 bug（同类簿记错误已实际发生过）→ 返工预写撞号无关卡拦截 → 发布把重号写进任务记录 → 解析歧义且类型 4 改不动。

**反驳尝试（成立，故只降严重度不撤销）**：雪花 ID 全局唯一、撞号概率极低；影子副本随标记入库后预写扫描能看见。所以是防御型缺口，不构成日常阻塞。但「依赖标识」是识别条件依赖的字段却不在矩阵里，与 §10 `:880` 类迁移义务的字面要求不一致，且正是口径 10⑥ 的目标形态。

**并入的镜像面**：配套 §6.4 `:163`、§6.5 `:193` 的发起静态校验清单未同步 v44 增补的占用校验——实现者照配套写会漏。这不是独立发现，是 F3 的镜像。

**最小修复方向**：见第 4 节根治方案 R3。

## 3. 根因分析（三条共因）

按用户给出的修正版根因，我核对后确认成立，并补一条我首轮没写出的机制。

### 3.1 生存位置：校验只挂在机制入口，创建期写入无任何校验

- `:609` 的边变更统一校验入口只列 **建边 / 返工加边 / 替换·放弃的重连**；**任务创建时写 deps 不在其中**。
- 后果：规则文本写错不会被任何机制链路抓到。创建期写进去就生效，而设计稿又依赖创建期承载「继承」语义。
- 这解释了 F1 为什么能长期存在：真实链路测试只验证机制会拦的东西，**创建期是盲区**。

### 3.2 收尾是唯一没有任何验收位的角色

- A1（`:78`）只写 P 的继任路径；B9（`:97`）不含收尾；§10 自检（`:891`）只有「建收尾」与「替换收尾」，**没有「放弃收尾 + 重定义」**。
- `.trellis/spec/docs/index.md` 的注册表与全部探针中，「收尾」出现 **0 次**（实测 `rg -c` = 0）。
- F1 的第二面正落在这里，且它是唯一连「替换 / 新建替代」后门都没有的路径。

### 3.3 「能跑通的路径」被当成「规则成立」

- 两批 15 组场景、12 道终态门全绿；口径 10⑤ 把封闭断言逐条标「已核对」。
- 但我核对时用的路径族是「建图 / 继承 / R 加边 / 重连 / 迭代建边 / 删边 / 类型 4 修复分域」，**没有「任务定义」这一族**。
- 于是「这条断言我核对过」被混同为「这条断言为真」。F1 恰是漏掉那一族的产物。

### 3.4 枚举按来源写，而不是按规则写

同一清单有 4 份副本、3 种成员集（§0 3 个 / §4.4 5 个 / §7.5 3 个 / 配套无成员），每次只补被点到的那一处。

### 3.5 类迁移义务只在被点到的那一格执行

v40 把 §7.4 换成字段谓词，同类的「边」与「创建」一条没迁移；v41–v45 只查识别字段，没查「来源清单」这类同类载体。

### 一句话根因

**缺陷的生存位置是「整个创建期不校验」——所以修一处、留一类；而链路测试与六项扫法都只照机制会拦的地方，照不到写进去就过的地方。**

## 4. 根治方案（一次解决整类，不是逐条打补丁）

三条共因，因此修复要落在**同一处结构性缺口**上。方案分三块，顺序固定：先建唯一源，再补入口与字段，最后同步副本与扫法。

### R1 — 建立「已归档前置的合法来源」唯一源（治 F1）

1. **定唯一源**：以 **§4.4「归档终态约束」** 为唯一源（它已是归档侧约束的归属处），成员集改为按**产生规则**而非按来源枚举：
   - **继承类**：0→1 建图、返工、替换、放弃-新建替代、类型 1 补建 —— 新任务继承旧任务当前前置集合时，被继承者可以已归档；
   - **活动期建边后随前置归档**：边建于两端活动区，前置一侧随后归档；
   - **任务定义类（新增，治事实 B）**：收尾任务重定义、基线变更新建任务、P 建图 —— 人定义任务时可直接把已归档任务写入前置集合，**不受「两端活动区 / 前置未完工」限制**（该限制只约束建边，不约束任务定义）。
2. **§7.5 `:602` 降为引用**：改写为「已归档任务作为前置的合法来源按 §4.4 判定；本节只约束建边与重连」，删除自带的 3 成员枚举。
3. **§0 `:45`、配套 `:28`/`:216` 同步降为引用**，删除各自成员枚举。
4. **§6.7 补一句**：收尾任务重定义时，其前置集合按 §4.4 的任务定义类确定（可含已归档的最后一个实现任务），不走 §7.5 建边校验。
5. **补齐验收位**：§10 自检增加「放弃收尾任务 → 人重定义收尾 → 前置为已归档任务 → 项目完成判定以新收尾为准」；A1 的 P 路径条款旁补收尾角色的同等条款。

### R2 — 给入口表补一格路由（治 F2）

1. §9.1 两表当前任务行（`:792`、`:804`）补一格：**「当前任务进行中、但被后置前置挡住收尾 → 先按 §7.6 取最早就绪的该前置图内任务开工，完成后回本任务」**。
2. 这格是**引用 §7.6**，不新建选择规则；它只在「有当前任务且收尾被挡」时命中，与现有「继续当前任务」不重叠（后者是收尾不被挡时的行为）。
3. §10 自检把该场景推进到「建边 → 开工前置 → 前置完成 → 回本任务 → 收尾通过」，不再只写到「建完边就收」。

### R3 — 把依赖标识纳入占用校验与受控恢复（治 F3）

1. §7.8 `:680` 写入前校验枚举补 **`返工登记准备（R 预生成依赖标识）`**。
2. §7.8 矩阵增列或增行，给**依赖标识**一个受控重生成许可：撞号时按「重新生成后重校验」处理，与替换/放弃侧同款。
3. 类型 4 恢复边界（`:704`）补「依赖标识的受控重生成」，使撞号后有改回路（仍须人确认、不得借修复新建关系）。
4. 配套 §6.4 `:163`、§6.5 `:193` 发起静态校验清单同步 v44 的占用校验项。

### R4 — 同步扫法与注册表（治 3.2 / 3.3，防止复发）

1. 路径族枚举补 **「任务定义（创建期写 deps / 收尾重定义 / 基线变更新建）」** 这一族，并用于口径 10⑤ 的封闭断言核对。
2. `.trellis/spec/docs/index.md` 注册表为**收尾角色**补条目与探针（当前 0 次），并为「来源清单唯一源」补探针。
3. §0.1 口径 10 的扫法说明补一句：**「能跑通的路径」不等于「规则成立」，创建期写入不进机制校验，必须单独枚举。**

### 修复顺序（硬性）

**源 first → 引用与镜像 second → 探针 third → 修订记录 last。** 先改唯一源，再把摘要、兄弟位点、配套镜像降为正确引用，然后更新/新增能捕获根因的探针与期望值，最后写附录修订记录（只记录源改了什么、哪些副本跟随，不重定义规则）。禁止在多个位置各补一句。
