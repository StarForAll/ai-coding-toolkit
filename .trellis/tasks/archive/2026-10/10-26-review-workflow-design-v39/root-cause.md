# 根因判定（阶段 B · B0）

依据：`review-report.md` v2 §3（四层根因）+ 用户五点分析核对结论。修复前先定根因，避免逐条打补丁。

## 1. 直接机制

v39 的缺陷集中在同一处：§7.4「异常任务的下游处置」这条**唯一源**只登记了 4 种继任形态中的 1 种；而 v39 新增的「改判放弃」形态、以及早已存在的「补建」形态，都要求下游重连到继任者。于是同一状态（旧任务已归档 + 账本异常 + 有替换指向 + 继任者未建）被两条规则分处分。

## 2. 四层根因

| 层 | 根因 | 证据 | 为何会复发 |
|---|---|---|---|
| **L1 登记维度** | 限定与例外按「来源 / 角色」立格，状态空间（继任形态 × 归档前后）从未枚举 | §7.4 559/563；v36→v38 连续三版同格位；v39 新增形态未登记 | 每新增一种来源必缺一格；v36 就这样补过、v37 又补、v38 再补 |
| **L2 枚举单位** | 去重单位是「判定」（§0 37、口径 11 66），验收判据是「有入口 / 有出口」（A1、口径 10 ②）；两者都不检查「同一状态只有一个处分」「同一动作只有一份序列」 | 动作链 4 处、2 种语序（主 464/467 + 配套 193/196 vs 主 633 + 配套 287）；F1 的入口存在而处分冲突仍通过 A1 | 新写的序列与旧序列并存时，没有任何检查会失配 |
| **L3 闸口位置** | 多步写入纪律定义在审查面（§0.1 71「同属审查动作」），写作端无自检、无产出物 | 口径 13/14；§6.5 465 无窗口表 | 每版新文本天然是下一版的缺陷源 |
| **L4 自证与周期** | 修订记录可写「已补」而文本未补；副本比对是点同步（本次改动），旧漂移无主 | 配套 452（v38 声称已补 §5 异常行）vs 实际行 90 未补；口径 11 作用域 | 缺陷跨版存活、被重复发现；记录本身成了噪声源 |

## 3. 共同根因

这套文档把「完整性」设计成**逐格补 + 事后审 + 自述记录**，而不是**按状态收敛 + 写作即产出 + 周期全量 + 记录可核对**。所以每轮都能修好被点名的那一处，生成器一直在生产下一处——v36→v39 的同一格位四连击就是直接观测值。

## 4. 修法与根因的对应（不可只改一处）

| 修法 | 灭的层 | 若省略会发生什么 |
|---|---|---|
| S1 §7.4 改按状态收敛 | L1 | 下一版再出现一种继任形态，同一格再缺一次 |
| S2 动作序列单一源 + 枚举单位扩到序列 | L2 | 两份语序并存，实现者仍可能按「先归档」写，制造 F1 那个状态 |
| S3 §0 加写作闸口 + 记录不得与正文相反 | L3、L4 | 下一版新增多步动作仍无窗口表；记录仍可自证成功 |
| S4 口径 11 周期全量 + §10 自检每版一次 | L4 | 配套 90 这类旧漂移继续无主，直到被点名 |
| S5 探针登记表 | 观测 | 以上四条改了也无法在下一版被机械复核 |

## 5. 反例与边界（修复时不得违反）

1. **不能给继任 P 记挂起**：挂起清除扫的是「返工来源」，继任者不是返工任务，集合为空会永远清不掉。P 的继任只走 §6.5 / §7.7 类型 1。
2. **状态句不得退化成阶段句**：若把「有已实施未完成的替换/放弃」写成「按阶段（实施 / 归档）」，就又把状态空间按时间切片，回到按来源枚举的老问题。
3. **序列单一源不得搬进配套文档**：§7.9 把「对账与恢复规则」交给配套，但序列顺序属设计层约束（顺序决定归档与补建的先后，进而决定哪些处分合法），必须留在主稿 §7.7，并在 §7.9 一句写清归属，避免新增一处「两处都算权威」。
4. **不做文档内新章节 / 不新增机制**：§10「本文件不扩张」、§0.1 口径 2。所有修法都是改写现有句子与表行。
5. **不改已有判定**：表 4-2 行集、组合自检表行集、状态取值一律不动；S1 只改「归档后处分」的限定维度，不改任何转移。
6. **识别以字段为准，不枚举来源**：凡「某态从哪来」的列举都会随新来源过期；识别句只写字段组合（有/无替换指向 + 说明 + 下游边 + 归档态）。
