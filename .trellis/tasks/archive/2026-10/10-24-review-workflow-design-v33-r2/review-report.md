## Main findings

### F1 「当前任务」有效性对「正常但未归档」指针双口径，§9.1 两处行 2 构成死行（内部矛盾；B1）

- **约束编号**：B1（"每节可定位到唯一判据""§9.1 三段互斥且状态穷尽……指针无效按 §3 判定"）
- **证据**：
  - §3 术语「当前任务」（L180）：无效清单含"账本为'正常但未归档'"→"视为无当前任务；入口判定以 DAG 视图与账本为准"。
  - §9.1 第三段两表行 2（L704、L716）："**有当前任务**，但该任务未归档、账本为'正常但未归档' → 按 §7.7 类型 3 修复后再继续"；说明区（L725）"'当前任务'按 §3 判定"；B1 验收列"指针无效按 §3 判定"。
  - §9.1 第二段进入条件（L688）："当前任务无效（……按 §3 视为无当前任务）而存在挂起任务"——先于第三段命中。
  - §8.4 第三段（L670）："按 §3 视为无当前任务**或走对应修复行**"——"或"字把两种口径写进正文。
- **推演**：
  - 按 §3 + 说明区读法（§3 为权威）：指针指向「正常但未归档」任务 = 无当前任务，**行 2 永不可达（死行）**——行 1（L703/L715）要求"账本为'无记录'"，行 3（L705/L717）只收"已归档 / 规划中且前置含非正常"。
  - 该指针失效后的实际路由：未收尾表的"无当前任务"四行（L706–L709）**全部以 P 为对象**，非 P 的该态任务在 §9.1 没有以其为主语的行；已收尾表下该任务自身不就绪（账本非"无记录"），落入 L718"最早就绪的其他任务"或 L720 对账。真正的兜底来自 §8.4 第三段末句（L670"账本为'正常'但任务未归档 → 按 §7.7 类型 3 处理"）与 §7.7 启动对账（L576、L580、L603）。
  - 两种读法的实质分叉：行 2 读法下会话**留在该任务上**，引导人按类型 3 确认修复（L603：类型 3 出口本就要求人确认，非自动修）后继续它；§3 读法下**视为无当前任务并改选另一个就绪任务**，该任务的修复由 §7.7 对账入口承载。分叉是"选哪个任务 + 修复引导路径"，不是"自动修 vs 人对账"——但仍是 B1 意义上的同一状态两种走法。
  - 旁证：§9.1 未收尾表 L707 把 P 自身的「正常但未归档」放在"**无当前任务**"行下处理（与 §3 一致），而 L704/L716 把非 P 的同状态放在"有当前任务"行下（与 §3 不一致）——§9.1 内部两种处理并存。
- **来源类型**：内部矛盾（同一情形两条规则给出不同路由）
- **影响**：入口路由是每次会话第一判定与 §10 自检"入口兜底"场景；实现方案落入口逻辑时必须二选一——**实现阶段被迫改**。触发态为防御态（诚实流程不可达，见 F3 可达性分析），严重度中等；但 §9.1 行集是"状态穷尽"验收对象，死行本身就是 B1 未达标。且该口径家族已跨 v31→v33 三轮各改一半（见归因时间线），不收口还会继续漂。
- **建议（最小修复，不新增机制；两案择一，写入 §10 修订说明，不得并存）**：
  - **案 B（推荐，净复杂度更低）**：保留 §3 不动，删除 L704/L716 两行；「正常但未归档」指针统一按 §3 视为无当前任务，修复由 §8.4 L670 末句 + §7.7 类型 3（启动对账标记 + 人发起）兜底——出口完备（类型 3 修复本需人确认，"入口就地引导"的损失有限）。同步收敛 L670 的"或走对应修复行"两可句。与 §10"净复杂度不增"及 v32"按 §3 引用、删除自带口径"原则同向。
  - **案 A（备选）**：从 §3 无效清单移除「正常但未归档」，使行 2 成为活行。注意波及面比表面大：除 §8.4 L660/L670、§9.1 说明区、附录 C 新条目外，还需处理 §8.4 第三段行首条件（拆句后"按 §3 有效 → 继续当前任务"会把该态吞进"继续"，须额外排除）。
  - 两案都需同版同步配套文档（`依赖机制设计说明.md` `design` 字段同版 bump）。

### F2 §8.4 第三段括注冒充「按 §3 有效」，多出"账本为'无记录'"一处，把挂起指针排除在有效之外（内部矛盾；B1；严重度低于 F1）

- **约束编号**：B1
- **证据**：
  - §8.4 第三段（L670）："有当前任务且**按 §3 有效**（未归档、**账本为'无记录'**，且进行中或前置全正常）→ 继续当前任务"。
  - §3（L180）无效清单不含"挂起" → 指向挂起任务的指针有效；§9.1 第二段进入条件（L688）"当前任务按 §3 判定有效**且挂起**"只有在挂起指针有效时才可满足；§8.4 第二段（L665）也以"当前任务挂起"为上下文来源之一。
  - 差异恰好只有一处：§3 无效清单的否定 = 未归档 +（进行中或前置全正常）+ 账本 ∈ {无记录, 挂起}；括注把账本收窄为"无记录"，多排除的恰是挂起。
  - 归因：v32 修订说明（L842）明文"§8.4 步骤 1、§9.1 第二段进入条件与说明一律按 §3 引用，**删除自带口径**"；本括注是 v33（dc33762）加回的自带口径——违反上一轮自己定下的原则。
- **推演**：
  - 在 §8.4 自身段序下该括注不会误伤挂起指针：步骤 4 按三段顺序处理，第二段（L665"当前任务挂起"）先接管，第三段的括注到不了挂起情形。
  - 分叉出现在**跨节传递**：实现者若按 L670 括注实现 §9.1 L688 第一支的"按 §3 判定有效"，则"有效且挂起"恒假 → 挂起指针全部落入第二支"按创建时间取最早的挂起任务" → 指针指向 T1（挂起）而更早的 T0（挂起）存在时，第二段上下文从 T1 变为 T0，四行子表结论可能不同。第二支兜底存在，第二段不会失效——是上下文选错，不是段失效。
- **来源类型**：内部矛盾（有效性定义复述时收紧，且违反 v32"删除自带口径"原则）
- **影响**：B1"唯一判据"被破坏；分叉需经"错误复述被反灌回 §9.1"才行为化，属跨节传递风险，严重度低于 F1。
- **建议（拆句，既不冒充 §3 又保住段内正当条件）**：L670 改为"有当前任务且按 §3 有效 → 继续当前任务；本段只处理非挂起，故其账本为'无记录'"。不要改成纯"按 §3 有效"了事——"无记录"是第三段（非挂起段）的正当收缩（挂起由第二段消费），删掉它反而会在第二段未命中时让挂起任务掉进"继续当前任务"。

### F3 「前置满足」判定两口径，收尾侧无挡板，可违背可见性顺序且不产生对账项（内部矛盾，低频防御态；B1 + 轻量 B9）

- **约束编号**：B1（唯一判据）、B9（失败安全：可见性顺序）
- **证据**：
  - 字面口径：§4.3（L250）"依赖满足 = 前置任务在账本中的状态为'正常'"；§7.4 表（L538）"正常 → 满足"（对下游，不带归档条件——最直接的字面表述）；§4.5（L301）、§3 就绪（L182）、§7.5 开工/完成（L548/L549）、§5.3（L340）、§6.3（L392）、§9.1 行 1（L703/L715）均为"前置全部为'正常'"。
  - 相反口径：§7.7 组合表（L598）"前置含'正常但未归档' → 等待（欠一次类型 3）→ **先按类型 3 修复该前置**"。
  - **§7.5 节内自相矛盾**：L548 开工校验把账本"正常"当前提满足；L554/L560 建边规则却把"正常但未归档"与"尚未完工"（无记录/挂起）并列为可接受前置（L560 括注"前置未完工（或为正常但未归档）"）——同节两种定性。
  - 辅助（不单独作硬证据，因主语可两读）：L580"账本'正常'但未归档 → 视为未满足并报告"。
- **推演**：
  - **开工侧有可推导挡板，v1 的"开工一路通过"撤回**：§7.5 L575"开工前对账：前置集合、账本、派生视图一致才允许开工" + §7.7 L585"组合自检在启动时与**每次对账前**执行" + L598 出口"先修复该前置"，串起来可挡住开工。但这是推导链而非明文——L548 的字面口径与该链不一致，只按 L548 实现开工校验、未把开工前对账实现为含组合自检的实现者会漏。判据不唯一仍在。
  - **收尾侧无挡板，这是真正的洞**：§5.3 L343 / §6.3 L395 的兜底句是"**前置集合不全正常**按组合表'等待'行处置"——前置账本恰为"正常"（只是未归档），条件不成立，兜底不触发；收尾序列（校验源状态 → 归档 → 账本写正常）没有对账钩子。结果：下游 D 可在前置 P 未归档（未完成）时通过收尾、归档并写"正常"；此后组合表行 1（L589"已归档 + 正常 + 前置全正常"）对 D 字面判**合法、不产生对账项**——违背 §4.2 可见性顺序第②点（L241"下游只能在归档完成且账本提交后看到'正常'"）。
  - 后续是否暴露取决于 P 的类型 3 修复走向：P 改回"无记录" → D 变"已归档 + 正常 + 前置含非正常" → 组合表行 2 / 类型 4 兜底（出口存在）；P 重新归档并保持"正常" → 最终一致，但 D 曾在 P 未归档时被判完成的窗口已发生且账本无痕迹。
- **来源类型**：内部矛盾（口径失配 + 收尾侧出口缺口）。**低频**：触发态"未归档 + 正常"在诚实流程中不可达——表 4-2 中"正常"的写入者只有收尾逻辑（先归档后写账本，§5.3/§6.3）与类型 1 修复（对已归档任务），均不产生该组合；类型 3、表 4-2 行 6 只是消费该态。全文无一处说明其产生路径（留白，见排除项 4）。
- **影响**：仅防御/故障恢复场景触发；但收尾侧是完成判定本身，一旦触发即静默违背可见性顺序，且 D 侧无对账项——正是最需要确定性时无确定性。实现阶段需自行补口径。
- **建议（一处定义收口，不逐处改写八处副本）**：在 §3 或 §4.3 加一句统一定义——"'前置为正常/已满足'不含'正常但未归档'（该态属类型 3 不一致，视为未满足，先按 §7.7 类型 3 修复）"；§7.4 表 L538 同版核对加同等限定。其余各处（L182/L269/L301/L340/L392/L548-549/L703/L708/L715）保持"前置全部为正常"措辞不动——一处定义改语义，零散副本不必动，净复杂度反而下降，也规避 §7.9"重复规则同版同步"的漂移风险。不新增机制。

### F4 表 4-1 行 2 触发列与 §4.5 开工关卡不同步，且机制关卡条件被写进基底表（低烈度，口径 5 受理："同一规则两处不同"）

- **约束编号**：B1（唯一判据）；涉及 §1.2 分工（基底不含任务间顺序）
- **证据**：表 4-1 行 2（L269）表头"**Trellis 任务状态流转（基底）**"、写入者"基底"，触发列却写"开工：**前置全部正常 + 规划确认**"；而 §4.5 关卡行（L301）写"前置全部正常 + **目标账本无记录** + 规划确认 | 硬（**机制校验**）"，§7.5 L548 才是执行者（"满足后登记当前任务（基底入口）"）。

- **来源类型**：内部矛盾（同一规则两处不同步 + 分层归属错；§7.5 有完整正确规则，烈度低）

- **建议**：触发列改为"开工：规划确认（基底）；前置与目标账本校验属机制关卡，见 §4.5 / §7.5"，或把前置条件移出基底表。

## Wording and precision

- **W1（§3，留白级建议，非缺陷）**：「活动区 / 归档区」在 §0 事实边界（L39）、§7.5（L553"两端都必须在活动区"作为硬闸）、§7.7、§7.8 承重使用，但术语表无条目。按口径 5 属"未规定"留白、不算缺陷；且语义可从 L562（"异常归档的任务……离开活动列表"）与 L526（返工集合扫描两区）反推（活动区 ≈ 未归档任务集）。因它是建边硬闸的运算对象，建议补一行术语（"活动区 = 未归档任务集；归档区 = 已归档任务集"），成本极低，消除"是否含规划中任务"类实现歧义。
