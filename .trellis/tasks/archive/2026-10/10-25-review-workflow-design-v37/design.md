# 设计：v37 审查仍以证据门槛为骨架，修复前先定根因

## 边界

- 只读审查：审查阶段不改 `workflow-design.md` 与配套文档；产出 `review-report.md` + `acceptance-sweep.md`。
- 结论证据链固定在稿内（§ / 表 / 行），不引外部最佳实践。
- 后续修复（同任务、另阶段、人工确认后）受「判定源唯一」协议约束：源先改、引用后跟、探针再跑、附录 C 最后记；主稿与配套同一提交。
- 修复前必须先写 `root-cause.md`（直接机制 + 共同根因 + 为何 v37 的修法没根治），避免按单条 finding 局部落笔、修完复发。

## 结论分层的门槛

1. 候选 → 四道过滤器（F1 层 / F2 决策日志 / F3 留白 vs 冲突 / F4 失败模型）→ 连过四道的进反驳验证。
2. 口径 10 三项全量扫 + 口径 11 全量副本比对 + 口径 12 引用回放 + 口径 13/14 窗口复核先跑，缺口优先于印象候选。
3. 反驳验证三步做完（检索含配套与附录、端到端走到稿内出口、最简合规实现测试），再做作者反驳。
4. 只有「作者一句 § 引文能反驳掉」的候选才降级；反驳成功的留主发现，失败的一句降为 W 项。
5. 主发现按实况，不凑数；无真缺陷就报 0 条。

## 拒绝的方向

- 不把实现细节（提交失败回滚、幂等实现、扫描算法）当设计缺口。
- 不把已声明的事实边界与有意取舍翻案（§0 事实边界、§0.1 口径 3 清单）。
- 不为「更优雅」重排章节、改表结构；修复只准补判定 / 补同步 / 改措辞。
- 不因 v37 已修过某条就跳过复核；也不把 v37 的修复当成不可动的新地基。

## 主要风险与对策

| 风险 | 对策 |
