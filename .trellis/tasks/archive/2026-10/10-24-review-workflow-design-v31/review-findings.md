## 一、主发现

### F1 §3「就绪」定义未排除"异常"账本——与 §7.6 / §7.7 / §9.1 字面冲突

| 项 | 内容 |
|---|---|
| 约束编号 | B1（可执行：每节可定位到唯一判据）；涉 B9 |
| 证据 | §3 就绪 = "前置集合全部为'正常'，且该任务未完成、未归档，**且账本不是'正常'**（…）；挂起是就绪的临时排除项"。该条件排除了"正常"（括号处理类型 3）与"挂起"（专用分句），**唯独没有排除"异常"**。而 §7.6 明写"替换/放弃实施后旧任务不再参与选择"；§7.7 组合表"未归档 + 异常 → 替换/放弃未完成 → 类型 5"；§9.1 第一段"有未完成的替换/放弃 → 类型 5 向前完成"。 |
| 触发场景 | 替换实施第 1 步完成并持久化（旧任务账本"异常"，§6.5 步骤 1）后、第 5 步归档前崩溃：旧任务**未归档、账本"异常"、前置集合可能全部"正常"**（替换允许对"无记录"任务实施，其前置此时可已全正常）。该组合完全满足 §3 就绪字面条件。诚实使用（崩溃窗口）即可达，无需绕过。 |
| 来源类型 | 内部矛盾：§3 与 §7.6 两条成文规则对同一可达情形（未归档+异常+前置全正常）的"是否就绪"结论相反。任一保真的实现都必然违反其中一条。 |
| 影响 | DAG 视图（§8.3，人只读）与就绪集构造（§7.6 引 §3 定义）在实现阶段就会把类型 5 任务画成/判成"就绪"，与路由层（§9.1 第一段）冲突 → 实现阶段被迫改 §3。 |
| 作者反驳（已验证不成立） | "§7.6 与 §9.1 已截住选择，行为不会错"——反驳只救了选择行为，救不了定义本身：§3 是就绪/DAG 视图的唯一判据源，§7.6 需要额外补一句排除恰恰证明定义层漏了。 |
| 建议 | §3 就绪条件"且账本不是'正常'"改为"**且账本为'无记录'**"（挂起临时排除分句保留不动）。改措辞级修复，不新增机制，不影响任何表行号。 |

### F2 §7.7「账本/归档组合自检」表缺"已归档 + 无记录"行——收尾崩溃最高频组合在指定分类工具中无类可归

| 项 | 内容 |
|---|---|
| 约束编号 | B9（验收原文即写"§7.7 完整性自检覆盖账本/归档组合"）；涉 B10 |
| 证据 | §7.7 组合自检表枚举了：已归档+正常（前置全正常 / 含非正常）、已归档+挂起、已归档+异常、未归档+正常 / 挂起 / 异常 / 无记录各组合——**唯独没有"已归档 + 无记录"**。而 §7.7 绕过兜底第一条与表 4-2 行 5 都明确"已归档但账本为**无记录 / 挂起**"属类型 1；§5.3、§6.3 还两处明示收尾崩溃（归档成功、账本写入/持久化失败）的产物就是"已归档但账本无记录"。启动对账步骤指名"按下文'账本/归档组合自检'**表**识别非法或不一致组合"——表是该自检的指定分类工具。 |
| 来源类型 | 规定不清（同一规则在表与正文两处覆盖不一致：正文覆盖，表漏一行）。 |
| 影响 | 实现层按组合表编写启动自检/对账分类时，会漏掉收尾崩溃路径的最高频产物；进入对账联调阶段后被迫补行（该表行无编号，补行成本极低，但现在补比事后补便宜）。 |
| 作者反驳（已验证不成立） | "绕过兜底第一条与表 4-2 行 5 已覆盖该组合"——正文确实覆盖，但被指名为分类工具的表没有；表驱动实现必然漏类，两处覆盖面不同本身就是口径 5 的"两处不同"。 |
| 建议 | 组合表在"已归档 + 挂起"行旁补一行：`已归档 + 无记录 | 非法 | 类型 1（人确认正常 / 异常后补记）`。只追加，不改既有行。 |

## 二、措辞与精确项（不判缺陷，列为后续小修候选）

### W1 挂起清除的"执行者/时机"四处口径不一

- 证据：表 4-2 行 3 写入者列为"**返工逻辑 / 启动对账**"；§4.2 写入者清单为"收尾 / 返工 / 替换 / 放弃 / 启动评估清挂起 / 对账修复"（含替换、放弃，不含"入口"）；§6.6 放弃返工任务 R（删边）后"T 的…挂起即可清除（§6.4）"；§9.1 第二段行 2 由**入口路由本身**执行"清除挂起，继续 T"；§8.4 第二段行 2 同。
- 判定：行为无死路（启动评估 + 入口第二段双兜底，转移本身统一走行 3），不构成缺陷；但"谁在何时清挂起"实现时需自行仲裁四处文字。
- 建议：表 4-2 行 3 写入者改为"满足行 3 条件的机制动作（收尾评估、放弃/替换删边后的评估、启动评估、入口第二段）"，或反向在 §6.6 / §9.1 统一注"按表 4-2 行 3 执行"。

### W2 §8.4 与 §9.1 的"三段"第一段内容不对齐，存在平行漂移风险

- 证据：§8.4 第一段含"按 §7.7 组合表做完整性分类"但无"模块不可用"（后者在其步骤 5）；§9.1 第一段含"模块不可用"但无完整性分类行（类型 1/4 只经启动对账标记、§9.1 末行兜底或 §8.4 呈现）。两处描述同一三段结构，内容各有侧重，行为可相容（完整性检测归 §7.7 启动对账，模块不可用归 §8.4 步骤 5），但未来任一侧单独修改都会漂移——v31 恰好刚做过一次双处同步。
- 建议：§8.4 第 4 步压缩为引用 §9.1 三段（净复杂度不增），或在两处各加一句显式互引并注明差异归属。

### W3 §4.4 归档终态约束"只能来自继承"漏了第四种合法来源

- 证据："归档任务的前置集合只能来自继承（0→1 建图、返工与替换继承），建边不再往归档任务上挂"。漏了：任务在**活动期建边、随后正常归档**——其前置集合含建边产物，既非建图也非继承。严格读者会把这些合法边判为违反来源清单（该句是类型 4 对账检查的判据之一，误判代价真实）。
- 建议：改为"只能来自继承（0→1 建图、返工与替换继承）**或活动期建边后随任务归档**"。

## 三、排除项（低于门槛，不作为缺陷报告）

| # | 候选 | 排除理由 |
|---|---|---|
| 1 | 嵌套返工（R 自身挂起）时 §9.1 第二段"进入 R；R 自身未就绪时按第三段处理"看似绕开挂起段 | 端到端推演：R 挂起不入就绪集，第三段"最早就绪"收敛到 R2（唯一可行动作），路由结果正确；括号句功能上成立 |
| 2 | "第三段'最早就绪'是任务选择的唯一路由" vs 第二段直接"进入 R" | 第二段的优先来自**挂起任务上下文**（T），不是 R 作为任务类型的优先级；说明句明确限定"第三段"范围内。非矛盾 |
| 3 | P 未归档阶段不能插无关任务 | §6.8 明示的取舍（"P 未归档时仍只执行 P"），窗口有限，属有意设计 |
| 4 | 就绪集强制"取最早"限制人手选任务 | 有意确定性设计（多 CLI 无共享上下文）；建边/删边即塑形杠杆。个人偏好不受理 |
| 5 | 建边允许前置"正常但未归档"却要求目标先修复的不对称 | 语义不同：前置看"顺序是否已满足"（两种修复结果下边都合法），目标看自身可路由性。非矛盾 |
| 6 | 类型 1/4 不一致存在时仍可继续无关就绪任务 | "不放行"作用域为涉事任务；阻塞路径经 §9.1 末行进对账，出口存在 |
| 7 | 表 9-2 建边行"前置须未完工"简写，缺"正常但未归档"例外 | §0 写作约定"规则唯一来源是正文"，§7.5 为规则源，汇总表不构成第二规则源 |
| 8 | 建边可否给 P（链头）挂前置、违反"P 没有前置" | 建边限迭代期（"后续阶段允许"），届时 P 必已归档、不可达；0→1 期间给 P 建边必成环被检环拒绝 |
| 9 | §5.5/§6.6 引用"§6.5 实施第 2–3 步"中"移除旧任务标识"不适用于轻量新建场景 | 上下文裁剪可解，属引用措辞；行为无歧义出口 |
| 10 | 仅模块卸载期间原生归档图内任务导致账本缺记录 | §9.4 明示为合法路径，重装后类型 1 补记，非异常 |
