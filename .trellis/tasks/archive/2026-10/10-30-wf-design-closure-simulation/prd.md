# 修订 wf 三项边界并模拟任务闭环

## Goal

消除 wf 紧急变更边界的歧义，补足 spec 跨任务复用与暂停插单的验收；以 /tmp 临时项目模拟大致执行效果，判断既有设计能否闭合，不开发正式框架。

## Background

- 独立框架基线为 `docs/workflows/wf-framework-design.md`，旧两份内嵌模块文档仅作参考。当前只有设计及 `scripts/validate-wf-design.py`，无独立 wf 安装器、入口 skill 或运行脚本。
- 原审查第 2 点不是问题：§6.5 的审查人数、CLI 身份、轮次和降级规则保持不变。
- 用户已允许创建本 Trellis 任务，并限定在 /tmp 新建临时项目模拟，不进行正式实现。
- 收尾时用户明确授权按方案提交本任务路径、归档并记录会话；无关改动不纳入，不推送。

## Requirements

- R1：§5.6 说明 wf 内紧急任务仍遵守批准与门禁；wf 外已发生的应急改动按 §4.2 外部变更处置接入，事后立案不追认先做后补的授权。
- R2：§8.2 增加 spec 跨任务复用场景：任务 A 沉淀真实约定，后续独立进程模拟的新会话 B 从文件发现并消费该约定；覆盖缺失/旧版正文和违反约定的反例。
- R3：§8.2 增加 A 暂停 → B 插单完成 → A 恢复的场景；保留工作区边界，覆盖 A 业务脏改动阻断切换、B 无关改动与同路径改动对 A 检查有效性的影响。
- R4：同步唯一定义索引，按修订门禁枚举新增跨节引用与语义消费；不扩充新状态、字段类、应急系统或工作线机制。
- R5：临时项目中的最小业务产物必须实际运行验证；模拟控制数据、Git 事实与正反例均保留证据，明确与正式框架运行、真实 AI 跨会话执行及人工人判的区别。

## Acceptance Criteria

- [x] AC1 / R1：正文与应急正反例没有先做后补的授权例外。
- [x] AC2 / R2：模拟 A 沉淀、B 独立进程加载及业务契约断言通过；丢失/旧版读取及违约反例被识别。
- [x] AC3 / R3：模拟拒绝带 A 业务脏改动切换；处理后可完成 B 并恢复 A；同路径变更使旧检查失效，无关改动不使其失效。
- [x] AC4 / R4：设计机检通过，新增引用与索引语义回扫有逐项记录，§6.5 内容不变。
- [x] AC5 / R5：模拟报告、命令、结果及重建材料已保存，区分实际通过/失败/未运行；本次 /tmp 夹具已清理。无正式框架实现；模拟阶段未提交源仓库，收尾按后续明确授权提交。

## Out of Scope

正式运行件、安装/升级/卸载、多 CLI 审查变更、真实新 AI 会话、独立 reviewer、三类安装夹具全验收、正式数据 schema、MCP/hook 接管、团队/并发、推送本仓库及提交无关改动。模拟不替代 §8.2 实现验收。
