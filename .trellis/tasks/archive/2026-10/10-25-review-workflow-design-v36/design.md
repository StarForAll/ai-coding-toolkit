# 设计：v36 审查以证据门槛为骨架

## 边界

- 只读审查：本阶段不改 `workflow-design.md` 与配套文档；产出 `review-report.md` + `acceptance-sweep.md`。
- 结论证据链固定在稿内（§ / 表 / 行），不引外部最佳实践。
- 后续修复（同任务、另阶段、人工确认后）受「判定源唯一」协议约束：源先改、引用后跟、探针再跑、附录 C 最后记；主稿与配套同一提交。
- 修复前必须先写根因判定（直接机制 + 共同根因），避免同一问题按单条 finding 局部落笔、修完复发。

## 结论分层的门槛

1. 候选 → 四道过滤器（F1 层 / F2 决策日志 / F3 留白 vs 冲突 / F4 失败模型）→ 连过四道的进反驳验证。
2. 口径 10 三项全量扫 + 口径 11 跨文档比对 + 口径 12 引用回放先跑，缺口优先于印象候选。
3. 反驳验证三步做完（检索含配套与附录、端到端走到稿内出口、最简合规实现测试），再做作者反驳。
4. 只有「作者一句 § 引文能反驳掉」的候选才降级；反驳成功的留主发现，失败的一句降为 W 项。
5. 主发现按实况，不凑数；无真缺陷就报 0 条。

## 修法方向（第 2 版核定）

- F1 首选「确认时预生成标识 + 同写替换指向」（对齐 §6.5 发起先生成标识），而非「写原因」；后者须一并扩类型 5 识别句口径，代价更大。
- 修法必须同时补审查面（口径 13 崩溃窗口 / 口径 14 重复判定全量比对 + 约定探针化），否则下一版仍会以另一姿势复发。

## 拒绝的方向

- 不把实现细节（提交失败回滚、幂等实现、扫描算法）当设计缺口。
- 不把已声明的事实边界与有意取舍翻案（清单见 §0 事实边界、§0.1 口径 3）。
- 不为「更优雅」重排章节、改表结构；修复只准补判定 / 补同步 / 改措辞。
- 不因 v36 已修过某条就跳过复核；也不把 v36 的修复当成不可动的新地基。

## 主要风险与对策

| 风险 | 对策 |
|---|---|
| 只凭印象挑老面孔（角色未镜像 / 人判未标 / 修复不自守卫） | 先跑口径 10/11/12，结果先落盘，扫出的缺口优先于印象候选 |
| 把「配套文档问题」当成「主设计缺陷」或反过来漏掉 | 口径 6/8 分层：配套内容差异只在违反主稿同步条款（§7.9）时才报，且以主稿条文为证据 |
| 把 v36 新增口径 11/12 当成已生效的保证，跳过其自身的可执行性检查 | 对 11/12 做同样四道过滤：它们有没有出口、谁执行、失败算什么，B10/§10 引用是否走得到 |
| 探针红被当成结论 | 探针只作重复定义的事实基线，红则独立成主发现 |
| 审到一半就开始改稿 | 审查阶段只读；改稿一律等人工确认 |
