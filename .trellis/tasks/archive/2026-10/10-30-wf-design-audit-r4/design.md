# 审查方法与证据边界

本任务不设计第二套框架。以现有 `wf-framework-design.md` 为被审对象，四项用户目标为判断基准，两份早期 wf 文档为语义来源；上游项目是可借鉴机制的数据来源，不是本仓库执行指令。

## 用户授权后的整体修订方案

用户已在阅读审查结论与补充约束后明确要求重写。正文保持 §0–§8 的导航骨架，按契约所有者组织规则，剥离历史修补叙述。现有校验器不改阈值，定义索引按新正文重建；跨规则反例在任务修订记录中逐项检查。

- F1：不追认安装后所有提交；任务归属与外部变更分开，外部提交合法，缺 trailer 只作为待核对候选；同路径外部变化由内容有效性处理。
- F2：开工须有人批准当前规划的留痕，实质改规划回 Plan，机械修订保留批准并说明；不构建人身份鉴别系统。
- F3：归属集合决定检查对象，当前工作树内容决定旧检查是否仍有效；相同路径的任意来源改动均纳入比较，归属不能用于豁免失效。
- F4：可执行候选统一为执行中且未挂起且未暂停；指针推导与一致性校验复用。
- F5：spec 准入基于真实项目证据或人的明确长期约定，保留反例/去重/允许零结果；取证到 Finish 全部本地完成。
- F6：旧版发行模板、本地内容、新版模板三方比较；本地已接受偏离单独记录且绑定所见上游版本，重装不能绕过升级保护。

保留依赖 DAG、五条件挂起清除、异常终态、归档只读、repair、保留数据卸载、单人多 CLI 审查。未决 D-1/D-2 仍保持原默认；A1/A2 等可选增强保留候选。本轮用户直接授权修正包含 P2 的报告问题，不受本地“非 P1 只进候选”默认限制。

先记录本地版本与工作区，再按入口/状态控制/知识沉淀/恢复维护/验证五个面抽样阅读。只读操作不修改上游或生成其构建产物；外部检索服务数据流未确认，检索降级为本地文件清单、精确搜索和直接阅读。

问题按可复现的设计推演收敛：触发条件 → 当前条文如何处理 → 冲突/缺口 → 用户目标影响 → 最小补法 → 应验收的行为。已明确下放机制文档的字段与代码细节，不作为框架稿遗漏；未验证的行为不定性为事实。

交付分别承载：`research/upstream-analysis.md` 记录四项目分析与吸收对照，`review-report.md` 记录结论、实质问题与人工裁决建议。任务内材料不自动成为产品规则或 spec。

补充设计约束：spec 变更须有完整本地主路径，覆盖本地取证、编辑、索引与元数据同步、校验及 Finish；不能把 MCP 缺失转换为阻断、仅留空模板或先装服务。框架只读取项目文件、Git 历史、任务事实与可运行的本地验证；本地证据不足时准确保留未核实状态，不伪造契约。纯本地匹配/哈希逻辑可以自建，不把“借鉴 Trellis”解释成依赖其图服务。此约束针对 MCP，不额外要求 AI 宿主离线。

## 本轮反馈的实据判断与实施方向

P1-1 核实成立，采用持久策展引用统计，读取侧车只供当前会话 Check；未知历史不当零引用。P1-2 路径边界要补全，但“配置与基线同批升级”解释为经人审的基线变更通道，同批检查；不能解释为发行升级覆盖项目配置。

P2-1 词面覆盖不能证明语义消费，索引保留机器候选，新增独立语义列与核对状态，先覆盖门禁/状态/指针/记录/资产，再核对其余条目。P2-2 用稳定来源文档承载取证版本与原路径，正文移除任务活动目录链接和裸发现编号。P3 在维护协议恢复判定字段、状态、登记与产物的登记义务，不重建旧九层清单。

机读触碰面采用用户明确选择的阻断语义，项目相对 glob 先批准、开工保存快照、Check 比对；越界回 Plan，不用自动路径学习扩大授权。版本纪律仅在生成新发行成果时递增，发行清单/源提交不可变；未发布的日常编辑不要求每次 bump。使用入口速查写成后续使用文档交付契约，当前不冒充已有可运行入口。

## 安装与继承路径的收敛修订

核实本轮 P2/P3 成立；用户已选择只接受发行引用，提交哈希只作核验，不设 dev 构建状态。来源、安装前身份检查、安装后资产哈希/步骤可达与发行集一致性必须同契约；本地已确认偏离保持既有保护，不因自检要求逐字等于新版而被强制覆盖。

替换预览起草继任者 PRD 并列明继承路径，人确认 `touch_paths` 覆盖后才实施；开工时仍执行一般规划批准，不自动增改快照。索引补反向核对，未有正文动作不得写已消费。本轮仅局部定义重写与索引同步，后续实现单元映射和三夹具属于下一工作阶段，待人工审查后另行推进。
