# wf 框架设计深度审查与上游吸收评估

## 目标

基于四个参考仓库的实据与已交付审查报告，整体重写 `docs/workflows/wf-framework-design.md`，满足长期使用、新建与存量接入、spec 持续沉淀和单任务可控，并落实 spec 全流程不依赖外部 MCP。保留研究报告作为修订依据，交付待人工复审的设计正文与一致的定义索引。

## 背景与边界

- 参考：`~/projects/other/{skills,Trellis,stop-that-shit,mcode-stack}`；设计依据：`docs/workflows/{workflow-design.md,workflow-implementation.md}`。
- 当前设计已多轮审查，已有唯一定义索引、机检器与候选吸收清单。以本轮实际文件为准，历史报告只用于避免重报已解决事项。
- 原研究阶段已经交付报告；用户明确要求根据发现与补充约束修正并重新生成正文，授权进入文档修订。只修改正文、配套索引、稳定来源说明与任务材料；不实现框架、不修改上游仓库或部署资产。
- 不引入团队功能、常驻运行时、平台适配矩阵或偏离独立单人框架的要求。多 CLI 人工交替审查不自动等同团队功能。
- 补充硬约束（2026-10-30）：spec 的初始化、新增、更新、拆分、合并、改名、删除及其索引/元数据维护必须能通过本地文件、Git 和普通本地脚本完整完成，不依赖外部 MCP、GitNexus/ABCoder 服务或预建知识图谱索引。默认路径不得先要求安装、配置或探测这些服务。
- 用户明确要求人工审查通过前不得收尾：不执行 finish-work、归档、journal、提交、推送或 PR。文档修订阶段可启动任务，最终保持 `in_progress` 等待人工复审。
- 当前最新授权：用户人工审查通过后，已确认 `commit-plan.md` 中两批工作提交、当前任务归档及会话记录；按原生流程执行。不推送、不发布、不创建 PR，也不直接实现框架。
- 会话初始未提交内容：`.agents/skills/grill-me/`、`skills-lock.json`，保持不动。

## 要求

1. 分析四仓库的实际定位、使用场景、优点、限制、可迁移机制和不适合吸收的复杂度，固定本地版本与证据范围。
2. 对照两份参考设计与当前框架稿核对四项核心目标，区分实质矛盾、可补缺口、已有覆盖、已计划实现、可选改进。
3. 问题必须包含具体触发场景、证据锚点、影响、最小修正建议与验证方式；不以措辞、排版或未展开的实现细节凑问题。
4. 可吸收项说明是否已在正文或候选清单覆盖，以及引入成本；不重复包装既有建议为新发现。
5. 报告明确证据局限与待人工裁决项，不将上游宣传、静态审阅或已有测试文件当作本轮运行验证。
6. 审查 spec 变更的取证、写入、校验、加载/过期处置和 Finish 路径是否含隐性 MCP 前置；将“全部 MCP 不可用时仍能完整完成 spec 变更”作为强制验收条件，事实不足时标未核实，不以配置 MCP 为出口。
7. 重写时闭合 F1–F6 与 MCP 约束：控制面只限 wf 任务；开工消费最新规划批准；内容指纹比较当前树；挂起与暂停复用统一候选条件；正向知识可沉淀；升级采用三方判断。删除与新定义冲突的旧条款，保留原有恢复、依赖、卸载与审查出口。
8. 本轮反馈修订：策展引用提供持久回收统计源；流程文档与项目配置分别明确路径、写者和升级边界；索引分离词面候选与人工语义消费；产品引用不依赖任务活动路径；新增判定字段/状态须登记。吸收版本发行与使用入口说明的合理部分，观察期继续不引入。
9. 用户本轮明确裁决：批准的机读触碰面以仓库相对 glob 表达，超出时阻断继续执行，回 Plan 扩范围或确认必要变更；Check 复核实际路径。不得用范围 glob 假装语义验收完整，也不得声称可以实时拦截。
10. 本轮收敛修订仅处理安装发行身份/投放一致性与继任者路径授权：用户明确收紧为发行引用安装，提交哈希只核验内容；不引入 dev 安装机制。替换预览确认继承路径的触碰面，不待 Check 才发现遗漏；索引反向指向实际正文动作。完成后停止扩展文本审查，不提前进入实现。
