## 3. 主动删除/替换的旧机制

- 全仓安装锚点后重扫、空窗期禁业务提交、系统提交 WARN 豁免登记与二次锚点提交：由任务归属、合法外部变化和当前内容核对取代，删除它们的关联消费句，没有仅在一处放宽。
- 归属自己的提交才使检查失效、整个 `.wf/` 排除指纹：改为当前检查对象，其中交付 spec/基线不可排除；规划/记录等控制文件才不进入交付指纹。
- 文件存在即准许开工、轻量升级只补事后设计：改为批准当前规划；实质越界必须回 Plan。
- 升级仅比较模板与当前内容、接受偏离后改写旧模板哈希：改为三方表与独立偏离记录；上游删除、移动与新路径碰撞亦有出口。
- 卸载不读任何 `.wf/` 文件却要求使用其清单、清单缺失可猜删根：改为仅独立清单与必要资产状态，自包含且不依赖任务解析；清单不明时保留诊断与人确认恢复。
- “未复制代码即无许可义务”“完整机检即语义正确”“指针即可证明本会话启用”：全部移除，分别回归来源核对、人工复审与纪律边界。

## 4. 跨规则场景复核

以下为根据条文的人工逻辑推演，不是已执行框架测试。框架尚未实现，全部运行验收仍列在正文 §8.2。

| 场景 | 推演结果与依据 |
|---|---|
| 装 wf 后用其他流程提交 | 允许；§3/§4.2 不要求补建 wf 任务，任务相关变化按当前内容检查 |
| 卸载期间普通开发后重装 | 允许；§7.3 保留数据、外部变化语义不变 |
| 上轮有活动指针，新会话未调用 start | 不启用；§1.2 声明会话判断只是纪律，未冒称脚本可证明 |
| Plan 文件齐、仅批准建任务 | 不开工；§4.2 缺当前规划批准 |
| 批准后改范围/验收 | 回 Plan；机械进度勾选则留理由衔接，无重复批准 |
| 初始新项目没有基线 | 允许初始化自举；已批准 PRD 提供范围，Git/人批准不豁免 |
| 存量 bootstrap 还没有基线 | 同一自举规则；start 仅路由接入规划，不允许直接改业务 |
| A 已 Check，B 改同文件/删/改名 | A 旧 Check 失效，与 B 的提交归属无关 |
| B 改无关文件，A 对象未变 | A 指纹可保留；已知间接环境/契约影响仍须补查 |
| spec/基线在 Finish 发生变更 | 先回 Check，相关审查失效；不能从 `.wf/` 总排除漏过去 |
| T 挂起、R 执行，换 CLI | 仅 R 是执行候选，T 合法等待；不得报多个执行者 |
| 多个 T 同次解除挂起 | 逐个复评，已有候选时给后续 T 暂停，保持至多一个 |
| 指针指向暂停任务 | 只等待人恢复；指针有效不授权继续 Execute |
| R 被替换或删边放弃 | 继任 R 继承来源继续等待；放弃归档后按五条件复评 |
| 替换任务已有代码提交 | 继承来源路径进入继任者验收，旧任务仅异常归档 |
| 三件套/控制记录写入使工作区脏 | 精确的任务/动作控制路径可待提交；业务和外来改动不自动豁免 |
| 新契约首次验证成功，无事故 | 可准入；真实项目依据不限定为失败 |
| MCP 全关、无图索引 | 设计路径完整；本地证据不足只标未核实，必要业务验证仍独立约束 |
| 读取缓存丢失、换会话 | 重新读；策展不当作已读证据，缺缓存不放过门禁 |
| spec 改名，旧归档仍引用旧路径 | 当前引用同步，历史按原版本/提交解释，不篡改归档 |
| L=O、N 更新 | 更新；不误判用户改动 |
| 同一已确认 L、上游内容不变 | 保留；上游新内容再变或 L 再变才重新冲突 |
| 上游移除/改名、用户目录有新增文件 | 精确预览与冲突，不能递归吞掉未知内容 |
| 新版新增路径恰与用户文件同内容 | 先判所有权冲突，不因 L=N 自动接管 |
| 归档写入后、提交中断 | 按待持久化步骤恢复，不重复归档、不提前报告完成 |
| 没有提交许可或人未调用 finish | 停在待人处理，框架不会自行提交/归档 |
