# PRD：wf-framework-design.md 第十轮审查（外部对照 + 全文缺陷核查）

## Goal

对 `docs/workflows/wf-framework-design.md`（554 行，第九轮修订后）做第十轮实据审查，产出一份供人工审查的判断报告，回答三个问题：

1. skills / Trellis / stop-that-shit / mcode-stack 四个参照项目**是否还有** wf 未吸收、且在硬边界内可用的点；
2. 当前文档**是否还存在**矛盾、缺漏或可改进点（含" asserted 事实是否为真"这一类此前未查过的瑕疵类型）；
3. 上述问题范围不包含收尾动作——**修订正文由后续任务执行，本任务不改动被审文档**。

审查范围明确包含一项前九轮未做过的工作：**对被 documents §2.2 / §6.5 点名的外部资产（`skills/multi-cli-review*`），逐条核对其现行正文**，检验文档对它"路径、参数、目录约定"的断言是否成立。此举的依据是 §1.3 回扫对象 2 自身的规定（"凡点名外部 skill / 资产，读其现行正文核实……不凭记忆或'同源'印象断言形状"）。

## Requirements

### 约束（不得突破）

- 不偏离四条核心需求：① 项目中长期使用 ② 新建 / 存量项目均可用 ③ spec 持续沉淀 ④ 单任务流程执行可控；
- 不偏离硬边界：无 hook、无团队功能、无子代理派发、无平台分支、skill 为核心、不依赖 agent 宿主运行时特性；
- **本任务不修改** `docs/workflows/wf-framework-design.md`，**不修改** `skills/multi-cli-review*`；
- **不执行收尾**：不提交到 git、不归档任务、不更新 spec——人工审查通过后再由后续任务执行；
- Trellis 上游为只读参考，不提补丁，只借结构与判断句。

### 审查方法要求

- 四路只读勘察并行展开，每路专职一个参照项目，实地给出文件路径 + 行号证据；
- 主会话精读被审文档全文九章，做章节间交叉一致性核查；
- 对外部依赖的事实性断言，必须从**被依赖资产的现行正文**取证，禁止凭本仓库内文档的自述或"同源"印象下结论；
- 实事求是：未找到的写"未找到"，不假想不存在的机制（如前轮任务书中描述的 stop-that-shit "admission-linked 条款"实无对应物）；
- **不吹毛求疵**：纯措辞、排版、不影响判据成立的表述差异一律不列入报告。

### 产出要求

- 报告须按重要性排序，并区分三类：矛盾 / 缺漏（A 类，附落点与修法建议）、外部依赖的事实性偏差（B 类）、可吸收点与警示教训（C / D 类）；
- 每条须可追溯到具体证据（file:line），且吸收项须注明**许可边界**（CC-BY 受限于 mcode `engineering-*` 系列，MIT 为 skills 与 mcode 其余部分）；
- 须登记"已核查、不成立的疑点"，避免后续任务重查。
