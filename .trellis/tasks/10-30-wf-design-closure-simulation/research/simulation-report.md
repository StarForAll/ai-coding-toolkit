# wf 三项修订的临时闭环模拟报告

## 结论

本轮 11 组场景均达到各自预期，最终 6 个业务测试通过。实际创建了独立 /tmp 项目及 Git 仓库，用一次性脚本模拟控制动作；业务代码、文件重载、Git 提交/差异及子进程测试实际执行。正式 wf 运行件未实现，模拟不能作为框架安装/运行验收。

这些结果支持保留当前核心设计：三项问题可由明确边界和补验收解决，没有从本次样例发现引入新状态、应急系统、工作线或知识评分的必要。单一样例不能证明长期低成本，也不能证明通用正确性。

## 环境和材料

- 日期：2026-10-30；源仓库起始 HEAD、设计与索引内容指纹见 [provenance.json](simulation-evidence/provenance.json)。
- 临时根：`/tmp/wf-closure-sim-9d37yj8z`，项目子目录 `project/`；结束时仅清理本次临时根。
- Python：`/softwares/python/bin/python3`，只使用标准库；业务验证为 `-m unittest discover -s tests -v`。
- 业务为库存数量校验：负数拒绝，0 和正数允许；后续聚合接口必须复用逐项校验。
- 所有批准/暂停/恢复/finish 人判输入均标记 `SIMULATED_HUMAN`，不声称为真实人的逐次操作。临时 Git 身份仅用 `git -c` 传入测试身份，不改用户身份配置。
- [重建材料](simulation-reproduction.md)包含临时控制器、消费者、实验驱动及初始夹具；[命令日志](simulation-evidence/commands.json)保存每条实际命令、退出码及输出；[最终文件状态](simulation-evidence/final-project-state.json)与 [Git 历史](simulation-evidence/git-log.txt)供核对。

## 实际流程

1. K-producer 从已有业务缺陷开始：观察负数未抛错的红测试，修复后绿；沉淀 spec 与索引，经模拟 Check/finish 及独立归档提交闭合。
2. A-consumer 从新进程读取 K 的知识，新增聚合接口。先放入直接求和的违约版本，真实行为测试失败；消费者再从 spec 提取校验 API 并生成调用它的实现，6 个业务测试通过。
3. A 的业务改动尚未提交时模拟暂停被拒，工作区与任务文件保持原样；仅在临时仓库提交 A 检查点后，暂停 A。
4. B-docs 插入、检查并模拟归档，只改无关 README；经模拟显式恢复 A，旧 Check 仍有效。
5. 再暂停 A，C-same-path 改同一路径后闭合；A 恢复时旧 Check 失效，直接 finish 被拒，重读/重检后才能继续。
6. 外部 spec 内容修改使旧读取失效；外部应急提交不带 wf trailer，保留外部属性，其同路径变化使 A 检查失效，核对本例仅注释变化后重检并完成 A。
7. 最终 K/A/B/C 四个模拟任务归档，活动指针清空，夹具工作区干净；用于未批准拒绝测试的 emergency 仍未开工，没有冒称完成。

## 逐项结果

| 场景 | 实际观察 | 判定 |
|---|---|---|
| 紧急不增加开工许可 | `urgent` 不能越过 `PLAN_UNAPPROVED`，原记录字节不变 | 通过：预期拒绝 |
| 生产任务知识沉淀闭环 | 负数测试退出 1 → 修复后退出 0，spec/索引进夹具 Git 并归档 | 通过 |
| 新会话标识须重读 | 原会话读记录不能替代 fresh，返回 `SPEC_UNREAD` | 通过：预期拒绝 |
| spec 违约能被业务检查识别 | 直接 `sum(values)` 接受负数，测试失败，模拟 Check 非 pass | 通过：预期失败 |
| 后续任务消费 spec | 独立消费者进程从文件提取 API，聚合实现通过实际断言 | 通过：进程模拟 |
| 脏工作区不切换 | `DIRTY_WORKSPACE`；未 stash，未丢文件，任务记录不变 | 通过：预期拒绝 |
| 无关插单与恢复 | B 归档后 A 快照仍有效；缺显式模拟恢复输入被拒 | 通过 |
| 同路径插单与恢复 | C 归档后 A 快照失效；旧结果直接 finish 返回 `CHECK_INVALID` | 通过：预期失效 |
| spec 更新后重读 | 当前内容与旧读取不符，返回 `SPEC_CHANGED`；重读后可检查 | 通过：预期拒绝 |

| 最终闭环 | 4 个模拟任务归档、指针不存在、工作区干净，最终 6/6 业务测试通过 | 通过 |

机器结果详见 [results.json](simulation-evidence/results.json)。控制器是刻意缩小的模型：未实现完整提交归属、DAG/返工/替换、批准内容版本、路径安全与 glob 全语法、完整 spec 元数据、资产发行或原子中断恢复；任务路径集合由夹具明确给定。通过只说明本轮执行分支符合所表达的判据，不扩大到未表达分支。

## 成本观察与最低成本判断

单次成功实验记录 96 个子进程命令，其中控制器调用 44 次、带模拟人输入的调用 14 次，子进程耗时合计约 2.61 秒。此数含正反例、4 个模拟任务及 Git 证据查询，不能当正常任务命令数、真实人确认次数或 AI 成本基准。没有实测人的交接耗时或模型 token。

可观察的切换代价是：A 必须先处理业务脏改动，并留下检查点/交接；无关插单可保留旧检查，同路径插单则需重检。这与设计取舍一致，不以自动 stash 或新增工作线消除此代价。知识复用的关键是业务行为验证，引用计数本身不足。

## 失败和未运行项

- 夹具首次 `git add -- .gitignore ...` 退出 1：用户全局忽略文件将 `.gitignore` 忽略。已记录 [setup-failure.json](simulation-evidence/setup-failure.json)；仅在临时仓库设置 `core.excludesfile=/dev/null` 后按原场景成功运行，没有 force add 或改用户全局配置。重建 setup 已包含此隔离。
- 源仓库 `task.py start` 最初因空 JSONL 被拒：inline 不用子代理，按该命令的显式提示使用 `--allow-empty-context` 后进入 in_progress。这个参数不跳过任务规划或产品门禁。
- 业务红测试和上述拒绝退出码均为刻意验证，不能计为未处理的执行故障；全程日志保留了它们。
- 未运行：正式 wf、安装/升级/卸载、三类安装夹具、真实 AI 跨会话、独立 reviewer、人判真实性、真实长期成本、紧急变更涉及范围/验收变化的语义判读。
- 模拟结束时本仓库未获提交授权，文档与任务记录保持未提交。用户随后明确授权提交本任务路径、归档并记录会话；该收尾不改变模拟的证据边界，模拟归档本身不代表源仓库任务归档。
