# 第四十一轮外部评审的复核与修正（5 条）

- 处置编号 R77；实跑见 `validation.md` §67
- 判定：1、2、3、4 全部成立（同一处实现的四个缺口）；5 成立（文档自相矛盾）

## 1. unknown 与候选同时输出（成立）

设计稿 §6.2 要求"统计不足/未知"报出来，我却在记了 `unknown` 之后**照样构造候选**——人只看候选就会误删在用的 spec。

处置：**未知压制结论**。任一未知存在时 `reclaim_candidates` 为空，并置 `statistic_complete=false`；未知来源包括：样本不足窗口、样本缺 `curation`、条目非对象/不可解析、配置非法、样本引用过的路径已不存在。

## 2. 非法配置不阻断（成立）

`value_of` 给出的问题原来只放进 `problem` 字段，候选与 `due` 照算。

处置：`spec_reclaim_tasks` 非法 → 不产候选并记 unknown；`inspection_every_tasks` 非法 → `due` 为 `null`（不给结论），且不再参与取模。

## 3. 改名/合并映射是空列表（成立）

原来写成 `for path in []`，等于声明"永不未知"。

处置：拿窗口样本引用过的路径与当前 spec 文件集合比对，**引用了但当前不存在**的路径报 `unknown`（`rename/merge mapping unverifiable`）——不猜新名称，也不把它当"零引用"。

## 4. 畸形条目先 `.get` 后判类型（成立）

`entry.get(...)` 在 `isinstance(entry, dict)` 之前，字符串条目会直接抛异常，巡检本身失去"未知不当零"的保护能力。

处置：`entry_path()` 先判类型再取字段，非对象条目一律记 `unknown`（并计数），不再抛异常；活动任务与样本两侧都走同一函数。

## 5. §2.3.11 自相矛盾（成立）

标题与引言写"已登记、未实现"，正文却把锁探测描述成运行时与两个独立入口都已实现。

处置：该节改为「**已知边界与实现说明**」，说明"确属未实现的项会显式标注「未实现」"；锁探测条目改标"（已实现，含边界）"，并新增「巡检治理面的未知纪律」一条，把上面四条规则写进规范面。

## 用例

`r77_tests.py` 8 条：样本完整才给候选（正例）；样本不足/缺清单/畸形条目/改名映射四种未知各自压制候选；非法配置不给候选且 `due=null`；`inspect` 输出带 `unknown` 事实。
