# 第三十三轮外部评审的复核与修正（3 项）

- 处置编号 R69；实跑见 `validation.md` §59

## 0. 结论

| # | 原判 | 复核 | 处置 |
|---|---|---|---|
| 1 | `before: {}` 等于无约束；整批冲突在写入后才被发现 | **成立** | 前像必须有实际约束；分类整体前置，冲突则零写入 |
| 2 | 重导入不同摘要不报冲突，旧 pass 仍放行 | **成立** | 导入按摘要幂等/冲突；门禁核结论引用的摘要与当前导入一致 |
| 3 | 卸载确认期间内容变化仍被删除 | **成立** | 锁内重核待删资产内容与 `.gitignore` 全文 |

## 1. 前像与整批预检

- **空对象不再算前像**：`before` 为 dict 时必须含 `digest`，或显式 `{"exists": false}`；`{}` 直接 `WF_SEMANTIC_DECISION`。
- **分类前置**：先对全部条目算出 `skipped / write / conflict` 三类，**存在任何冲突就整体拒绝**（`WF_WORKSPACE_UNRESOLVED`，facts 列 `conflicts`），一件都不写。上一版把前像判定塞进写入循环，才会出现"A 已写、B 才报冲突"的半应用状态。

## 2. 审查导入与门禁引用

- **同槽位同摘要**：幂等重入，不重复写。
- **同槽位不同摘要**：`WF_REVIEW_INVALID`，不覆盖、不留旧结论（机制稿 §9.2「不同摘要报冲突」）。
- **门禁核引用**：`task.review-passed` 除了核 `verdict=pass` 与 `check_id` 绑定，还核 `result.imported[]` 里每份报告的 `report_digest` 仍等于当前 `reviews.imported` 的同轮同槽位摘要——报告被换掉，旧 pass 立即失效。

## 3. 卸载锁内重核

确认后在锁内除核"路径集合 + 写者状态"，还核：
- 每个待删资产**当前内容**是否仍等于发行摘要（不等即说明出现本地改动）；
- `.gitignore` 当前全文是否与预览时读入的一致（段外新增内容不能被旧文本覆盖）。

任一不符即 `WF_PREVIEW_STALE`，一个文件都不删。
