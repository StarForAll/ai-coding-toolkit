# 第四十二轮外部评审的复核与修正（1 条）

- 处置编号 R77b（续 R77）；实跑见 `validation.md` §68
- 判定：成立。上一轮只把**归档样本**纳入"未知压制候选"，**活动任务**那一侧仍是 `curated(task) or []`——读不出来就被当成"没有依赖"。

## 1. 缺口

`for entry in curated(task) or []`（活动任务侧）有三处漏判：
- 活动任务缺 `curation` 字段 → 空迭代，等于"无依赖"；
- `curation` 不是列表 → 同上；
- 条目不是对象 → 旧代码在 `entry.get` 处直接抛异常（上一轮已修），但即便不抛也会被静默跳过。

机制稿要求"活动任务依赖优先保护删除/回收"，把"读不出"当"没依赖"正好把保护反过来。

另有第四处：活动任务引用了**已不存在**的 spec 路径（改名/合并未映射）时，上一轮只查了归档样本的引用集合。

## 2. 处置

活动任务与归档样本走**同一套规则**：

| 情形 | 结果 |
|---|---|
| 缺 `curation` / 非列表 | 记 `active task lacks curation list` → 压制候选 |
| 条目非对象 | 记 `active task curation entry unparsable` → 压制候选 |
| 引用路径已不存在 | 记 `curation path no longer exists; rename/merge mapping unverifiable` → 压制候选 |

"消失路径"的判定集合从"样本引用"扩到"样本引用 ∪ 活动引用"。

## 3. 边界

- 不改变"有未知就不给候选"的总规则（上一轮定的），只是把未知来源补全；
- 活动任务正常时行为不变：仍按 `path` 且未 `released` 计入 `active_refs`。

## 4. 用例

`r77_tests.py` 增 5 条（共 13 条）：无活动任务时样本完整可给候选（正例）；活动任务缺字段 / 非列表 / 条目非对象三种各自压制候选并给出对应未知；活动任务引用已消失 spec → 压制候选。
