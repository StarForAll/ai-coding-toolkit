# workflow-design v31 修订

## Goal

按已归档的审查报告（`review-report.md` F1–F3、P1–P6）与用户补充说明，把 `workflow-design.md` 与配套 `依赖机制设计说明.md` 同版修订到 v31：建边收窄到活动区、入口表改三段路由（全局旁路 → 挂起阶段 → 非挂起阶段），并一次性消化 F3 与 P 项，避免下一次中途改设计。

## Requirements

1. F1：建边目标必须在活动区、前置必须在活动区；删边仍可对归档目标（类型 4 修复要用）。删掉“目标已归档先对账”分支与“新前置必须为正常”的旧守卫，改为：进行中任务新增前置不阻止继续，只阻止收尾。
2. F1 附带的连带收敛（上轮分析已确认）：§4.4 归档终态约束保留不开口子；§7.7“账本不自动清理”的理由从“建边找不到记录”改为“类型 1/4 修复与终态判定”；§7.7 组合表把“未归档 + 无记录 + 规划中/进行中 + 前置含非正常”从“不一致”改判为“等待（可容忍）”。
3. F2：§9.1 与 §8.4 同版改为三段：①全局旁路；②挂起阶段（当前任务挂起，或视为无当前任务且存在挂起任务时，只走挂起子表：有未归档 R→进入 R / R 全归档且 §6.4 条件满足→清挂起继续 T / 有返工记录、无未归档 R、前置不全正常→对账且异常前置走替换·放弃 / 无返工记录→类型 2；指针为空时按创建时间取最早的挂起任务走同一子表）；③非挂起阶段（进行中或规划中但前置含非正常 → 等前置，异常前置走替换·放弃或删边）。挂起与进行中不再并列，“进行中但前置不满足”行限定为非挂起。
4. F3：§10 补“实现方案必须给出升级 SOP、探针失败不得声明兼容”“旧模块迁移不得改写已有判定”；§0.1 A4/B6 验收列与正文对齐；§3 收 SOP 定义。
5. P1–P6：组合表补规划中、表 9-2 与 §7.5 对齐、类型 2 限定未归档、§6.6 引用改为“§6.5 实施第 2–3 步”、§4.2 写入者补启动评估、§10 design 字段措辞。
6. 版本：主设计 v31、配套 v31（`design: workflow-design.md v31`）、附录 C 与配套修订章各加 v31 条；`implements_design` 表述随版本走。
7. 附录 B 的 F 统一改成 R（与正文一致）。
8. 不用补丁式写法：受影响的整段重写，读起来是一次成型的规则，不出现“补一句/另注”痕迹。

## Acceptance Criteria

- [ ] `rg -n '归档区' workflow-design.md` 后，建边处不再出现“目标可在归档区”；保留处只剩解析、返工来源扫描、删边、类型 1/4 修复。
- [ ] §9.1 与 §8.4 都是三段结构，挂起子表 4 行齐全且含指针为空规则；两处不出现“有当前任务，且当前任务进行中但前置不满足”这类与挂起重叠的写法。
- [ ] §10 含升级 SOP 与迁移不改判定两句；A4/B6 验收列与 §10 同口径。
- [ ] `rg -n '新前置必须为正常'` 无命中；§7.5 写明进行中建边只阻收尾。
- [ ] 主设计与配套版本字段都是 v31，配套 `design` 指向 v31；两份文档的组合表与类型 1–5 文字逐条对应。
- [ ] 组合表含规划中行，且对其判定为“等待”而非“不一致”。
- [ ] 附录 B 全部用 R，无 F。
- [ ] 通读 §7.5、§7.7、§9.1、§8.4 无补丁痕迹（无“补充说明”“另见上句”式追加）。
