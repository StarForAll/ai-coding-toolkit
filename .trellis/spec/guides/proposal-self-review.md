# Proposal Self-Review（方案自查清单）

> 来源：2026-11-11 的 wf ⑥「修复中」方案，**23 轮外部审查仍未收敛**。
> 复盘发现根因不是审查太细，而是我把"设计是否闭环"的判断交给了审查——
> 每轮只修被点名的条目，从不自己做完整性检查。这份清单就是那次教训的产物：
> **改方案前先自己按它跑一遍，再交付。**

配套规则：[`review-phase-discipline.md`](./review-phase-discipline.md)（审查阶段只改文档、禁跑实现级验证）。

---

## 1. 何时用

- **每次改方案/规格文档之前**：先按 §2 跑一遍，把能找到的问题自己修掉；
- **每次交付方案时**：在回复里报"自查发现 N 处，修了 X/Y/Z"，并列出你以为的剩余风险；
- **外部审查报出问题时**：先问"§2 的第几条本该抓到它？"——**先补清单，再修那一条**（只修条目 = 下一轮同样问题再来一次）。

---

## 2. 十条清单（每条都给机械做法，不靠"想一想"）

| # | 检查项 | 机械做法 | 不做的后果（本项目实例） |
|---|---|---|---|
| 1 | **每个字段只有唯一产生函数？** | 列出所有"派生字段"，逐个写"由哪个函数产出"；出现两处计算即不合格 | `pending_unknown` 曾被独立实现，与 `blocking_unknown` 两套口径 |
| 2 | **每条规则都有反向规则？**（继续 ≠ 解除） | 对每个"出口/解除"断言，问"它到底解除了什么？"；把"让流程继续"和"解除阻断"分两列写 | 把"重发新一轮"写成 `blocking_unknown` 的解除出口 → 重审成功仍无法归档 |
| 3 | **每个身份都有域定义？**（谁是谁） | 列出所有"名字"字段（`slot`/`agent`/`id`/`round`），写清取值域与匹配键 | `slot`（声明名）与 `agent`（reviewer 名）混用，放行永远匹配不上 |
| 4 | **每条路径都有三态？**（首次/幂等/显式重做） | 对每个写操作画三行表：首次、重复同一输入、显式覆盖 | 幂等重入是否改写 `anchor` 没写 → 记录与判定互相矛盾 |
| 5 | **每类事实都有归属？**（不许静默消失） | 列出"所有可能产生事实的来源"，逐个指定归入哪个字段；检查"既不在 A 也不在 B"的空隙 | `stale`（锚点≠当前）报告里的 findings 既不入 blocking 也不入 unknown |
| 6 | **每个错误都有能真正解除它的出口？** | 对每个阻断，写"解除它的**唯一机械动作**"；若只能靠重做 → 明确写"重做不解除" | 缺摘要的遗留记录被写成"另开新轮"，实际新轮不解除 → 死路 |
| 7 | **每个阻断都有作用域？**（挡完成 ≠ 挡工作） | 画表：事实 × {阻断结论/阻断归档/不阻断}；逐格检查是否"顺手扩大到全部工作" | `escalated` 被写成"先处理再继续"，与 v42 K10 原义相反 |
| 8 | **每处读取都有健壮归因？** | `grep` 全仓读取入口（摘要/文件/JSON），逐个确认"缺失 vs 不可读 vs 损坏"分别归到哪 | 只补了两处 `except OSError`，`decide`/gate 仍会把异常抛成内部错误 |
| 9 | **每个旧记录都有迁移规则？**（且不回写） | 对每个新增字段写"旧记录没有它时怎么推导"，并声明**不回写历史** | 只固定"轮"，没固定"槽位"，旧裸 id 仍会随新报告扩大关闭范围 |
| 10 | **每个数字与引用都能解析？** | 交付前跑：条目数 = 标题数字 = 影响面里的计数；正文每个"§x / 第 n 条"都能在文中找到 | 标题写 26 项、表里 33 行；正文引用不存在的 10a–10d |

## 3. 三条纪律

1. **机制 vs 指引要有判据**：能机械判定的进机制；不能的**如实登记为已知限制**，不要用文案假装覆盖（例："不要试归档"是纪律，机制上仍会先提交——必须写进"已知限制"）。
2. **不复制既有判定**：凡是已有函数在判的事（判定资格、门禁步骤），方案只能**引用事实**，不得在方案里再写一套条件（否则两处漂移）。
3. **范围先锁死**：方案开头写"明确不做什么"。没有非目标章节的方案，会被无限追问边界，永远"不完整"。

---

## 4. 反模式（都是本项目真实踩过的）

- [ ] ✍️ "审查说一条，我改一条" → 下轮同样的问题换个地方再来
- [ ] 🧱 "先加档位/枚举，再想数据模型" → 模型缺口每轮从新档位里冒出来
- [ ] 🌀 "把'能让流程继续'写成'解除阻断'" → 造成"重做成功但仍无法收尾"的死路
- [ ] 🕳️ "新增字段但不写旧记录推导" → 同一事实两种身份
- [ ] 📊 "数字自己写，不核对" → 计数/引用成为审查的主要噪声
- [ ] 🧪 "声称机制能保证 X，其实只能纪律保证" → 假保证（例：AI 无法自签人裁）
- [ ] 🚀 "方案还没闭环就改实现" → 见 `review-phase-discipline.md`（另一条红线）

---

## 5. 交付模板（回复里固定报三段）

```
自查：按 §2 十条跑过，发现 N 处，已修 N 处（列表：…）
边界：明确不做的事（M 项），理由：…
待你裁：K 条（各带默认值）
```

**判据**：如果一次交付里"自查发现"为 0，多半是没认真跑清单——**先怀疑自己，而不是相信文档没问题**。
