# wf-grilling

用于 Plan 期澄清。它是原语，不是入口：不建任务、不批准、不写判定字段。

## 做法

1. 先查本地事实（代码、测试、文档、既有决策），能查到的不问人。
2. 只把真正需要人取舍的问题编号为 `plan-q-<n>：`，写在 PRD 正文（n 从 1 连续、不重复）。
3. 每问附推荐答案，措辞使「是」即接受推荐项；可逆细节自己定，并在结果里列出。
4. 一轮内批量呈现；人答完后由入口写入 `execution.human_decisions`。
5. 完成信号：人所有决策已澄清、事实已调查、规划可批准。

## 不做

- 不代人作答；不把「提取结果为空」当成无疑问。
- 不把固定流程步骤改成可略项。

## 纪律

- 身份只在请求信封里：不读环境变量、不从命令行或文件猜身份；信封缺失就报 `WF_IDENTITY_UNRESOLVED`。
- 不代人作答、不代跑终端确认与令牌；人的决定只经 `--decision` / `--plan` / `--disposition` 文件承载。
- 入口输出的 `tier` / `code` / `facts` / `next` 是唯一判定源；不自行改写状态或补写门禁结论。
- 命令一律形如 `python3 <项目根>/.wf/bin/wf.py <子命令>`；不装 PATH、不做 shell shim。

## 来源与差异

| 项 | 值 |
|---|---|
| 来源 | 全局 skill `grill-me`（本仓库 `~/.claude/skills/grill-me`，非本仓库资产） |
| 许可 | 跟随本仓库（内部私有源，无第三方 NOTICE 义务；上游为同作者资产） |
| 基线 | 适配基线＝本仓库上述源文件；本副本为唯一发行件，上游改动不自动流入 |
| 差异 | 改编为单会话顺序提问：去掉子代理派发与轮次等待，问答留在同一会话 |
| 最近正例 | 复杂任务把 3 个未决点编号并各带推荐答案，人一轮作答后进入批准 |
| 最近反例 | 复杂任务个别提问发散；缺失时人判问题补齐被拖到 Execute |
