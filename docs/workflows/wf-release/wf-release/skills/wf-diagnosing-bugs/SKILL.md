# wf-diagnosing-bugs

> **判断指引**：判定"这条缺陷是否真的修好"要看证据能否指回问题本身——完整口径见 `wf-repair-loop`「这条 blocking 真的修了吗」。

用于 Execute 期的调试循环。重复失败达到 `debug_repeat_threshold` 时，入口会产生待决项：由你（主会话）按根因裁定「同一问题/不同问题」并把依据与证据写进裁定 reason（机制保留计数与留痕；机制稿 §1.3）。一条裁定覆盖 `covers` 列出的全部已越过倍数——不必为每个倍数各签一条；证据不足以区分根因时才交人。

## 做法

1. 建立可重复的最小反馈（一条命令或一个断言）。
2. 最小化输入，直到失败可稳定复现且范围最小。
3. 提出假设 → 定向探测 → 记录被排除项（写进交接材料的 `ruled_out`）。
4. 修复后回归：同一反馈由红转绿，且不改变已批准范围。
5. 无法复现就如实报告环境与观察，不推测修复。

## 不做

- 不为了让计数好看而省略失败记录；不在未授权范围外改动代码。
  这不算违反：在批准触碰面内改业务代码，失败记录如实进 dedupe/证据——诚实计数正是「同一问题/不同问题」裁定的输入。

## 纪律

- 运行纪律见 `.wf/workflows/session-flow.md`「运行约定」：身份只经信封或宿主映射通道；不代人作答；入口输出是唯一判定源；解释器整会话固定、失效即停。
